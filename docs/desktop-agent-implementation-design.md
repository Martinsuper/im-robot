# Piko 桌面代理实施设计

> 目标：把桌面精灵扩展成能理解节律、能受控执行、能做桌面整理的代理  
> 覆盖范围：桌面操作、受控 Shell、工作节律提醒、今日输入字符数统计、按需剪贴板分析  
> 核心原则：可确认、可中止、可解释、默认不越界

## 1. 设计背景

Piko 已经具备聊天、提醒、专注、日程、记忆和基础插件能力，但如果只停留在“会说话”，它很难真正进入用户工作流。

用户真正需要的是：

- 能整理桌面、打开路径、处理文件
- 能在用户明确授权后执行受控命令
- 能在不读取内容的前提下感知工作节律
- 能在适当时机提醒休息
- 能基于今日输入活跃度做轻量辅助判断
- 能按需分析剪贴板，但不长期监控正文

这份设计把这些能力合并为一个统一的桌面代理层。

## 2. 总体原则

1. **默认不读内容。** 除非用户明确触发，Piko 不读取剪贴板正文，也不读取键盘输入正文。
2. **默认不后台执行。** Shell 执行必须显式确认，且可中止。
3. **默认不保存明文。** 统计与分析只保留聚合结果，不保留原文。
4. **默认低打扰。** 提醒基于空闲、前台场景、专注状态和活跃度，不基于内容画像。
5. **高风险操作先预览再确认。**

## 3. 能力分层

### 3.1 只读感知层

只采集低敏感信号，用于判断当前状态。

- 空闲时长
- 前台应用类别
- 专注模式状态
- 今日输入字符数
- 今日输入活跃时长
- 剪贴板是否变化、变化频率、大小

不采集：

- 键盘具体按键
- 剪贴板正文
- 应用内完整输入内容
- 屏幕正文内容

### 3.2 受控操作层

用于处理明确的系统任务，所有写操作都必须确认。

- 打开文件、文件夹、应用
- 列出桌面项目
- 整理桌面文件
- 执行受控 Shell 命令

### 3.3 互动提醒层

用于主动但克制地提供帮助。

- 休息提醒
- 起身提醒
- 专注持续时长提示
- 剪贴板分析提醒

### 3.4 轻量自动化层

后续扩展用，不作为第一版重点。

- 单次快捷键
- 短文本输入
- 预设 UI 动作

## 4. 桌面操作层

### 4.1 目标

给 Piko 补上“手和脚”，让它可以处理桌面事务，但不变成无约束的自动化工具。

### 4.2 第一版能力

#### `list_desktop_items`

列出桌面上的文件、文件夹和快捷方式。

输出建议包含：

- 名称
- 路径
- 类型
- 分类建议

#### `open_path`

打开文件或文件夹。

约束：

- 只做存在性校验
- 只打开，不修改
- 失败要有明确错误

#### `organize_desktop`

按类型整理桌面。

建议分类：

- 图片 -> `图片`
- 文档 -> `文档`
- 压缩包 -> `压缩包`
- 代码 -> `代码`
- 快捷方式 -> `快捷方式`
- 其他 -> `其他`

执行前应展示：

- 会移动多少个文件
- 会创建哪些文件夹
- 哪些项目会被跳过

执行时必须：

- 不覆盖已有文件
- 重名时使用安全的新文件名
- 不默认递归整理子目录

### 4.3 交互链路

```text
用户意图
  -> 本地规划器 / 模型工具调用
  -> 生成 Action Draft
  -> UI 预览与确认
  -> 宿主执行
  -> 结果回传
```

### 4.4 安全边界

- 不开放任意 Shell
- 不开放无确认删除、覆盖、移动
- 不开放持续鼠标键盘接管
- 不开放屏幕内容持续读取

## 5. 受控 Shell 执行层

### 5.1 目标

让用户可以让 Piko 执行明确的系统命令，但必须由用户把控。

### 5.2 适用场景

- 项目构建
- 依赖安装
- 格式化代码
- 明确的维护命令

### 5.3 执行模型

```text
用户输入命令意图
  -> 生成命令草稿
  -> 展示命令、工作目录、影响范围、超时
  -> 用户确认
  -> 宿主执行
  -> 输出结果
```

### 5.4 风险分级

| 等级 | 示例 | 默认策略 |
| --- | --- | --- |
| `pure` | 版本查询、目录列表 | 可直接执行 |
| `read` | 检查状态、读取日志 | 首次授权或确认 |
| `write` | 修改文件、安装依赖 | 每次确认 |
| `sensitive` | 删除、覆盖、系统配置变更 | 强确认 |
| `forbidden` | 账号、支付、凭据、危险命令 | 不开放 |

### 5.5 推荐边界

第一版优先开放：

- `npm run ...`
- `cargo ...`
- `git status`、`git diff`
- 受限文件操作脚本

不建议开放：

- 任意网络抓取
- 任意权限提升
- 任意删除和覆盖
- 长时间驻留进程

## 6. 工作节律提醒

### 6.1 目标

在不读内容的前提下，给用户更合适的休息提醒和状态提示。

### 6.2 输入信号

只用低敏感度信号：

- 空闲时长
- 前台应用类别
- 专注模式状态
- 用户是否暂停感知
- 最近一次主动交互时间
- 今日输入字符数
- 今日输入活跃时长

不使用：

- 键盘具体按键
- 剪贴板正文
- 屏幕正文识别结果

### 6.3 提醒策略

- 连续专注过久时提示短休息
- 长时间无输入时提示起身活动
- 切到高压场景时降低互动频率
- 用户开启专注模式时优先安静

### 6.4 文案原则

- 简短
- 不指责
- 不推断具体工作内容
- 可忽略、可关闭、可延后

## 7. 今日输入字符数统计

### 7.1 目标

用一个低侵入指标表示今天的输入活跃度。

### 7.2 数据口径

- 只统计今日累计输入字符数
- 只统计文本输入的字符数量
- 不统计修饰键、方向键、功能键

### 7.3 存储策略

建议只存最小聚合值：

- 日期
- 今日输入字符总数
- 今日输入时长总数
- 最后更新时间

示例：

```json
{
  "date": "2026-06-03",
  "typedCharacters": 18432,
  "typingSeconds": 28640,
  "updatedAt": 1717400000
}
```

### 7.4 展示位置

建议放在：

- 工作节律卡片
- 今日活跃度卡片
- 专注模式辅助指标区

### 7.5 与提醒联动

- 输入字符数持续增长且无长休息时，提示短休息
- 输入活跃时长过长时，提示起身活动
- 专注模式开启时降低提醒频率
- 前台是 IDE / 文档编辑器时提醒更克制

### 7.6 约束

- 不记录原文
- 不落盘内容
- 不上传云端
- 不进入长期记忆

## 8. 剪贴板按需分析

### 8.1 目标

用户主动发起时，临时读取剪贴板并完成一次分析。

### 8.2 触发方式

- 用户点击“分析剪贴板”
- 用户在对话中明确要求分析剪贴板

### 8.3 安全约束

- 只读一次，不轮询
- 只在前台确认后读取
- 只做单次分析
- 不保存原文
- 不进入长期记忆

### 8.4 适用任务

- 摘要
- 格式化
- 纠错
- 提炼待办
- 生成回复草稿

## 9. 产品形态建议

### 9.1 面板入口

建议新增或强化：

- 桌面操作入口
- 受控 Shell 入口
- 今日活跃度卡片
- 工作节律卡片
- 剪贴板分析开关

### 9.2 气泡交互

- “要不要休息一下？”
- “要执行这条命令吗？”
- “要分析当前剪贴板吗？”
- “桌面整理已准备好，是否执行？”

## 10. 推荐实施顺序

### 第一批

1. 工作节律提醒
2. 前台应用类别感知
3. 今日输入字符数统计

### 第二批

4. 桌面操作层
5. `list_desktop_items`
6. `open_path`
7. `organize_desktop`

### 第三批

8. 受控 Shell 执行层
9. 命令草稿与确认卡
10. 执行结果摘要

### 第四批

11. 剪贴板按需分析
12. 单次分析模板
13. 脱敏结果展示

## 11. 验收标准

- 系统不会持续读取键盘正文。
- 系统不会持续读取剪贴板正文。
- 今日输入字符数只显示聚合值。
- 命令执行必须先确认。
- 命令执行可中止。
- 休息提醒不依赖内容级监控。
- 剪贴板分析仅在用户主动触发时发生。
- 桌面整理能生成清晰计划并正确执行。

## 12. 结论

这套能力应该被看成一条统一的桌面代理链路，而不是几块互不相关的功能。

我们先把“节律感知 + 受控执行 + 桌面整理”打通，再逐步扩展到更复杂的系统协作能力。这样 Piko 才能真正长出手脚，同时仍然可控、可审计、不过线。
