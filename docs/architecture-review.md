# 架构检查与维护约定

本次检查日期：2026-10-23。

## 当前结构

- React 按 `src/features` 组织业务；`src/lib` 放持久化、错误处理等公共基础能力。
- `src/generated/ipc.ts` 提供类型化的前后端契约；`src-tauri/src/bootstrap.rs` 负责应用装配，Rust 模块分别拥有命令和领域逻辑。
- `agent/` 是独立的 Node sidecar；SDK 接入集中于 `sdk-adapter.mjs`，协议、权限和文件操作分开实现。

整体分层可以继续沿用。本次针对已确认的依赖倒置和初始化竞争进行修改。

## 已处理问题

### 公共层反向依赖业务层

`appSharedData.ts` 原来从 `features/pet/hooks` 获取通用异步订阅清理工具，使应用公共能力依赖宠物模块的内部目录。

工具及其测试已移动到 `src/lib/eventSubscription.ts`，业务模块统一引用该公共实现。异步注册晚于卸载完成时，仍保证清理一次。

`scripts/check-runtime-boundaries.mjs` 增加前端检查：`src/lib` 不得通过相对静态导入、再导出或字面量动态导入依赖 `features`、`components`、`hooks`。这是一条公共基础层规则，不覆盖全部业务模块的依赖关系。

### 持久化初始化缺少并发与重试控制

原实现中，多个调用者在首次加载完成前可同时读取或迁移状态，并清空共用事件缓冲，存在新事件丢失或旧快照覆盖新状态的风险。事件订阅失败后，缓存的 rejected Promise 还会阻止后续恢复。

现在同一窗口中的调用者共享一次初始化；订阅失败后重置缓存以支持重试，事件按版本合并后释放缓冲。新增回归测试覆盖并发加载期间的跨窗口事件，以及订阅失败后重试并写入成功。

## 后续拆分顺序

`src/features/chat/BubbleWindow.tsx` 仍约 1,600 行，是下一步值得收敛的模块。建议先沿会话提交与流式状态、附件与截图、工作区交互划分职责，保留窗口组件负责装配。当前仅凭文件长度不足以安全界定这些状态的所有权，本次没有进行大范围机械拆分。

`appShared.ts` 同时再导出数据与 React 组件，消费者容易引入过宽的依赖。后续修改调用点时，优先直接引用实际拥有该能力的模块，逐步缩小聚合入口。
