# Piko 桌面操作层设计

> 目标：给桌面精灵补上“手和脚”，但仍保持受控、可确认、可回滚  
> 适用范围：文件整理、路径打开、窗口操作、轻量自动化  
> 非目标：任意 Shell、无提示的系统控制、持续鼠标键盘接管

## 1. 背景

当前 Piko 已经能聊天、提醒、记日程、做专注模式、写受控文件，也有基础插件运行时。
但它对系统的“操作能力”还停留在间接层面，缺少真正能帮用户完成桌面事务的执行层。

典型需求包括：

- 整理桌面，把散落文件归类
- 打开某个文件夹、文档或应用
- 在用户确认后批量移动、重命名文件
- 后续可扩展到窗口管理和有限的快捷键自动化

这个能力不能直接交给模型随意执行，必须通过宿主层能力、明确权限和确认流程来完成。

## 2. 产品目标

### 2.1 核心目标

1. 让 Piko 能处理明确、可理解的桌面任务。
2. 让这些操作有预览、有确认、有结果反馈。
3. 让能力逐步扩展，但不突破安全边界。

### 2.2 用户价值

- 不只是会说话，还能替用户做事。
- 能处理桌面清理、文件归类这类高频琐事。
- 能把“帮我整理一下”变成可执行流程，而不是一句空话。

## 3. 能力分层

### 3.1 第一层：只读感知

用于了解当前环境，不产生修改。

- 列出桌面文件、文件夹、快捷方式
- 打开路径前先做存在性校验
- 获取当前前台应用状态

### 3.2 第二层：受控文件操作

用于处理桌面整理类任务，必须先预览再确认。

- 创建文件夹
- 移动文件
- 重命名文件
- 批量整理桌面

### 3.3 第三层：窗口与应用操作

用于辅助用户切换和打开环境。

- 打开文件、文件夹、应用
- 前台窗口切换
- 最小化、显示、聚焦特定窗口

### 3.4 第四层：轻量自动化

仅做明确、有限、可追踪的动作。

- 发送单次快捷键
- 输入短文本
- 点击预设 UI 目标

这一层不是第一版重点，必须在更严格的限制和确认机制下开放。

## 4. 明确非目标

以下能力不进入第一阶段：

- 任意 Shell 命令执行
- 无确认的文件删除、覆盖、移动
- 长时间持续监听和控制鼠标键盘
- 读取屏幕内容并做持续分析
- 操作账号、支付、邮件、消息发送

## 5. 交互模型

桌面操作建议统一走同一条链路：

```text
用户意图
  -> 本地规划器 / 模型工具调用
  -> 生成 Action Draft
  -> UI 预览与确认
  -> 宿主执行器
  -> 结果回传
```

这意味着：

- 读操作可以直接执行。
- 写操作必须先变成草稿。
- 高风险操作必须逐项确认。
- 执行结果必须可见，不能“静默成功”。

## 6. 工具设计建议

### 6.1 `list_desktop_items`

用途：列出桌面上的项目，供整理前确认。

输出建议包含：

- 名称
- 路径
- 类型
- 分类建议

### 6.2 `open_path`

用途：用系统默认应用打开文件或文件夹。

策略：

- 只做存在性校验
- 不修改文件
- 打开失败要返回明确错误

### 6.3 `organize_desktop`

用途：按类型整理桌面。

典型策略：

- 图片 -> `图片`
- 文档 -> `文档`
- 压缩包 -> `压缩包`
- 代码 -> `代码`
- 快捷方式 -> `快捷方式`
- 其他 -> `其他`

执行前需要展示：

- 计划移动多少个文件
- 会创建哪些文件夹
- 哪些项目会被跳过

执行时要保证：

- 不覆盖已有文件
- 发生重名时自动生成安全的新文件名
- 文件夹默认不自动递归整理，避免误伤

## 7. 安全策略

### 7.1 最小权限

每个工具都应明确声明风险等级：

- `read`：可直接执行或首次授权后执行
- `write`：必须确认
- `sensitive`：强确认，且尽可能限制参数范围

### 7.2 路径边界

默认只建议作用于用户可见目录，例如：

- 桌面
- 下载
- 文档

如果后续扩展到其他目录，应增加可见的授权提示。

### 7.3 可恢复性

桌面整理类操作应尽量做到：

- 先预览
- 再执行
- 出错可继续
- 结果可追踪

如果未来增加删除类操作，应额外提供回收站或撤销路径。

## 8. 推荐实施顺序

### 第一阶段

1. `list_desktop_items`
2. `open_path`
3. `organize_desktop`

目标是先把“整理桌面”这类高价值场景打通。

### 第二阶段

4. 创建文件夹
5. 移动文件
6. 重命名文件

把整理能力拆成更细的可组合动作。

### 第三阶段

7. 窗口聚焦与切换
8. 固定快捷键动作
9. 轻量输入自动化

把精灵从“会做文件任务”扩展到“会协助操作系统”。

## 9. 验收标准

一个合格的第一版至少要满足：

- 用户说“整理桌面”，能生成清晰的整理计划。
- 用户能看懂会移动什么、建什么文件夹。
- 用户确认后，实际文件被移动到正确位置。
- 打开路径时不会误删或覆盖。
- 出错时有明确报错，不会悄悄失败。

## 10. 结论

桌面操作层应当被定义成“受控执行能力”，而不是“无限自动化能力”。

先把文件整理、路径打开、窗口切换这三类高频动作做稳，Piko 才算真正长出手脚。
