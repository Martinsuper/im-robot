# Piko 受控执行与工作节律提醒设计

> 目标：让 Piko 能主动帮忙，但不越过隐私和安全边界  
> 覆盖范围：受控 Shell、按需剪贴板分析、工作节律提醒、轻量桌面感知  
> 明确非目标：持续读取键盘输入正文、持续读取剪贴板正文、无约束后台命令执行

## 1. 背景

桌面伙伴如果只能“聊天”，很难真正融入用户工作流。用户通常希望它能：

- 主动提醒休息
- 帮忙执行一些系统任务
- 在用户明确授权后读取当前上下文并提供帮助

但这些能力如果做成“无限监控 + 任意执行”，会直接越过隐私和安全边界。因此本设计采用“受控执行 + 事件级感知 + 按需分析”的方案。

## 2. 设计原则

1. **默认不读内容。** 只在用户主动触发时读取剪贴板或执行命令。
2. **默认不后台执行。** 受控 Shell 必须显式触发、可见、可中止。
3. **默认不长期保存原文。** 分析结果可存，原始内容尽量不落盘。
4. **默认低打扰。** 提醒策略优先基于空闲、专注和前台场景，而不是内容分析。
5. **所有高风险动作先预览再确认。**

## 3. 明确非目标

以下能力不纳入本设计：

- 持续记录键盘输入正文
- 持续记录剪贴板正文
- 自动读取密码、验证码、密钥
- 无约束后台执行任意 Shell
- 基于完整输入内容进行长期画像和行为推断

## 4. 受控 Shell 执行层

### 4.1 目标

允许用户让 Piko 执行明确的系统任务，但必须保留控制权。

### 4.2 适用场景

- 安装依赖
- 运行项目脚本
- 批量格式化文件
- 执行明确的开发维护命令

### 4.3 交互模型

```text
用户输入命令意图
  -> 生成命令草稿
  -> 展示命令、工作目录、影响范围、超时
  -> 用户确认
  -> 宿主执行
  -> 输出结果
```

### 4.4 安全限制

- 默认只允许预设 allowlist
- 必须显示完整命令
- 必须显示工作目录
- 必须显示超时上限
- 必须支持中止
- 必须限制输出长度
- 必须记录执行结果摘要，不记录敏感正文

### 4.5 风险分级

| 等级 | 示例 | 默认策略 |
| --- | --- | --- |
| `pure` | 版本查询、目录列表 | 可直接执行 |
| `read` | 读取构建日志、检查状态 | 用户确认或首次授权 |
| `write` | 修改文件、安装依赖 | 每次确认 |
| `sensitive` | 删除、覆盖、系统配置变更 | 强确认 |
| `forbidden` | 账号、支付、凭据、危险系统命令 | 不开放 |

### 4.6 推荐边界

第一版只建议开放：

- `npm run ...`
- `cargo ...`
- `git status`、`git diff`
- 受限的文件操作脚本

不建议开放：

- 任意网络抓取
- 任意权限提升
- 任意删除和覆盖
- 长时间驻留进程

## 5. 工作节律提醒

### 5.1 目标

让 Piko 可以在不读取用户内容的前提下，给出合理的休息和专注提醒。

### 5.2 输入信号

仅使用低敏感度信号：

- 空闲时长
- 当前前台应用类别
- 专注模式状态
- 用户是否暂停感知
- 最近一次主动交互时间

不使用：

- 键盘具体按键
- 剪贴板正文
- 屏幕正文识别结果

### 5.3 提醒策略

- 连续高专注时长后提示短休息
- 长时间无输入时提示起身活动
- 切到高压场景时降低互动频率
- 用户手动开启专注模式时优先安静

### 5.4 提醒文案原则

- 简短
- 不指责
- 不推断具体工作内容
- 可忽略、可关闭、可延后

示例：

- “你已经连续专注 45 分钟了，要不要休息 5 分钟？”
- “你看起来已经离开电脑一会儿了，要不要顺手做个活动？”

## 6. 剪贴板按需分析

### 6.1 目标

用户明确发起时，临时读取剪贴板内容并完成单次分析。

### 6.2 触发方式

- 用户点击“分析剪贴板”
- 用户在对话中明确说“帮我分析剪贴板”

### 6.3 安全约束

- 只读一次，不后台轮询
- 只在前台确认后读取
- 只做单次分析
- 不保存原文
- 不进入长期记忆
- 分析结果默认脱敏

### 6.4 适用任务

- 摘要
- 格式化
- 纠错
- 提炼待办
- 生成回复草稿

## 7. 产品形态建议

### 7.1 面板新增能力

- 受控 Shell 执行入口
- 当前节律状态
- 最近提醒记录
- 剪贴板分析开关

### 7.2 气泡交互

- 提醒“是否休息”
- 提醒“是否执行命令”
- 提醒“是否分析当前剪贴板”

### 7.3 默认策略

- 无用户触发时，Piko 只做轻提醒
- 用户明确发起时，Piko 才进入受控执行

## 8. 实施顺序

### 第一批

1. 工作节律提醒
2. 前台应用类别感知
3. 专注模式联动

### 第二批

4. 受控 Shell 执行层
5. 命令草稿与确认卡
6. 执行结果摘要

### 第三批

7. 剪贴板按需分析
8. 单次分析模板
9. 分析结果的脱敏展示

## 9. 验收标准

- 系统不会持续读取键盘正文。
- 系统不会持续读取剪贴板正文。
- 命令执行必须先确认。
- 命令执行可中止。
- 休息提醒不依赖内容级监控。
- 剪贴板分析仅在用户主动触发时发生。

## 10. 结论

如果目标是“让精灵真的能帮忙”，正确的方向不是放开所有权限，而是把高风险能力做成受控能力，把高侵入感知降到最低。

这样 Piko 才能既主动，又不越界。
