# 日程回归测试

## 自动化检查

```sh
npm test
cargo test --manifest-path src-tauri/Cargo.toml
npm run build
git diff --check
```

新增覆盖位于 `src/features/chat/BubbleWindow.chat.test.tsx` 和 `src-tauri/src/lib.rs`：

- 批量创建、批量删除只提交已勾选的索引，显示后端执行结果，不再次请求模型。
- 全部取消勾选时禁止执行；取消草稿不调用确认执行接口。
- 后端执行失败不显示删除成功，不再次请求模型。
- 空删除列表、重复 ID、含不存在 ID 的列表均不产生部分删除。
- 创建→统一存储读取→选择删除→重新读取→删除剩余日程；保留 ID、时间、地点、备注。
- 日程删除全过程保留提醒记录及其全部字段。

## UI 检查

使用独立测试标题；记录测试前日程和提醒基线。真实删除需要用户在执行时确认。

1. 批量创建：`请创建两条测试日程：2026年10月16日14:00到15:00，标题“完整回归-A-评审”，地点“测试会议室”；同一天15:30到16:00，标题“完整回归-B-取消验证”。生成批量确认卡片。`
2. 核对日期、时间、标题后确认；界面应显示后端创建成功结果，存储应新增两条。
3. 只读查询：`只查询：2026年10月16日有哪些日程？列出准确时间、地点，包括标题含“取消验证”的日程，不要删除。` 不得误判为写操作。
4. 创建取消：`创建测试日程“完整回归-C-不应保存”，2026年10月16日17:00到17:30，先给确认卡片。` 点击取消，检查存储没有新增。
5. 退出并重启，从“Piko 操作→对话”进入，重新查询。已创建日程日期、地点应准确，取消记录应不存在。
6. 单条创建：`创建测试日程“完整回归-D-单条创建”，2026年10月16日16:30到17:00，地点“单条测试室”。` 确认后再次查询。
7. 单条删除：`删除“完整回归-D-单条创建”，先给确认卡片。` 获得执行确认后删除，A/B 应保持不变。
8. 批量取消：`帮我删除所有日程，先生成确认卡片。` 核对全部目标，点击取消；存储应不变。
9. 再次生成批量删除卡片。获得执行确认后删除测试目标，查询应为空，提醒与基线一致。
10. 再次重启并查询，已删除记录不得重新出现。

模型回答不能作为唯一依据：同时核对确认卡片、执行结果和 `schedule-items.json` 的日程数量。不要使用旧 `calendar-events.json` 判断当前数据。
