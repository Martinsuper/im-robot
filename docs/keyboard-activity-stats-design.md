# Piko 今日输入字符数统计设计

> 目标：在不记录输入内容的前提下，统计用户今天的输入活跃度  
> 范围：今日输入字符数、输入活跃时长、活跃节律提示  
> 非目标：持续保存键盘内容、记录具体按键、重建用户输入正文

## 1. 背景

用户希望 Piko 能理解“我今天到底忙不忙”，并据此做更合适的提醒。

“今日输入字符数”是一个低侵入、易理解、容易展示的指标，适合作为工作节律的一部分：

- 帮助判断今天是否处于高强度工作状态
- 用来驱动休息提醒的节奏
- 让用户看到自己的工作活跃度，但不暴露输入内容

## 2. 设计目标

1. 只统计数字，不记录正文。
2. 只统计今日，不长期保存历史明细。
3. 只在本机聚合，不上报、不同步。
4. 与休息提醒联动，但不作为唯一依据。

## 3. 明确非目标

以下内容不纳入设计：

- 记录键盘输入的具体字符序列
- 重建用户输入的原文
- 将按键内容写入日志
- 将输入内容传入长期记忆
- 将统计结果用于远程画像或上传分析

## 4. 数据口径

### 4.1 今日输入字符数

定义为：

- 从当日 00:00 到当前时刻的累计输入字符数
- 仅统计“输入动作”的字符数量
- 不统计修饰键、功能键、方向键等非文本输入

### 4.2 输入活跃时长

可选辅助指标：

- 今日累计处于输入状态的时长
- 单次连续输入段长度

这可以帮助判断“长时间高强度工作”，但不替代字符数本身。

## 5. 采集边界

### 5.1 可采集

- 是否发生了输入
- 输入字符数量
- 输入持续时间
- 今日累计值

### 5.2 不可采集

- 具体按键内容
- 剪贴板正文
- 用户密码、验证码、密钥
- 应用内输入框的完整文本

## 6. 存储策略

建议只存以下最小数据：

- 日期
- 今日输入字符总数
- 今日输入时长总数
- 最后更新时间

示例：

```json
{
  "date": "2026-06-03",
  "typedCharacters": 18432,
  "typingSeconds": 28640,
  "updatedAt": 1717400000
}
```

### 6.1 保留期

建议保留：

- 今日数据：实时更新
- 历史聚合：最多保留 7 到 30 天

不保留：

- 明细按键记录
- 原始文本
- 剪贴板正文

## 7. UI 展示建议

### 7.1 面板位置

建议放在以下区域之一：

- 工作节律卡片
- 今日活跃度卡片
- 专注模式旁边的辅助指标区

### 7.2 展示文案

建议用易懂、低压力的表达：

- 今日输入字符数：`18,432`
- 今日输入时长：`4 小时 53 分`
- 当前活跃度：`较高`

避免使用会引起被监控感的措辞。

## 8. 与提醒联动

这个指标最适合和休息提醒联动，但不建议单独驱动提醒。

### 8.1 联动规则建议

- 输入字符数持续增长且无长休息时，提示短休息
- 输入活跃时长过长时，提示起身活动
- 若用户已开启专注模式，提醒频率降低
- 若前台应用是 IDE 或文档编辑器，提醒频率略高但更克制

### 8.2 不建议的规则

- 看到输入字符数高就频繁打断
- 基于字符内容推断工作性质
- 根据单次输入片段做行为画像

## 9. 风险控制

### 9.1 隐私控制

- 不记录原文
- 不落盘内容
- 不上传云端
- 不进入长期记忆

### 9.2 误判控制

输入字符数只能说明“输入量”，不能说明“工作质量”。

因此它只应作为辅助信号，不能单独作为提醒依据。

## 10. 验收标准

- 面板能显示今日输入字符总数。
- 统计值只变化数字，不出现输入内容。
- 重启后今日统计能继续读取最小聚合值。
- 历史明细不会保留。
- 提醒逻辑可读取这个指标，但不会依赖它单独判断。

## 11. 结论

“今日输入字符数”是一个合适的低敏感指标。它能帮助 Piko 更像一个懂节奏的伙伴，但又不需要碰用户输入正文。

如果后续要继续增强，也应该优先扩展聚合指标，而不是保存内容。
