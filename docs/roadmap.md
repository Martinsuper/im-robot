## 1. 设计原则

与 P0 一致，所有后续功能遵循以下原则：

1. **先是伙伴，再是工具。** 精灵体验优先，功能服务于陪伴感。
2. **默认安静，不打断专注。** 新增能力默认不弹窗、不通知。
3. **高风险操作：先预览、再确认、可撤销。** 文件写入、工具调用等均需用户确认。
4. **权限按需申请，透明说明。** 每项新权限都有明确用途和数据流向说明。
5. **核心体验跨平台一致，平台差异诚实呈现。**

### 安全红线（不可突破）

以下功能**永远不在计划内**：

- ❌ 持续读取屏幕内容
- ❌ 摄像头或麦克风访问
- ❌ 未经确认的文件删除/移动/覆盖
- ❌ 未经确认的邮件/消息发送
- ❌ 支付、下单和账户变更
- ❌ 模型执行任意 Shell 命令

### 1.1 多轮对话上下文

**问题：** 当前每次提问是独立的，模型没有上下文记忆。用户无法像正常聊天一样说"接着上面的说"。

**实现方案：**

- Rust 侧维护最近 N 条对话（建议 10 条）作为 `messages` 数组传入模型
- 新消息追加到数组末尾，超出上限后移除最早的对话对
- 面板中的"清除历史"同时清空上下文窗口
- 每条对话仍单独持久化，不影响现有 `chat-history.json` 格式

**接口变更：**

```rust
// chat_start 新增可选的 history_window 参数
#[tauri::command]
async fn chat_start(
    app: AppHandle,
    // ... 现有参数
    history_window: Option<Vec<Message>>, // 可选，默认为自动取最近 N 条
) -> Result<(), String>
```

**验收：**
- 连续提问时，模型能引用上文内容
- 清除历史后上下文清空
- 重启应用后上下文不自动恢复（每次新会话从零开始）

**预计工作量：** 1-2 天

### 1.2 Markdown 渲染优化

**问题：** 当前 `react-markdown` 基础渲染缺少代码块复制、表格支持、流式闪烁等问题。

**实现方案：**

| 优化项 | 方案 |
| --- | --- |
| 代码块复制按钮 | 自定义 `pre` 组件，右上角添加复制按钮 |
| 表格渲染 | 安装 `remark-gfm` 插件，传入 `ReactMarkdown` 的 `remarkPlugins` |
| 流式防闪烁 | 在 `<ReactMarkdown>` 外层包裹 `<div>`，添加 `min-height` 避免内容跳动 |
| 链接安全 | 自定义 `a` 组件，添加 `rel="noopener noreferrer"` 并用 `openUrl` 打开 |
| 图片渲染 | 自定义 `img` 组件，限制 `max-width: 100%` |

**依赖新增：**
```bash
npm install remark-gfm
```

**验收：**
- 代码块有复制按钮，点击后内容进入剪贴板
- Markdown 表格正确渲染
- 流式生成时不会出现明显跳动或闪烁
- 链接点击通过系统默认浏览器打开

**预计工作量：** 0.5 天

### 1.3 精灵情绪系统

**问题：** 当前 5 种情绪（♥ ? z ! …）仅由离散事件触发，与聊天内容脱节。

**实现方案：**

- 基于聊天状态自动推断情绪：
  - 用户刚提问 → `curious`（?）
  - 回复成功完成 → `happy`（♥）
  - 回复出错/超时 → `worried`（…）
  - 长时间无交互 → `sleepy`（z）
  - 收到意外响应 → `surprised`（!）
- 情绪切换带过渡动画，停留 2-4 秒后渐变为 `neutral`
- 活泼度影响情绪出现频率（`active` 更频繁切换，`minimal` 几乎中性）

**验收：**
- 精灵在聊天过程中情绪自然变化
- 情绪变化不影响聊天功能
- 休息状态下不显示情绪

**预计工作量：** 1 天

### 1.5 提醒周期支持

**问题：** 当前提醒仅支持一次性，无法创建每天/每周重复提醒。

**实现方案：**

- `Reminder` struct 新增可选字段：
  ```rust
  struct Reminder {
      // ... 现有字段
      repeat: Option<RepeatRule>, // "none" | "daily" | "weekly" | "weekdays"
  }
  ```
- 提醒触发后：
  - `none`：标记为 `triggered`，不再触发
  - `daily`：`due_at` 增加 86400 秒，状态重置为 `pending`
  - `weekly`：`due_at` 增加 604800 秒
  - `weekdays`：`due_at` 增加 86400 秒，跳过周六/日
- 面板 UI 添加重复频率选择器

**验收：**
- 每日提醒每天同一时间触发
- 工作日提醒跳过周末
- 删除重复提醒后不再出现

**预计工作量：** 0.5 天

### 1.6 语音朗读（TTS）

**问题：** 用户可能不方便阅读长回复，希望通过语音听取。

**实现方案：**

- 桌面端使用系统本地 TTS：macOS `say`、Windows `System.Speech`、Linux `spd-say`

- 气泡窗口底部添加 📢 朗读按钮
- 点击后朗读当前消息内容
- 朗读过程中按钮变为 ⏹ 停止，点击可中断
- 支持 macOS / Windows 原生语音（自动选择系统默认语音）

**验收：**
- 点击朗读按钮后听到 AI 回复的语音
- 生成过程中也可朗读（读已生成的部分）
- 停止按钮可中断朗读

**预计工作量：** 0.5 天

### 2.1 空闲检测

**状态：** ✅ 已完成（2026-06-01）。

**问题：** 当前精灵不知道用户是否在电脑前，可能在不该互动的时候打扰。

**实现方案：**

- Rust 侧查询系统距上次输入的空闲时长，不读取具体键盘或鼠标事件内容：
  - macOS：Core Graphics `CGEventSourceSecondsSinceLastEventType`
  - Windows：`GetLastInputInfo`
  - Linux：`xprintidle`（需要系统安装该命令；不可用时静默停用空闲检测）
- 用户无输入活动超过阈值时：
  - `active` 模式：60 秒 → 精灵进入 `sleepy` 状态
  - `balanced` 模式：120 秒 → 精灵休息动画变慢
  - `minimal` 模式：300 秒 → 精灵进入 `resting` 状态
- 用户恢复活动后精灵自动唤醒
- 不记录具体按键内容，只检测是否有输入事件

**验收：**
- 停止操作后精灵按设定时间进入休息状态
- 移动鼠标或按键后精灵恢复
- 不记录任何键盘输入内容

**预计工作量：** 1-2 天

---

### 2.2 前台应用感知

**问题：** 精灵不知道用户当前在做什么，无法根据场景给出合适的反应。

**实现方案：**

- Rust 侧定期（每 5-10 秒）获取当前活跃窗口标题和进程名：
  - macOS：`NSWorkspace.shared.frontmostApplication`
  - Windows：`GetForegroundWindow` + `GetWindowText`
  - Linux：`xdotool getactivewindow getwindowname`
- 根据活跃应用分类做出反应：
  - IDE/编辑器 → 精灵进入 `working` 状态，降低互动频率
  - 浏览器 → 精灵保持 `idle`，正常互动
  - 视频会议应用 → 精灵进入 `resting`（静音陪伴）
  - 游戏 → 精灵保持 `resting`
- 不记录窗口标题内容，只匹配应用名分类

**隐私声明：** 仅获取前台应用名/类名，不读取窗口内容、不保存历史记录。

**验收：**
- 切换到 IDE 时精灵表现更安静
- 切换到浏览器时精灵恢复正常
- 不记录或存储任何应用使用数据

**预计工作量：** 2-3 天

### 2.4 工具调用（Tool Use）

**问题：** 当前 AI 只能纯文本回复，无法主动获取外部信息或执行操作。

**实现方案：**

- 预定义一组只读工具：

| 工具 | 功能 | 风险等级 |
| --- | --- | --- |
| `web_search` | 搜索网络信息 | 低（仅读取） |
| `calculator` | 数学计算 | 无风险 |
| `time_query` | 查询当前时间/时区 | 无风险 |
| `weather` | 查询天气 | 低（仅读取） |
| `unit_convert` | 单位换算 | 无风险 |

- 模型返回 `tool_use` 指令时：
  1. Rust 侧解析工具名称和参数
  2. 在气泡中弹出确认卡片：「Piko 想要执行：搜索 "xxx"，是否允许？」
  3. 用户点击"允许"后执行，结果返回给模型继续生成
  4. 用户点击"拒绝"后告知模型无法使用该工具

**接口设计：**

```rust
#[derive(Debug, Deserialize, Serialize)]
struct ToolCall {
    name: String,
    parameters: Value,
}

#[tauri::command]
fn execute_tool(call: ToolCall) -> Result<Value, String>;
```

**验收：**
- 模型能正确调用预定义工具
- 每次工具调用前用户可确认或拒绝
- 工具结果正确返回给模型
- 不在预定义列表中的工具被拒绝

**预计工作量：** 3-5 天

### 3.1 自动更新

**问题：** 当前更新检查只跳转到 GitHub Releases 页面，用户需要手动下载安装。

- macOS 支持 `.dmg` 自动挂载替换
- Windows 支持 `.exe` / `.msi` 静默更新

**新增依赖（Cargo.toml）：**
```toml
tauri-plugin-updater = "2"
```

**验收：**
- 发布新版本后客户端能检测到
- 下载和安装流程顺畅
- 更新失败有明确错误提示和回退方案

### 3.3 国际化（i18n）

**问题：** 当前 UI 全部为中文，非中文用户无法使用。

**实现方案：**

- 使用 `i18next` + `react-i18next` 或自建轻量方案
- 支持语言：
  - `zh-CN`（简体中文）— 默认
  - `en-US`（English）
  - `ja-JP`（日本語）
- 根据系统语言自动选择，默认回退到中文
- 所有 UI 文本提取为语言文件（JSON 格式）
- Rust 侧错误消息也做多语言处理

**语言文件结构：**
```
src/
  locales/
    zh-CN.json
    en-US.json
    ja-JP.json
```

**验收：**
- 切换语言后所有 UI 文本正确翻译
- 新增语言只需添加 JSON 文件
- 系统语言变更后自动跟随
