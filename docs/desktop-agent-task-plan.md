# Piko 桌面代理任务拆解

> 依赖：[桌面代理实施设计](desktop-agent-implementation-design.md)  
> 目标：把总设计拆成可开发、可验收、可逐步上线的任务清单

## 1. 任务总览

### Epic A：工作节律与低敏感感知

目标：先让 Piko “会看节奏”，再谈主动执行。

- A1 前台应用类别感知
- A2 今日输入字符数统计
- A3 今日输入活跃时长统计
- A4 工作节律状态机
- A5 休息提醒与起身提醒

### Epic B：桌面操作层

目标：先做最常见、最安全的桌面动作。

- B1 列出桌面项目
- B2 打开路径
- B3 桌面整理计划生成
- B4 桌面整理执行
- B5 桌面整理结果回传

### Epic C：受控 Shell 执行层

目标：让用户能执行明确的命令，但始终保留控制权。

- C1 命令草稿模型
- C2 命令预览确认卡
- C3 受控执行器
- C4 输出摘要与可中止

### Epic D：按需内容分析

目标：只在用户触发时读取剪贴板，并且只做单次分析。

- D1 剪贴板按需读取
- D2 单次分析模板
- D3 脱敏结果展示
- D4 分析结果不落盘策略

## 2. 推荐排期

### 第一阶段

1. A1 前台应用类别感知
2. A2 今日输入字符数统计
3. A4 工作节律状态机
4. A5 休息提醒与起身提醒

理由：这部分最容易形成用户感知，同时风险最低。

### 第二阶段

5. B1 列出桌面项目
6. B2 打开路径
7. B3 桌面整理计划生成
8. B4 桌面整理执行

理由：桌面整理是最直接的“手和脚”能力。

### 第三阶段

9. C1 命令草稿模型
10. C2 命令预览确认卡
11. C3 受控执行器
12. C4 输出摘要与可中止

理由：Shell 能力价值高，但风险也高，应该在前两阶段稳定后再上。

### 第四阶段

13. D1 剪贴板按需读取
14. D2 单次分析模板
15. D3 脱敏结果展示
16. D4 分析结果不落盘策略

理由：按需内容分析对用户最敏感，建议最后上线。

## 3. 每个任务的验收标准

### A 组验收

- 能识别当前前台应用的大类。
- 今日输入字符数只显示聚合数字。
- 统计结果可用于提醒，但不包含内容正文。
- 休息提醒不依赖内容级监控。

### B 组验收

- 能列出桌面项目。
- 能预览桌面整理计划。
- 用户确认后可实际整理。
- 不覆盖已有文件。
- 失败时有明确错误反馈。

### C 组验收

- 命令必须先生成草稿。
- 草稿必须包含命令、目录、超时和影响说明。
- 用户可以确认或取消。
- 执行过程中可以中止。
- 输出结果可见且不超过限制。

### D 组验收

- 剪贴板只在用户触发时读取。
- 分析只执行一次。
- 原文不落盘。
- 分析结果默认脱敏。

## 4. 风险与依赖

### 高风险项

- 任意 Shell 执行
- 文件移动和重命名
- 剪贴板读取

这些都必须带确认或按需触发。

### 关键依赖

- 工作节律状态机依赖前台应用感知和输入统计
- 桌面整理依赖路径定位和文件操作能力
- Shell 层依赖统一的动作草稿和确认卡
- 剪贴板分析依赖一次性读取机制

## 5. 推荐开发原则

1. 先做聚合指标，再做内容能力。
2. 先做只读感知，再做写入动作。
3. 先做桌面整理，再做 Shell。
4. 所有高风险操作都要有确认卡。
5. 所有结果都要可解释、可追踪。

## 6. 建议的实施节奏

### Sprint 1

- 前台应用感知
- 今日输入字符数
- 工作节律提醒

### Sprint 2

- 桌面项目列表
- 打开路径
- 桌面整理计划

### Sprint 3

- 桌面整理执行
- 命令草稿与确认
- 受控 Shell 执行

### Sprint 4

- 剪贴板按需读取
- 单次分析模板
- 脱敏展示

## 7. 结论

这份拆解的目标不是一次把所有能力做完，而是把“能主动帮忙”的能力按风险和价值分层推进。

如果按这个顺序推进，Piko 会先变得更懂节奏，然后更会做桌面任务，最后才开放更强的执行能力。
