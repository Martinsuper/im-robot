# Piko 产品迭代路线图

> 面向产品决策的版本：强调用户价值、阶段目标、优先级和验收指标  
> 基于现状：桌面骨架、对话、提醒、专注模式、受控写入、基础插件与记忆系统已具备

## 1. 产品定位

Piko 的目标不是做一个“能聊天的桌面工具”，而是做一个“会看场景、会记住用户、能受控执行任务的桌面伙伴”。

因此，后续迭代不应再以“新增能力数量”为主，而应围绕以下三件事展开：

1. 让新用户更容易上手。
2. 让精灵更懂当前场景和用户状态。
3. 让数据、记忆和插件能力可以长期扩展。

## 2. 当前阶段判断

当前产品已经从 MVP 进入“可用但需要产品化”的阶段。

已完成的底座包括：

- 桌面精灵、对话气泡、面板、截图提问
- 提醒、专注模式、TTS、受控写入
- 多提供商模型接入
- 基础插件运行时
- 记忆中心与长期记忆方向

这意味着下一阶段的重点不是补“基础功能缺口”，而是补“产品闭环”。

## 3. 核心策略

### 3.1 先做高频闭环

优先完善用户最常用的链路：

- 首次打开 -> 配置模型 -> 成功对话
- 对话 -> 提醒 / 日程 / 专注任务 -> 确认执行
- 使用中 -> 记住偏好 -> 下次更顺手

### 3.2 先降打扰，再加智能

Piko 是桌面伴侣，不是高频弹窗工具。

所以新能力的默认策略应是：

- 默认安静
- 只在有明确价值时打断
- 高风险动作必须先预览再确认

### 3.3 先本地闭环，再平台化

先把本机内的体验做完整，再考虑更复杂的同步、插件分发和生态扩展。

## 4. 阶段规划

## Phase 1: 上手与留存

### 目标

让用户第一次安装后，能快速完成配置并建立使用习惯。

### 重点功能

- 首次启动引导
- 模型服务配置引导与连接测试
- 自动更新
- 国际化
- 更完整的空状态、错误提示和恢复路径

### 用户价值

- 降低安装后的流失
- 降低配置门槛
- 降低“我不知道怎么开始”的阻力

### 验收标准

- 首次启动能进入引导流程
- 完成引导后可直接进入主界面
- 用户能在最少步骤内完成一次成功对话
- 更新和失败状态都有明确反馈

### 优先级

P0 / 最高

## Phase 2: 场景感知与陪伴感

### 目标

让 Piko 在不同工作场景下表现得更像一个“懂分寸”的伙伴。

### 重点功能

- 前台应用感知
- 空闲、专注、会议等状态联动
- 精灵情绪与行为联动
- 更统一的打扰策略

### 用户价值

- 减少打扰
- 提升“像活的”体验
- 增强长期陪伴感

### 验收标准

- 在 IDE / 编辑器场景降低互动频率
- 在会议或高专注场景尽量静默
- 在轻松场景恢复正常互动
- 不保存窗口标题历史，不做内容级记录

### 优先级

P1

## Phase 3: 记忆与迁移

### 目标

让 Piko 记住用户的稳定偏好和长期任务结果，并且可查看、可删除、可迁移。

### 重点功能

- 记忆中心增强
- 长期记忆检索
- 记忆分类、合并、过期与删除
- 通用数据导入导出

### 用户价值

- 让产品越用越顺
- 降低换设备成本
- 提升数据可控性和信任感

### 验收标准

- 用户能查看“Piko 记住了什么”
- 用户能删除或清空记忆
- 导入导出不包含 API Key 等敏感信息
- 记忆可在后续对话中被合理引用

### 优先级

P1 / P2 之间

## Phase 4: 任务扩展与平台化

### 目标

让 Piko 从单一助手升级为可扩展的任务平台。

### 重点功能

- 系统日历双向同步
- 更完整的业务插件生态
- 动态 WASM 插件沙箱
- 内置插件扩展到笔记、搜索、任务类能力

### 用户价值

- 支持更多结构化任务
- 把模型能力变成可控工具能力
- 为后续生态留接口

### 验收标准

- 插件遵循 manifest 和权限边界
- 高风险操作仍需确认
- 插件不能直接获得任意文件或 Shell 权限
- 日历同步可见冲突并可人工处理

### 优先级

P2

## 5. 推荐排期

### 第一批

1. 首次启动引导
2. 自动更新
3. 国际化基础

### 第二批

4. 前台应用感知
5. 精灵情绪与打扰策略
6. 场景联动优化

### 第三批

7. 记忆中心增强
8. 长期记忆检索
9. 数据导入导出

### 第四批

10. 系统日历双向同步
11. 插件沙箱
12. 更多业务插件

## 6. 核心指标

建议重点关注以下指标，而不是只看功能是否“做完”：

- 首次启动完成率
- 首次成功对话率
- 7 日留存
- 30 日留存
- 提醒 / 日程 / 专注功能使用率
- 记忆查看与删除使用率
- 插件确认通过率

## 7. 约束与红线

以下内容不进入下一阶段规划：

- 持续读取屏幕内容
- 摄像头或麦克风访问
- 未经确认的文件删除、移动、覆盖
- 未经确认的消息发送、邮件发送或发布内容
- 支付、下单、账户变更
- 模型执行任意 Shell 命令

## 8. 结论

后续迭代的正确顺序是：

1. 先把上手链路打通。
2. 再把场景感知和陪伴感做出来。
3. 然后把记忆和迁移能力补齐。
4. 最后再平台化扩展插件和同步能力。

这样 Piko 才不会变成“功能很多但不好用”的桌面应用，而是一个能持续使用、持续扩展的产品。
