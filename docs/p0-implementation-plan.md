# Piko P0 功能设计与实施路线

> 状态：实施中  
> 基线：Tauri 2 + React + TypeScript + Rust  
> 原则：每个阶段独立可验证，不向模型暴露任意 Shell 执行能力。

## 1. 当前基线

已具备：

- `pet`、`bubble`、`panel` 三窗口骨架
- 托盘菜单、全局快捷键、精灵自由拖动和位置恢复
- 互动活泼度持久化
- OpenAI-Compatible 模型设置、Keychain 存储、模型探测
- SSE 流式聊天

第一批可靠性补强：

- 修复 SSE 监听启动竞态
- 修复 Windows 和 Linux 全局快捷键修饰键
- 增加 `chat_cancel`、复制结果、对话历史和清除入口
- 将聊天生命周期广播给精灵窗口
- 建立前端状态机单测入口

## 2. 分阶段实施

### 阶段 A：对话可靠性

目标：让已有文本聊天达到可日常使用的最低标准。

实现项：

- `chat_cancel`：Rust 层登记当前请求，前端可停止流式读取
- 复制结果：使用浏览器剪贴板 API
- 对话历史：Rust 层保存最多 50 条精简会话记录，面板提供列表和清除入口
- 错误处理：区分连接失败、HTTP 错误、取消和超时
- 精灵联动：通过窗口事件同步 `thinking`、`speaking`、`idle`、`error`

验收：

- 快速模型不会丢失首个 SSE 文本片段
- 生成过程中可停止，停止后可再次提问
- 回复可复制
- 重启后可读取历史，清除后不可恢复

### 阶段 B：文本文件交互

目标：支持单个受控文本附件，不让模型直接访问任意文件。

> 状态：已完成。气泡窗口支持拖入单个文本文件、预览、移除，以及显式选择“总结”“翻译”“解释”后发送。

IPC：

```text
prepare_text_attachment(path) -> AttachmentPreview
clear_text_attachment()
```

约束：

- 仅允许用户主动拖入或选择的单个文件
- 默认支持 `.txt`、`.md`、`.json`、`.csv`、`.log`
- 限制文件大小，建议 `1 MiB`
- Rust 层读取并返回预览、字符数和脱敏后的显示名
- 发送时由前端明确选择“总结”“翻译”“解释”
- 附件正文只暂存在 Rust 内存中，历史记录仅保存动作和脱敏显示名
- 日志不得记录正文和真实路径

验收：

- 非文本文件、超大文件和读取失败均有明确提示
- 模型上下文只包含用户确认后的附件文本

### 阶段 C：提醒与通知

目标：支持一次性提醒并在到点后发送系统通知。

> 状态：已完成。面板可创建、查看和删除提醒；后台调度器会恢复未触发记录，并在到点后仅通知一次。

IPC：

```text
create_reminder(input) -> Reminder
list_reminders() -> Reminder[]
delete_reminder(id)
```

数据：

- 使用配置目录下的 `reminders.json` 保存 `id`、`title`、`due_at`、`status`
- 启动时恢复未触发提醒
- 使用 Tauri 通知插件按需请求权限

验收：

- 可创建、查看、删除提醒
- 重启后提醒仍存在
- 到点仅通知一次

### 阶段 D：截图提问与权限中心

目标：只在用户主动触发时截图，发送前必须预览。

> 状态：部分完成。权限中心已上线，展示通知、文件访问、屏幕录制和主动感知状态；截图选择窗口和发送前预览待实现。

窗口：

- 新增全屏透明 `capture` 窗口
- 选择区域后展示预览卡
- 用户确认后才进入模型请求

权限中心展示：

- 通知权限
- 屏幕录制权限
- 文件访问说明
- 暂停感知状态

约束：

- 不持续读取屏幕
- 不在日志写入图片正文或真实文件路径
- macOS 屏幕录制权限按需申请

### 阶段 E：个性化与系统集成

目标：完成 P0 设置面板。

> 状态：已完成基础入口。已实现精灵名称、主题色、互动活泼度、开机启动、暂停感知、清除历史和检查更新入口；联网更新需在发布源确定后接入。

实现项：

- 精灵名称、主题色、互动活泼度
- 开机启动开关
- 检查更新入口
- 暂停感知开关
- 清除历史入口

验收：

- 设置重启后恢复
- 平台不支持的能力明确标注

## 3. 数据与安全边界

- API Key 只进入操作系统安全存储。
- SQLite 不保存 API Key、附件正文、截图正文或完整日志。
- IPC 使用白名单命令，不暴露 Shell。
- 文件和截图必须由用户主动选择，发送前提供预览。
- 高风险操作遵循“先预览、再确认、可撤销”。

## 4. 实施顺序

按以下顺序连续推进：

1. 阶段 A：对话可靠性
2. 阶段 B：文本附件
3. 阶段 C：提醒与通知
4. 阶段 D：截图与权限中心
5. 阶段 E：个性化和系统集成
6. 阶段 F：CI、E2E、安装包和跨平台冒烟
