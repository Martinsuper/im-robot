# Piko 桌面代理开发里程碑

> 依赖：[桌面代理实施设计](desktop-agent-implementation-design.md)  
> 目标：把桌面代理能力拆成可按周推进的开发计划

## 1. 里程碑总览

### Milestone 1：节律感知与轻提醒

目标：让 Piko 先能“看节奏”，再决定要不要打扰。

包含能力：

- 前台应用类别感知
- 今日输入字符数统计
- 今日输入活跃时长统计
- 工作节律状态机
- 休息提醒

### Milestone 2：桌面操作层

目标：让 Piko 先能安全地做桌面事务。

包含能力：

- 列出桌面项目
- 打开路径
- 生成桌面整理计划
- 执行桌面整理
- 返回整理结果

### Milestone 3：受控 Shell 执行层

目标：让用户可以在确认后让 Piko 执行命令。

包含能力：

- 命令草稿
- 命令确认卡
- 受控执行器
- 可中止执行
- 输出摘要

### Milestone 4：按需剪贴板分析

目标：只在用户主动触发时读取剪贴板并分析。

包含能力：

- 单次读取
- 单次分析
- 脱敏展示
- 原文不落盘

## 2. 按周推进建议

### 第 1 周

- 前台应用类别感知
- 今日输入字符数统计
- 工作节律状态机基础

验收：

- 面板能看到工作节律状态
- 今日输入字符数能更新

### 第 2 周

- 休息提醒
- 起身提醒
- 专注模式联动

验收：

- 提醒不依赖内容级监控
- 用户可关闭或延后提醒

### 第 3 周

- 桌面项目列表
- 打开路径
- 桌面整理计划生成

验收：

- 能看到桌面文件预览
- 能看到整理计划

### 第 4 周

- 桌面整理执行
- 整理结果回传
- 错误处理和失败恢复

验收：

- 用户确认后可执行整理
- 不覆盖已有文件

### 第 5 周

- 命令草稿模型
- 命令预览确认卡
- 受控执行器

验收：

- 每条命令先进入草稿
- 用户可确认或取消

### 第 6 周

- 受控 Shell 中止
- 输出摘要
- 执行历史摘要

验收：

- 命令可中止
- 输出不会无限制展示

### 第 7 周

- 剪贴板单次读取
- 剪贴板单次分析
- 脱敏结果展示

验收：

- 只在用户触发时读取
- 原文不落盘

### 第 8 周

- 任务收尾
- 权限文案整理
- UI 文案统一
- 文档和测试补齐

验收：

- 主流程完整
- 风险边界明确
- 设计与实现一致

## 3. 依赖关系

### 高依赖项

- 工作节律状态机依赖前台应用感知和输入统计
- 桌面整理依赖路径打开和文件列表
- Shell 执行依赖草稿和确认卡
- 剪贴板分析依赖单次读取机制

### 先后关系

1. 先做节律感知
2. 再做桌面整理
3. 再做受控 Shell
4. 最后做剪贴板按需分析

## 4. 风险控制

### 最高风险

- 任意 Shell
- 文件移动
- 剪贴板正文读取

### 控制方式

- 先预览后确认
- 只读优先
- 明确可中止
- 不保留原文

## 5. 推荐交付标准

每个里程碑至少要满足：

- 有明确输入和输出
- 有事件通知或状态刷新
- 有错误反馈
- 有最小测试覆盖
- 有文档记录

## 6. 结论

这份里程碑表的目标不是“快做完”，而是“按风险和价值顺序稳步推进”。

如果按这个节奏，Piko 会先有节律感，再有桌面操作能力，最后才开放更强的受控执行能力。
