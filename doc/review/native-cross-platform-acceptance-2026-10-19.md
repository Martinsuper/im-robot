# 原生与跨平台验收（2026-10-19）

## 独立环境

正式 Piko 保持运行。验收应用使用独立 bundle identifier、配置/数据目录、全局快捷键和空凭据命名空间。为确保不同应用标识不会读取正式 API Key，凭据服务名现在使用 Tauri identifier；正式 identifier 对应服务名保持原值。

构建采用单独的配置覆盖，生成 Piko Acceptance.app。测试开启主动感知暂停、关闭休息提醒，模型仅连接本机模拟 HTTP 服务，没有向云模型发送数据。首次准备配置时应使用合法主题 `sage` 或 `blue`，不能使用 UI 未定义的 `light`。

## 已验证的真实 WebView 流程

- 首次启动、跳过引导，主面板与宠物窗口正常显示。
- 通过 UI 创建测试记录和完整备份，随后新增第二条对照记录。
- 使用原生文件夹选择器预览快照，确认恢复后显示阻塞遮罩并自动重启。
- 重启后，新进程正常显示主面板；磁盘和 WebView 均只保留备份中的第一条记录，第二条对照记录已移除，恢复日志已清理，回滚快照保留。
- 名称修改自动保存，并同步到主面板、对话和宠物窗口；正常退出后仍持久化。
- 未授予屏幕录制权限时，截图入口显示明确错误，窗口仍可使用；没有擅自授予系统权限。
- 对接仅监听 127.0.0.1 的模拟模型，真实 Rust/Node Agent 发起请求；停止按钮令界面恢复可输入且子进程退出。
- 再启动一个模拟请求，正常退出验收应用后，应用与 Agent 子进程均退出。

截图成功及授权后恢复路径需要用户为验收应用授予屏幕录制权限，尚未验证。测试未申请麦克风、输入监控或日历权限。

## 远端验证与修复

草稿 PR：https://github.com/Martinsuper/im-robot/pull/22 。使用临时 Git 索引生成独立分支快照，本地 main 和原暂存区不变；未纳入个人配置与运行时文件。

第一轮前端和安全审计通过；原生矩阵发现：

- Ubuntu 22.04 的 PipeWire 头文件不兼容 xcap 0.9.8 所需绑定。最终固定 xcap 0.8.0（0.8.3 同样会带入更新绑定），保留 Ubuntu 22.04 验证基线；复查 Cargo 审计仍为零漏洞。
- Windows 暴露 macOS 菜单导入、日历授权函数和通知参数的条件编译缺口。按平台限定导入，并让非 macOS 日历授权明确失败；没有开放不支持的平台能力。

第二轮远端结果：待完成。
