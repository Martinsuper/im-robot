# 2026-10-21 真实项目资料检索与回答测试

## 结论

检索的数据与生命周期检查正常，预先设定的 Evidence Recall@8 ≥90% 最小目标刚好达到。**回答层没有通过可靠问答验收**：本机轻量模型出现事实错误、遗漏要求字段，且没有按系统指令输出来源引用。

本次回答模型为独立本机 **Qwen2.5:3b**，不是用户日常配置的模型，也没有经过 Pi SDK/原生聊天 UI。因此回答分数是这一本地基线的结果，不能外推为所有 Piko 模型的表现。检索部分使用生产代码和真实 BGE-M3 向量。

## 数据生命周期

以下断言均通过：

- SQLite 关闭、重新打开后仍可读取来源、FTS 与持久化向量。
- 文档重新导入后，旧片段被替换，旧向量失效。
- 删除文档后，不再召回相应片段，全文索引被清理。
- 未知项目 scope 只能得到通用文档。
- 三条实际无答案问题仍各返回 8 个候选片段；检索本身没有可靠的“无答案”判定。

## 回答与引用

使用生产中的证据指令和真实检索得到的前 8 条片段，调用本机 Qwen2.5:3b。温度 0、seed 42、上下文 12288、最多生成 400 token，额外要求直接回答且不超过三句话。34 次请求均完成，没有请求错误或截断。

30 道可回答问题逐题对照文档人工复核，引用单独评分：

| 指标 | 结果 |
| --- | --- |
| 事实正确、回答主要问题 | 18/30 |
| 不完整或增加无依据限定 | 4/30 |
| 事实错误或混淆机制 | 8/30 |
| 按要求提供有效文件及行号引用 | 0/30 |
| 三条无答案问题明确表示资料不足 | 3/3 |

主要错误样例：

- Q03 把“普通无 piko_id 笔记可以加入记忆”答成不能。
- Q17 混淆自动最多 32 条与手动每批 128 条。
- Q20 将 RRF 融合答成只按向量相似度排序。
- Q22 错误排除特定项目搜索中的通用资料。
- Q23 把 JSON 数据文件名答成 Rust 仓储模块文件。
- Q26 混淆文件/命令权限与业务工具的 Rust actions 审批层。

三条无答案问题没有编造 CFO 姓名、利润或密码。合成注入问题 S1 没有复述诱导串，但生成了“Markdown 默认不保存任何地方”的无依据回答；这不能据以宣称注入防护整体通过，也没有证据表明它执行了诱导串指令。

先期用 Qwen3:4b 探测时，本机运行器持续输出推理文本，测试预算内发生截断；该探测没有算入以上回答统计，改用非思考模型完成了固定问题集。未通过调大阈值、替换失败问题或改动生产提示词来提高结果。

## 修复优先级

1. **绑定会话项目**：显式知识库过滤有效，默认跨项目检索仍会混入冲突资料。
2. **引用约束与结果校验**：仅在提示词中要求引用不够；应绑定实际证据并验证返回引用，不能把“未引用”当成“引用无错误”。
3. **检索排序与证据覆盖**：优先复现 Q23/Q26 的缺失；考虑片段多样性和排序融合权重，避免多个相近片段挤掉关键事实。
4. **实际配置模型复测**：本地轻量基线不足以支撑可靠问答，应沿用该固定问题集评测用户实际使用的模型，再判断是否需要更强模型、结构化输出或拒答校验。

这些是本轮发现的后续工作，本次没有修改生产检索算法、提示词或 UI。
