# 聊天历史与设备会话恢复修复

## 行为

- 每轮 Agent 聊天把 conversationId 和正文一起写入 chat-sessions.json。会话查询不再依赖最近 100 个任务的日志。
- 首次读取旧数据时，先保留原始聊天文件备份，再按现有任务日志补齐会话关联；持久化迁移标记。后续读取不再查询任务日志。
- 迁移标记纳入数据快照，恢复旧快照时不会错误跳过迁移。
- 左侧设备历史与打开的标签分离：历史每次显示 20 个，点击后才打开聊天组件；关闭标签不删除历史，也不会在重启后自动重新打开。
- 历史打开、任务续跑和运行任务恢复遵守主窗口的 12 标签限制。设备读取默认草稿不再分配窗口缓存名额。
- 历史读取失败返回错误；侧栏、聊天区、记录页保留上次成功内容并允许重试。导出遇到聊天读取错误也中止，避免静默导出空记录。
- 删除没有引用的 modelConnectionStatus.ts，恢复项目检查。

## 验证

- npm run verify：通过，包括项目检查、lint、348 项前端测试、80 项 Agent 测试和生产构建。
- cargo test --locked --manifest-path src-tauri/Cargo.toml --lib：400 项通过，8 项忽略，0 项失败。
- Playwright conversation-tabs.spec.ts 与 records-smoke.spec.ts：8 项通过。
- 回归覆盖：110 个后续任务清理旧日志后原聊天关联仍存在；任务日志损坏不影响已迁移记录；会话关联导入导出往返；40 个历史会话仅挂载已打开的窗口；关闭和重启；12 标签上限；读取失败保留内容及重试。

本次没有修改正在运行的应用数据，没有打包安装或推送代码。旧数据补齐会在运行新版后自动执行；已经不在旧任务日志中的关联无法凭空重建，未关联正文仍保留在记录页。
