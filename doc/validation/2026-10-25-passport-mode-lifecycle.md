# 音频与 BLE 资源按模式切换

## 改动

- 音频 init 幂等，按模式创建队列、worker、codec/I2S；不再在开机时常驻。
- deinit 先禁止新的数据 API 访问，再等待 worker 完成本次 I/O 并退出，随后释放队列和 DMA。persistent mutex 协调迟到回调与资源删除。
- 退出超时保留资源和 pending 状态，允许后续完成清理；禁止覆盖尚未释放的队列。BSP 释放失败同样保留 pending，不能误报已恢复。
- BLE 使用明确的主机任务退出握手，停止后依次清理 HID/事件循环、NimBLE 和控制器；部分失败可以从剩余阶段重试。停止过程禁止断线回调重新广播。
- 页面处理阻止失败的模式切换，恢复音频时应用已保存音量。退出翻页会断开连接，配对记录不清除。
- BSP 全量释放入口通过 build-local 源码扩展实现；SDK/vendor 源文件未修改。

## 验证

主机测试：40 轮真实 audio worker 的释放/重建（pthread/I2S doubles）、正在读写时退出、2 秒停止超时及清理重试、并发 capture/status、幂等 init；队列计数回到零。AddressSanitizer 检查通过。BLE teardown 50 轮及各阶段失败重试、退出握手超时测试通过。原有语音输入协议、UI、录音积压/取消/音频顺序等回归通过。

实机临时诊断版自动执行 8 轮：本地短录音（内容丢弃，不发送）、静音播放、释放音频、进入 BLE 与真实页面绘制、关闭 BLE、回到普通页面。每轮录音/播放及初始化均成功，日志出现 PASS 8 real audio/BLE lifecycle cycles。蓝牙视图余量约 49.7–50.1 KB；释放后约 116.0–116.2 KB（首轮约 116.5 KB），没有看到大块缓冲持续占用，期间未崩溃。小幅波动仍受 Wi-Fi 等系统活动影响，8 轮不能证明无限期无泄漏。

最终构建关闭自动诊断，编译命令确认无 PIKO_MODE_LIFECYCLE_TEST 定义。只刷应用区，esptool 数据校验通过；正常启动取得原 Wi-Fi IP，初始内容视图空闲堆约 111.8 KB。

最终镜像、SHA-256、诊断及正常启动日志位于忽略提交的 firmware/passport/backup/20261025-mode-lifecycle/。已有备份保留。实机循环未主动向配对电脑发送 HID 按键；真实电脑配对后的停止/回连、最终端到端语音输入仍需用户操作确认。
