# Passport 随身语音输入接入

日期：2026-10-24。

## 功能与模式

新增第六个“输入”入口，与原有 Piko 陪伴、专注、消息、语音助手、连接页面并存。第一版是独立输入模式入口，还不是完整的通用应用启动器。

- **Piko → 语音**：麦克风 → Piko 桌面端 → ASR/助手/设备回复。
- **随身语音输入**：麦克风 → Wi-Fi UDP → 原项目电脑客户端 → 虚拟声卡 → 输入法 → 电脑当前光标。识别服务由输入法提供，不由设备执行。

本次采用 [folo-ai-passport-voice](https://github.com/manchunx7-bit/folo-ai-passport-voice) 固定版本 `378fb41e35f769d522ec797a54d714ee089ca74a` 的公开协议；复用其 MIT ADPCM 编码器，保留许可证和来源。上游公开的是语音模块，不是可直接构建的完整固件，因此没有导入其启动器及宿主 UI。

## 使用

1. 设备先完成已有 Wi-Fi 配置，与电脑处于同一局域网。此功能不要求先配对 Piko。
2. 按上游文档启动一个电脑客户端：
   - [Apple 芯片 Mac 教程](https://github.com/manchunx7-bit/folo-ai-passport-voice/blob/378fb41e35f769d522ec797a54d714ee089ca74a/macos/README.zh-CN.md)：需要 BlackHole 2ch、Python 客户端、输入法语音快捷键和相关权限。
   - [Windows 教程](https://github.com/manchunx7-bit/folo-ai-passport-voice/blob/378fb41e35f769d522ec797a54d714ee089ca74a/docs/QUICKSTART.zh-CN.md)：需要 VB-CABLE、客户端及输入法配置。
3. 设备上下切换到“输入”，屏幕显示发现的电脑 IPv4，核对后短按确定选择。
4. 在电脑上聚焦目标文本框；设备按住上键说话，松开结束。先核对电脑上的识别文字，再短按下键发送一次 Enter。Enter 在不同应用可能代表换行或发送。
5. 输入模式内短按确定退出控制；之后上下键可继续切换 Piko 页面。重新选择电脑后才能恢复输入。

UDP 端口固定为 33333，与原项目默认配置一致。一次只运行一个原项目电脑客户端。发现多个电脑时，设备保留首先发现且仍在线的候选；只启动目标电脑客户端可避免选错。界面显示 IP，不能验证电脑名称或身份。协议没有加密认证，物理确认用于选定目标，不能防止局域网地址伪造。

不必刷入上游整机固件；应使用本项目新增功能后的固件。本文不授权刷机，仍需先备份并核对设备和分区。

## 实现

- `main/voice_input.c` 是独立模式适配器，UDP socket 只在进入“输入”入口后打开，离开即关闭。不增加第二套 I2S 驱动或常驻音频任务。
- 复用 `passport_audio` 的有限录音队列；16 kHz、16 bit、单声道 PCM 按 1600 样本分块，编码为 804 字节独立 IMA ADPCM 数据块。
- 音频帧为 `[0x01][seq][0x80][804B block]`；事件为 `[0x02][JSON + 换行]`；兼容 `device.hello`、`voice.start`（`audio=ima_adpcm`）、`voice.end`、`key.action`（`action=enter`）。
- 校验来自 UDP 33333 的 PC beacon：`v=1, role=pc, port=33333`。用户确认前不发录音或键盘事件；选定后拒绝其他来源地址切换目标。入站命令/音频/审批事件均忽略。
- 收到上键释放后停止录音，排空队列并补零发送尾块，再发送结束事件；退出、Wi-Fi 断开、3 秒无有效 PC 信标、录音错误时取消。录音最长 60 秒，停止排空最多 500 ms；无界重试不占用 UI。
- 下键需要本模式中新一次按下，且不在录音或排空阶段，600 ms 防重复。只有主动按下才发送 Enter，不自动提交识别结果。
- 离开 Piko 语音页会取消原会话；输入模式期间忽略旧 Piko 语音回复，Piko WebSocket 断开不会取消输入模式的录音。设备配对凭证与桌面专注任务保留。
- 第六个底部导航入口使用现有界面，三个 UI 字体已重新生成。版本升为 `piko-0.7.0`，未更改分区表。

UDP 传输不保证音频或开始/结束事件可靠到达。原客户端的超时恢复仍然必要；这次没有增加与上游不兼容的 ACK 协议。设备不会获得输入法最终识别结果，文字核对在电脑上完成。
