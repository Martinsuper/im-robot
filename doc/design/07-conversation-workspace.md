# 聊天与主面板合并（第一版）

## 决策

以 `bubble` 作为唯一聊天与业务工作区窗口，不再创建独立 `panel` WebView。
`open_panel` 保留 IPC 兼容性，但改为显示 bubble 并发送 `workspace-open`。
顶部名称菜单只负责导航，不与标题栏拖动混用。菜单选择今天、记录、设置后展开右侧内容。

## 状态与布局

- 聊天组件始终挂载；展开、切换、收起不会取消任务或清空输入。
- 工作区首次访问栏目时加载，之后通过 hidden 保留表单、筛选和独立滚动容器。
- 本地存储记住最近栏目，不自动恢复展开，以免每次快速聊天都变成大窗口。
- 原生窗口展开时按当前显示器工作区限制尺寸和位置；收起恢复展开前尺寸和位置。
- 小于 880px 时使用工作区单页，返回聊天只改变可见性，不卸载会话。
- 数据更新通知改为应用事件，让合并后的工作区持续收到历史、记录、记忆、提醒等变更。
- 聊天和面板使用同一 settingsStore，避免同一窗口内设置副本漂移。
- workspace-ready 握手重放 WebView 初始化前的面板请求。

## 第一版不包含

引用卡片、AI 自动导航、完整历史会话恢复。这些按第二版推进。

## 验证

单元测试覆盖显示器边界与原生尺寸恢复；浏览器回归覆盖菜单、双栏、窄屏返回、草稿和栏目保留。
打包原生端还需人工验证多显示器、屏幕边界、系统托盘、首次引导和真实流式回复。

2026-10-22 开发验证结果：

- 前端单元测试：49 个文件，305 项通过（包含切换工作区时流式事件继续到达、未发送输入保留）。
- 浏览器针对性回归：31 项通过，涵盖工作区、面板、记录、设置与模型配置。
- Rust 单元测试：344 项通过，4 项显式忽略的原生/真实模型验收测试未运行。
- TypeScript / Vite 构建、ESLint、Rust 编译与格式检查通过。
- 架构边界与翻译键检查通过；Rust 第三方 xcap 仍有既有废弃 API 警告。

## 发布回归修正

完整浏览器回归额外发现：记录操作菜单的 Escape 事件会冒泡收起工作区；旧测试仍寻找独立面板的「开始对话」，双栏下全页按钮定位还会匹配聊天按钮。
修正版阻止菜单 Escape 冒泡，将返回聊天按钮保持为至少 36px 点击区域，并把相关测试定位限定在工作区内。已推送的 v1.2.17 标签保留，修正版使用 v1.2.18。


## 2026-10-22 布局优化方案与实现

目标：开关位置稳定，聊天为主、设置为辅；避免宽窗口展开时聊天突然收窄到600px。

- 开关固定在顶部左侧头像之前，展开/收起不改变槽位，保留选中状态、展开语义与名称菜单。
- 顶部不再按展开状态隐藏在线状态与副标题。副标题按聊天栏实际可用宽度收起；在线状态保持可用。
- 面板默认400px，可在360–480px范围内调节并保存到 `piko.workspace.width`；聊天使用剩余宽度且双栏下至少480px。
- 宽度不足时优先保证聊天480px，临时限制面板实际宽度但不覆盖用户保存的偏好。
- 分隔线支持拖动、左右方向键20px微调、Home/End到边界、双击恢复400px，并提供名称、方向、当前值及可用上限。
- 原生窗口宽度至少880px即可内部划分，不增加宽窗口的高度；紧凑窗口才扩大并约束在屏幕工作区内。
- 已有足够空间的原生窗口展开/收起不调整几何信息，也不退出最大化状态；因展开而调整过的窗口收起时恢复尺寸与位置。
- 小于880px使用单栏，隐藏分隔线，显示“返回聊天”；桌面并列显示时用“收起面板”。

验证：9项几何与原生窗口单测、15项面板/工作区端到端测试通过；覆盖开关坐标、右栏默认比例、拖动与键盘调宽、宽度记忆、草稿/筛选保留、窄屏返回。构建及相关ESLint通过。浏览器1200×800预览已目视检查，截图见 `artifacts/design-audit-panel-20261022/04-optimized-settings.png`。尚未重新打包安装本次改动，原生多屏与系统缩放仍需新版安装后验收。


## 原生窗口控制统一

- 聊天窗口始终启用系统标题栏及任务栏/Dock入口，窗口标题为Piko；pet和capture继续使用无边框浮层。
- 移除“在完整窗口继续/返回快捷浮层”按钮、模式状态及动态切换decorations/skipTaskbar的逻辑。
- 移除应用工具栏重复的关闭按钮；红色系统按钮继续走CloseRequested拦截，只隐藏窗口、不终止任务；Esc保留先关闭面板再隐藏聊天的顺序。
- 应用工具栏保留面板开关、名称菜单、状态、置顶、新对话。窗口缩放及全屏交给系统控制。
- 浏览器只能验证业务工具栏与会话行为；系统标题栏、红黄绿按钮、真正全屏和原生关闭拦截需要重新打包后在桌面端验收。
