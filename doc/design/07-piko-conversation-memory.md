# Piko 对话记忆：设计、实现与验收

## 产品行为

Piko 已有 SQLite 记忆库、记忆中心和聊天上下文检索。本次增加持久化的周期提取流程，并将原来的「每轮聊天直接把 AI 的任务完成声明写入记忆」替换为更可核实的候选审核流程。

- 默认开启，每 30 分钟增量扫描已保存的对话。
- 应用启动时补扫；应用关闭时不运行。不是操作系统后台服务，也不创建 Codex 定时任务。
- 后台每分钟检查是否到期；每批最多处理 100 条未处理对话，积压分批补扫。
- 「记录 → Piko 记住的」提供开关、间隔选择、立即提取和上次提取时间。
- 立即提取独立于自动开关，允许用户暂停自动任务后手动扫描。
- 提取出的记忆进入「待确认」，用户确认后纳入现有聊天上下文检索；拒绝后不反复提取相同事实。
- 删除已确认记忆后，旧对话不会自动重新生成它。

## 本次提取范围

使用本地、确定性的规则，不发送额外的模型请求，不增加模型费用。支持明确陈述的中文个人事实、偏好和习惯，以及部分英文表达，例如：

| 对话内容 | 结果 |
| --- | --- |
| 请记住：我不喜欢喝咖啡。我住在上海。 | 两条待确认的个人事实 |
| 我喜欢早上喝咖啡。 | 一条候选 |
| I prefer tea! | 一条候选 |
| 我希望你帮我写代码 | 不作为长期偏好 |
| 我喜欢喝咖啡吗？ | 不提取问题 |
| 助手回复「已完成支付」 | 不将助手声明作为事实 |
| 包含密码、API key、token 等敏感关键词 | 跳过该轮用户文本 |

每个事实最长 500 字。提取仅使用用户文本，不使用助手回复，也不推断未明确陈述的信息。用户审核是写入正式记忆的必要步骤。

规则不覆盖所有语言表达、隐含偏好、跨轮总结或语义冲突消解。精确内容去重不等于语义去重；同义陈述可能产生不同候选。偏好变化后，用户可在既有记忆详情中修改或删除旧事实。

## 数据与可靠性

在既有 `memory.db` 中按需建立四张表，无需修改现有记忆条目模型：

| 表 | 用途 |
| --- | --- |
| memory_extraction_settings | 自动开关、间隔、最近完整扫描时间 |
| memory_extraction_processed | 已处理的对话 ID，避免重启、拒绝和删除后的重复提取 |
| memory_extraction_candidates | 持久化候选 JSON，重启后仍可审核 |
| memory_extraction_seen | 内容的 SHA-256 指纹，跨对话精确去重；不保留被拒绝事实的明文副本 |

候选、指纹、来源 ID 和进度在同一个 SQLite 事务中提交。任何写入失败都会回滚，下次运行重试，不会把未成功保存的对话标记为已处理。SQLite 锁串行化手动与自动提取。

审核写入沿用现有记忆模型：个人事实属于 Profile，来源为 Conversation，只有 Active 正式记忆进入聊天上下文。失败时保留候选；审核写入成功、候选清理失败时，重试识别确定的记忆 ID 并继续清理，避免重复写入。

自动提取不再阻塞聊天完成事件。后台任务使用阻塞工作线程读取历史和操作 SQLite，异步循环只负责调度；异常写日志并在后续运行重试。前端显示设置／手动提取错误，状态每分钟及候选变化后刷新。

间隔后端允许 1–1440 分钟，界面提供常用值。系统时钟向后调整时重新检查，避免长期卡在未来的扫描时间。

## 接口与代码

- `get_memory_extraction_status`：读取启用状态、间隔、最近运行时间、已处理数、待确认数。
- `configure_memory_extraction`：持久化开关和间隔。
- `extract_memories_now`：手动执行一批，返回新增候选数。
- `get_pending_candidates`：合并持久化自动候选和既有手动候选。
- `apply_memory_candidates`／`reject_memory_candidate`：审核、拒绝持久化候选并刷新界面。
- `memory/extraction.rs`：调度、事务、规则和持久化逻辑。
- `MemoryExtractionControls.tsx`：提取设置和手动触发入口，支持中／英／日文。

同时修复候选命令的 `State<Arc<CandidateCache>>` 与实际注册的 `State<CandidateCache>` 不匹配问题，以及写入失败前移除内存候选的问题。

## 自动化验证

运行方式：

```sh
cargo test --manifest-path src-tauri/Cargo.toml --lib
npm test
npm run build
npm run lint
npx playwright test tests/e2e/memory.spec.ts
```

新增后端验证：

1. 时间间隔、关闭自动扫描、敏感文本过滤和每批 100 条上限。
2. 同一来源重试、拒绝后的幂等性，以及不同对话的内容去重。
3. 多条事实、负面偏好、英文偏好、问题和临时任务排除。
4. 关闭并重新打开真实文件数据库，候选及进度保留。
5. 数据库触发器注入写入失败，验证候选／指纹／进度一并回滚，再次运行成功。
6. 未确认候选不进入上下文，确认后可以被后续聊天检索。

新增前端验证：读取设置、保存开关与间隔、手动提取后刷新状态、错误反馈和重试。Playwright 验证 400×700 面板的记忆入口、提取控制、待确认视图和无横向溢出；浏览器预览明确显示桌面限制，不模拟后台提取。桌面调用行为由组件测试验证。
