# Markdown 记忆库与双向同步

## 使用

在桌面应用中打开「记录 → Piko 记住的 → Markdown 记忆库」。默认开启自动同步，默认目录为应用配置目录下的 `memory-vault`。面板会显示实际绝对路径，可直接打开目录，或选择现有 Obsidian vault 等其他文件夹。

```text
memory-vault/
  Piko 使用说明.md
  用户档案/
  事件记忆/
  项目知识/
  操作记录/
  反思总结/
  .piko-history/        # 文件替换前的本地恢复副本，不参与检索
```

每条有效、非私密记忆对应一篇 Markdown 笔记。文件名包含初始标题和 ID 哈希；修改标题后文件名保持稳定，避免破坏已有链接。YAML 与正文示例：

```markdown
---
piko_id: memory-example
type: profile
importance: 3
tags:
  - 个人信息
---

# 居住城市

我住在上海。
```

可以直接修改一级标题、正文、标签和重要度（0–5）；可以在分类目录中新建普通 `.md` 笔记，Piko 会分配编号并加入记忆。移动到其他分类目录会更新记忆类别。不要修改或复制 `piko_id`：同一编号代表同一条记忆。未知的 YAML 属性会在 Piko 写回文件时保留。

Piko 正在运行时，每约 15 秒比较一次两侧内容；启动后约 2 秒进行首次检查，也可以点击「立即同步」。暂停同步或关闭 Piko 后仍可编辑文件，下次同步会比较上次基线。更换目录会保留旧目录内容并停止同步旧目录。

## 检索

Markdown 是可读、可编辑的持久记忆文件；SQLite 继续作为检索索引。外部修改导入后，立即可以通过现有关键词检索和 `search_knowledge` 工具召回。旧向量会失效；如果用户启用了语义检索，现有后台索引服务会补建新向量。聊天和 Agent 每轮请求前仍主动检索相关记忆，不会每次把整个 Markdown 目录塞进上下文。

原始文档知识库（Markdown、TXT、PDF 导入）与这套记忆文件同步分开管理；原始参考文档变化目前仍需重新导入。

## 冲突与删除

| 检测结果 | 行为 |
| --- | --- |
| 只有 Piko 修改 | 更新 Markdown，替换前保存恢复副本 |
| 只有 Markdown 修改 | 更新记忆，保存 `markdownEdit` 修订并清理旧向量 |
| 两侧最终内容相同 | 更新同步基线，保留文件原有格式 |
| 两侧都修改且不同 | 保留双方，面板中比较并选择 Piko 或 Markdown |
| 文件被移走或删除 | 不自动删记忆；用户选择恢复文件或确认忘记 |
| Piko 删除、归档或隐藏记忆 | 删除未被外部修改的对应文件与恢复副本 |
| Piko 记忆失效但文件有新修改 | 不复活旧记忆；可删除文件或另存为一条新记忆 |
| YAML 无效、编号重复或编号被改动 | 保留原文，显示问题并等待手动修正 |

比较界面展示标题、正文、分类、标签和重要度。选择操作携带显示时两侧的版本指纹；文件或数据库在比较后又改变时拒绝旧选择，要求重新打开比较。

替换和删除前均检查文件内容是否仍是扫描版本。写文件使用同目录临时文件与原子替换。数据库导入采用事务和字段比较，避免覆盖并发更新。上次同步的语义指纹与文件指纹存于 `memory_vault_state`，重启后保留；错误与待处理项存于 `memory_vault_report`。

## 备份与恢复

数据库快照包含记忆、修订、同步设置和基线。外部 Markdown 文件、尚未导入的编辑以及 `.piko-history` 不会被现有数据库快照自动打包，请使用文件备份或 Obsidian 自己的同步保护这些文件。

从快照恢复数据库后自动暂停 Markdown 同步，并在面板说明原因。确认磁盘文件后再启用，避免较新的笔记立即覆盖数据库恢复结果。持久数据库不可用、应用降级为临时内存数据库时，不启动 Markdown 同步。

## 范围与限制

- 仅处理上述五个分类目录内的 UTF-8 `.md` 文件，不扫描说明文件或恢复副本目录。
- 每篇笔记最多 1 MB，一次扫描最多 10000 篇，目录深度最多 16 层。
- 跳过隐藏文件与符号链接；分类目录不允许为符号链接，拒绝相对路径穿越。
- 已同步目录不可用时报告错误，不把磁盘离线误判为批量删除。
- 普通文件系统不提供跨编辑器的事务锁。内容检查、原子写入和恢复副本用于避免常见覆盖问题；同时编辑同一篇笔记时仍建议等待一次同步完成。
- 仅本机同步，不新增云端同步、OCR 或 Obsidian 插件依赖。
