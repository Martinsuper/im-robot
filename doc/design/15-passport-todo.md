# Passport 待办事项：本地优先同步与 UI 设计

日期：2026-10-24。UI 初稿交互以本文为准（可视化稿见会话内 `passport-todo-ui` v3）。

## 背景与目标

在 Piko Passport 固件（`firmware/passport`，当前 0.9.0，语音输入 / Piko / 设置三页）中新增第四个页面"待办"。设备端只做**查询、勾选/重开、归档**；新增与编辑由外部完成——调用方将提供一套待办增、删、改、查接口，设备定时同步。核心需求：**离线时改动保存在设备本地，网络恢复后自动把本地待办更新到服务器**。

## 功能定位决策

- **V1 不做设备端删除**。删除只在接口侧（网页端/服务），通过同步单向流到设备。理由：设备不能新增，本地垃圾数据几乎为零，列表整洁靠"已完成折叠 + 归档"维持；去掉设备端删除后，本地变更只剩"完成/重开/归档"三种纯字段更新，同步协议不需要 tombstone 与"删除 vs 修改"冲突仲裁，是可单测的最简形状。
- **归档替代删除**：本质是 `archived` 状态位，与勾选同为普通字段更新，可逆、不需要确认弹窗。
- **新增/编辑不在设备端**：三键输入中文不现实，且与现有固件"配置走 portal 网页"的习惯一致。

## 数据模型

每条待办（纯 C 结构，UI 与同步层共享，可在主机上单测）：

```c
struct todo {
    char     uuid[37];    // 设备生成的 UUID，主键，推送幂等的关键
    char     title[64];
    char     note[128];
    char     due[24];     // 截止时间，展示格式；无则为空
    char     repeat[16];  // 重复规则文本；V1 只透传展示
    uint8_t  state;       // 未完成 / 已完成 / 已归档
    uint8_t  source;      // 来源：网页端 / 语音 / API
    bool     dirty;       // 本地有未同步改动
    uint32_t local_seq;   // 本地单调递增序号
    int64_t  synced_at;   // 上次同步成功时服务器返回的 updated_at（epoch 秒）
};
```

- **本地是唯一事实源**，服务器是副本；`deleted` 只从服务器往设备单向流（接口侧删除 → 下次同步拉掉），设备端不产生删除。
- 完成数、分页、折叠区均由纯函数从任务表推导，不单独存。

## 本地变更与 Outbox 队列

所有本地变更**先写任务存储，再向 outbox 追加一条变更记录**，两步都成功才算改完。outbox **按任务合并**：同一任务的多次改动只保留最新一条全量状态（推送是幂等全量 upsert，中间态无意义），队列不因反复编辑膨胀。队列与任务数据一起持久化，掉电不丢。

- 队列上限 200 条：超限先合并，仍超限淘汰最旧的"已归档任务"变更并记日志。
- 存储用 NVS（namespace `todo`）：NVS key 上限 15 字符，任务与队列条目按槽位序号存（`t0..tN` / `q0..qN`），一个 `meta` 条目记录槽位占用与 `local_seq` 计数器。8 MB Flash 下几百条绰绰有余。

## 同步方案

### 触发时机

- **网络恢复即触发**：Wi-Fi 连接事件后先做一次轻量连通性探测，成功立刻启动第一轮同步（离线积压推送的关键路径）。
- **变更后防抖**：本地改完 10 秒内无新改动即同步。
- **定时兜底**：在线时每 5 分钟对账一次。不做长连接长轮询，待办没有秒级时效需求。
- **失败退避**：30 s → 1 min → 5 min → 15 min；任何新的本地变更或重连事件立即重置退避。

### 一轮同步：先推后拉

**推**：outbox 按 `local_seq` 顺序批量上送（每条带 `client_uuid`，服务器按 UUID upsert 幂等）。逐条 ack 后移出队列；中途断网下次重推，幂等保证不产生重复。全部推完再拉，避免本地改动被服务器旧数据覆盖。

**拉**：`GET /todos?since=<cursor>` 增量拉取，逐条与本地合并：

- 本地不 dirty → 直接覆盖；
- 两边都改过 → **整条 Last-Write-Wins**：比较服务器 `updated_at` 与本地 `synced_at`，新的赢。待办场景冲突损失极小，不做字段级合并；
- 服务器已删除 → 本地真删。

cursor 存 NVS，每轮同步成功后更新。

### 时钟问题（设备无 RTC，必答项）

重启后本地时钟不可信，未校时前**只推不拉、不做任何 LWW 覆盖**；未同步变更之间的顺序只看 `local_seq`。每次同步成功后立刻校时（SNTP，失败则取 HTTP 响应 `Date` 头），校时完成后的轮次才启用时间戳仲裁。

### 对接口的要求与适配层

理想接口形状（与接口方确认）：

| 端点 | 作用 | 缺失时的退化 |
| --- | --- | --- |
| `PUT /todos/batch`（按 client_uuid 幂等 upsert） | 推送 | 单条 upsert，逐条发 |
| `GET /todos?since=cursor` | 增量拉取 | 全量拉取 + 本地对账（任务量小反而更可靠） |
| 响应含 `server_time` 与每条 `updated_at` | LWW 与校时 | **必须有**；完全没有则退化为"设备单向赢"：本地 dirty 一律覆盖服务器，接口侧修改会被冲掉 |

接口适配层（`todo_api.c`）把实际接口包成上述形状，同步状态机不感知具体 REST 细节。

## UI 设计（对齐现有页面）

沿用现有主题：米纸底 `#f6f1e7`、墨绿 `#315446`、强调绿 `#315e49`、灰绿辅助 `#70806d`、白卡片 + `#e3e5d8` 描边 + 柔和阴影、Noto Sans SC 14/20px。唯一功能色是逾期/警示暖红 `#b3573f`。

### 页面结构（共 1 个导航页 + 1 个下一层详情页）

- **导航**：底部药丸标签从三个变四个："语音输入 / Piko / 设置 / 待办"。导航组件不改，`PAGE_COUNT 3→4`，`names[]` 追加"待办"。四个标签宽度实测可容纳。
- **浏览态**（未进入）：与其他页面一致——上下键切到"待办"时列表仅预览（无选中高亮），底部提示"短按确认进入 · 上下切页"，OK 进入锁定。
- **列表页**（已进入）：
  - 页头："待办"（20px）+ 副标（"今天 · 3/5"或"离线 · 上次同步 09:12"）。
  - 任务行：白卡片、圆形勾选框（完成态实心绿 + 白勾）、标题（超长省略）、右侧截止时间（今天/逾期用暖红，其余灰绿）。
  - 选中行：10% 绿底 + 描边加深，与设置页菜单选中样式同款。
  - **已完成折叠区**：列表底部虚线分隔的"已完成 N"，任务划线置灰。列表主体永远只剩未完成的事——这是不需要删除功能的根本。跨天后已完成自动收拢。
  - 底部提示："OK 勾选/重开 · 长按 详情"。
- **详情页**（列表的下一层，非导航页）：
  - 面包屑"待办 · 详情"、任务标题（19px）、状态胶囊、元信息行（截止 / 重复 / 来源 / 最近修改）、备注正文卡片。
  - 底部提示："OK 完成/重开 · 长按 归档返回"；上键返回列表。
  - 长按 = 归档并返回，对齐设置页"长按返回"的肌肉记忆。
- **离线态**（列表页自身的状态，非独立页面）：右上角同步胶囊变黄显示"N 条待同步"，改动过的任务行带"待同步"小标；联网推送成功后自动消失。同步中胶囊显示"同步中…"，失败显示"上次同步 HH:MM"。
- **退出/切页**：进入待办页后 OK 被勾选占用，不能沿用输入页"短按 OK 退出"；约定为**选中第一行再按上键 / 最后一行再按下键，直接切换到相邻页面**，与浏览态"上下切页"连续，不引入新手势。

### 按键表

| 页面 | 操作 | 效果 |
| --- | --- | --- |
| 列表 | 上下短按 | 移动选中行（首末行越界 = 切换页面） |

## 实现模块

```
main/
  todo_page.c/.h     页面适配器：LVGL 列表/详情、按键路由接入 piko_control
  todo_model.c/.h    纯数据模型与推导函数（主机可单测）
  todo_store.c/.h    NVS 持久化：任务槽位 + outbox 队列 + cursor
  todo_sync.c/.h     同步状态机：触发、退避、先推后拉、校时
  todo_api.c/.h      接口适配层：把实际 REST 包成 batch-upsert / since拉取
```

- 按键路由接入 `piko_control`（`ui_controls.h`）：新增 `PIKO_TODO` 页面分支，锁定态路由按上表；浏览态沿用全局逻辑。
- 字体：界面新增字符（含"待办归档已同步离线来源截止重复"等）加入 `font-characters.txt` 重新生成三套字体；启动沿用缺字检查。
- 版本升至 `piko-0.10.0`，分区表不动。
- 参照 EVA 的内存做法：任务行 `lv_obj` 复用不重建，状态变化只改样式与文本。

## 里程碑

1. **M1 本地待办**：数据模型 + 存储 + 列表页/详情页 UI，纯本地勾选与归档，无同步。
2. **M2 同步**：接口适配层（依赖接口文档确定）+ 同步状态机 + 校时，实机联调。
3. **M3 体验补全**：同步胶囊三态、折叠区跨天收拢、字体与缺字检查、模拟器回归。
4. **M4 发布**：`package.py` 打包、README 更新页面说明。

M2 是接口依赖点：接口形状确认前，M1 可先行。

## 风险与开放问题

- **接口形状未定**（batch upsert？增量拉取？时间戳？）：决定 LWW 是否可用；完全无时间戳则退化"设备单向赢"，需接口方知情确认。
- **长按语义分歧**：设置页"长按 OK = 退出页面"，待办列表"长按 OK = 进详情"。已用边界切页约定规避冲突，实机验证误触率；若不顺，备选"短按 OK 进详情、勾选改双击"。
- **NVS 写寿命**：outbox 每次变更写 NVS，高频编辑场景写入量可控（按任务合并后每次至多两条目），但需在 M1 用实测量确认。
- **首次同步全量对账**：设备首次接入已有大量服务器数据时走全量拉取，需要接口分页或一次可拉全量的容量确认（几百条以内无压力）。
