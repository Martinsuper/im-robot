# 多会话并行与独立原生窗口

## 用户行为

聊天窗口支持多个会话标签页。任务执行中，仍可新建独立会话；后端最多同时运行两个任务，每个会话同时只运行一个任务。后台完成、失败或等待确认时显示状态，并提供“查看”入口。

“在独立窗口打开”会转移当前会话的展示与输入归属。主窗口保留入口，不再挂载同一会话的编辑器；重复打开会聚焦已有原生窗口。“返回主窗口”、主窗口的“收回主窗口”和原生关闭按钮均将会话收回，不会取消后台任务。运行中的会话不能被直接删除。

独立窗口内可新建其他独立会话。任务记录中的“安全续跑”会切回原会话；跨窗口发起时先保存当前草稿，再由主窗口定位原会话，继续使用原任务的续跑关联。应用重启会恢复未关闭的独立窗口及其尺寸、位置、文字草稿和已有会话历史。应用退出中断的任务仍需要用户核对后手动续跑，不会自动重放。

## 会话与任务状态

`ConversationTabs` 管理标签页、窗口占用和通知。每个会话使用固定 ID；可见会话拥有独立的 `BubbleWindow`。切换标签保留组件，转移到原生窗口则先保存输入状态、等待保存队列完成，再由新窗口从后端恢复。

`ConversationViews` 按会话 ID 保存草稿、工作目录、知识库选择、附件操作类型和输入预览。关闭握手先刷新草稿再关闭窗口；页面重载也提交最新输入。窗口无响应时，原生关闭流程有兜底，不会永久阻止用户关闭。

`ConversationWindows` 管理原生窗口、唯一标签和递增版本的窗口列表。主窗口先订阅事件再读取列表，避免恢复竞态。窗口打开、关闭及任务事件都会更新主窗口入口。原生窗口配置独立保存，退出时记录几何信息；恢复时将窗口限制在可用显示区域。

Rust `AgentRuntime` 按请求 ID 管理进程及快照。审批、补充要求、目录选择、取消和操作确认都路由到对应请求。恢复快照可按会话查询；历史消息按任务记录中的会话 ID 筛选，不依赖单个 WebView 的本地消息列表。

## 输入与资源隔离

- 文本附件按会话 ID 保存；截图随当前会话请求显式传入模型。
- 原生截图选择记录发起窗口，只向发起窗口发送截图结果。
- 同一进程内的窗口转移保留附件和截图。应用完全退出后，仅恢复文字草稿、目录与知识库选择；附件和截图不写入草稿文件，避免恢复不可用的附件句柄或在磁盘额外保存截图。
- 同一会话不同时挂载两个输入界面，避免跨窗口草稿互相覆盖和重复提交。
- 后端统一检查并发额度、同会话重复任务及重叠目录。文件与 Shell 工具通过全局互斥租约串行执行，覆盖预状态检查、审批、执行及核验；其他会话的模型推理和聊天仍可并行。
- 取消、异常和进程退出都会释放工具租约。该机制协调 Piko 自身工具；已有检查点继续检测其他应用造成的文件改动。

## 验证

前端与 Agent 测试覆盖回复隔离、审批归属、单独取消、独立 SDK 会话、租约释放和快照恢复。Rust 测试覆盖任务准入、多任务记录恢复、草稿输入校验和恢复边界。浏览器测试覆盖后台回复、草稿、弹出/收回、即时重载和运行中转移，以及工作区原有布局。

macOS 原生验收使用独立应用标识及本地合成模型，验证双任务重叠执行、单独取消、运行中原生关闭、附件转移、重启恢复，以及待审批文件写入跨窗口转移后的实际执行和读回。详情见 `doc/review/parallel-windows-native-acceptance-2026-10-22.md`。
