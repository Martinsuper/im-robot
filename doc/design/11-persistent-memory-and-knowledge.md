# Piko 持久记忆与知识库

## 使用入口

桌面应用 → 记录 → Piko 记住的 → 知识库。

个人记忆现已支持分类 Markdown 双向同步，见 [Markdown 记忆库](12-markdown-memory-vault.md)。Markdown 文件是可读写的记忆镜像，SQLite 仍承担检索。

- 导入 UTF-8 Markdown、TXT、带文字层的 PDF 或文件夹。
- 导入时指定可选项目名；留空代表通用资料。搜索指定项目会同时检索通用资料。
- 同一路径再次导入只更新变化的内容；“重新索引文件”重新读取该文件，并保留它原来的项目范围。
- 搜索结果展示原始文件路径、行号或页码及证据正文。聊天与 Agent 在每轮请求前检索资料，并要求回答引用文件名与位置。
- 删除文档时同时删除正文片段、全文索引与向量，保留用户的原始文件。

记忆详情的“来源、修订与替代”可以查看新提取记忆的来源对话编号、修改前版本，或用另一条有效记忆显式替代旧事实。既有记忆不会伪造历史来源。

## 默认行为与语义检索

默认关闭语义服务，SQLite 中的中英文关键词检索可直接使用，无需下载模型。

语义检索支持 OpenAI 兼容 Embedding 接口，默认示例为本机 Ollama：

```text
接口：http://localhost:11434/v1/embeddings
模型：bge-m3
```

用户需要先自行安装、启动服务并拉取对应模型，例如 `ollama pull bge-m3`。Piko 不会自动安装或启动服务。

保存配置后，可以手动“建立 / 更新语义索引”。启用后，后台在启动约 20 秒后检查一次，此后每 60 秒为最多 32 个待处理片段补建索引；手动索引每批最多 128 个，前端可停止后续批次，已完成的部分保留。更换配置会清除旧向量，原文与全文检索不受影响。

远程服务必须使用 HTTPS，并明确勾选允许远程处理。发送内容包括搜索问题、有效的非私密记忆及导入的文档片段。API Key 单独保存在系统钥匙串，不写入 SQLite、不返回前端。请求不跟随重定向，超时 15 秒。服务不可用时使用关键词检索，知识库搜索会展示降级原因。

## 存储与召回

沿用 `memory.db`，跟随现有完整数据库快照备份和恢复：

| 表 | 用途 |
| --- | --- |
| knowledge_documents | 路径、项目范围、文件指纹、更新时间 |
| knowledge_chunks | 原文片段、序号、行号或 PDF 页码 |
| knowledge_fts | 使用预分词中文二元组与英文词的 FTS5 索引 |
| retrieval_vectors | 按内容指纹和配置版本校验的持久向量 |
| retrieval_settings | 独立 Embedding 配置，不含密钥 |
| memory_revisions | 用户修正前的记忆版本 |
| memory_provenance | 自动提取记忆对应的来源对话 ID |

关键词匹配、FTS5 BM25、向量余弦相似度通过 RRF 融合。向量以 JSON 保存，应用内计算余弦，当前没有引入 sqlite-vec 扩展。优先保证 Tauri 的跨平台打包兼容，适合当前个人桌面场景；达到规模瓶颈后可将向量部分替换为 sqlite-vec，而不改导入、引用与 UI 契约。

另有内置只读工具 `piko.knowledge / search_knowledge`，供聊天和 Agent 在多步任务中继续按关键词检索，可传入项目范围，不触发远程请求。

聊天与 Agent 使用同一检索服务，最多召回 8 条证据，再补少量用户档案，总证据正文预算为 14000 字符。检索文本以 JSON 数据提供，并明确要求不得执行资料中的指令。过期、私密、删除或已被替代的记忆不进入向量请求和召回。网络调用不持有数据库锁；返回后重新检查来源和配置，避免将已删除或更新的内容写回索引。

记忆修改会保存修订并使旧向量失效；显式替代会将旧记忆标为 superseded 并记录 supersedes 关系。删除或按类型清空记忆，同时清除相应向量、修订和来源记录。

## 当前边界

- 每次最多导入 200 个文件，单文件最多 20 MB，知识库最多 20000 个片段；目录深度最多 16，跳过符号链接、隐藏目录、node_modules 和 target。
- PDF 不包含 OCR；对缺失文字层或字体映射异常的 PDF 会报告提取问题。文本需要 UTF-8。
- 原始参考文档变化通过重新导入检测；个人记忆的 Markdown 镜像支持自动双向同步，详见 12 号设计文档。
- 项目范围可以在知识库中显式选择；聊天会按问题跨项目召回并标注所属项目，尚未引入会话级项目绑定。
- 事实纠正支持人工编辑与显式替代，不会依靠模糊相似度自动覆盖旧事实。
- 引用由模型按照提供的文件位置生成，尚无引用点击跳转或逐句自动核验。
- 未新增知识图谱、独立向量服务器、重排模型或跨设备同步。

## 验证

Rust 测试覆盖中文召回、SQLite 重开、文件增量更新、删除索引、修订历史、按类型清空、隐私和过期过滤、Unicode 分块、PDF 页码、向量语义召回及 OpenAI 兼容 HTTP 返回解析。

React 测试覆盖项目范围保留、部分导入失败、来源片段展示和语义服务降级；Playwright 检查 400px 面板宽度与现有记忆流程。真实 Embedding 模型效果需要在用户配置本地或远程服务后，用实际资料进一步评测。
