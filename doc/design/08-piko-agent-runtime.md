# Piko 统一聊天与 Agent Runtime

Piko 只保留一个输入框、一条对话流。普通聊天、日程、提醒、备忘录和电脑任务由同一个 Pi 会话承接，用户无需选择模式。文件与截图仍通过原输入工具附加，语音转写继续填入这个输入框。

## 交互

- 输入区上方的目录标签是可选上下文，点击可更换目录。
- 普通聊天及业务工具无需目录。需要访问本地文件而尚未选择目录时，模型调用 `piko_select_workspace`，在当前回复中提示选文件夹；选好后继续原请求。
- 文件和命令操作的批准卡片放在同一条回复内，自动滚动到按钮；不自动批准，不抢占焦点。
- 日程、提醒和备忘录继续使用原有 `ActionConfirmationCard`，包括批量项目选择。确认或拒绝后结果返回同一个 Pi 会话，不再创建另一轮独立聊天。
- 工具调用放在回复中的「执行详情」里，按需展开。生成/执行期间发送按钮变为停止，Esc 停止当前任务；空闲时 Esc 收起窗口。
- 后续提问沿用当前会话；换工作目录不清空上下文。「新对话」隔离对话上下文并保留目录选择。

## 架构

统一聊天界面 → Tauri 命令 → Rust AgentRuntime → 独立 Node 子进程 → Pi SDK。

- `agent/sidecar.mjs`：模型适配、Pi 会话、动态工具集、流式事件和截图内容。
- `agent/app-tools.mjs`：通过 JSONL 将应用工具交给 Rust，不在 Node 中重写业务逻辑。
- `agent/permissions.mjs`：目录内读取可执行；目录外读取（含符号链接）、修改和所有命令需逐次批准。
- `agent/execution.mjs`：纠正只输出“请批准”和代码块、未真正调用工具的回复；重试一次仍不调用则失败，避免误报完成。
- `src-tauri/src/agent.rs`：进程、凭据、附件/截图、业务工具桥接、确认和中止、聊天记录持久化。
- `src/features/chat/BubbleWindow.tsx`：唯一输入、同一对话流、目录标签与统一停止。
- `src/features/chat/AgentActivity.tsx`：无输入框的执行详情、目录请求和批准卡片。

原独立 AgentTaskPanel 已移除。旧 chat 命令仍保留兼容，新的输入统一调用 agent_start。

## 会话与目录

会话保存在应用数据目录 `agent/sessions/<conversation-id>/`。统一会话有稳定的内部目录，系统工具使用用户选择的独立工作目录，执行时明确覆盖 Pi 工具上下文的 cwd，避免更换目录时清空对话或误在内部目录操作。

未选目录时文件工具不向模型声明，执行器也拒绝文件操作；目录工具返回后激活文件工具。应用业务工具始终可用。不会自动加载用户扩展、MCP、技能或项目脚本。

升级时复用旧独立 Agent 会话的标识和已选目录，保留 Pi 的旧任务上下文。新会话首次可导入最近十条应用对话，后续不重复导入；每次请求沿用 Piko 的长期记忆检索。新对话不导入旧的短期对话。

Pi 回复同时写入现有聊天记录与窗口上下文，窗口重启从持久化记录恢复；界面过滤当前回复，避免历史中重复显示一次。

索引存在但历史文件丢失时明确报错，不能静默新建会话继续操作。损坏索引和越界会话文件也拒绝加载。

## 权限与生命周期

同一时间只运行一个请求。业务工具由 Rust 注册表解码并核对风险级别：只读操作直接执行；写入/敏感操作生成原有待确认草稿，等待用户确认。批准仅对当前请求及具体草稿生效，前端不能伪造业务执行结果；取消时清理草稿和等待中的调用。

命令和文件修改的确认由权限门暂停，工作目录不是 OS 沙箱。停止先请求 Pi 取消，五秒后仍未结束则终止进程；已产生的副作用不能撤销。

凭据通过私有 stdin 传递，不进入前端事件或命令行参数。任务结束清理进程。复用 Piko 的模型、API 地址及密钥；支持 OpenAI 兼容、Anthropic 和 Gemini 协议。

## 开发、打包与验证

```sh
npm ci
npm run agent:prepare
npm run tauri dev
```

准备脚本使用 agent/package-lock.json 安装生产依赖，下载固定版本官方 Node 22.23.3 并校验 SHA-256，作为 Tauri externalBin 和资源分发。用户无需安装 Node。首次需要网络，后续复用缓存；仅支持目标平台原生构建。官方 Node 的 macOS 最低要求为 11。

```sh
npm --prefix agent ci
npm run test:agent
npm run test
npm run build:tauri
npx playwright test
cargo check --manifest-path src-tauri/Cargo.toml --lib
```

运行时测试使用真实 Pi SDK、文件和 Shell，模型通过本地协议服务模拟。统一聊天测试包括无目录聊天、运行中选目录、应用工具返回/拒绝、中止、换目录保留上下文、旧会话迁移和截图。

`scripts/agent-real-model-smoke.mjs` 使用现有模型配置进行隔离的真实模型测试，不修改配置，只批准精确的 pwd 命令并读取临时文件。原生 UI 验证使用同样的隔离目录，不访问用户桌面内容；业务写入只生成测试草稿并拒绝，不写入真实备忘录。

系统鼠标键盘、浏览器自动化和完整任务历史差异视图仍属于后续工具扩展。

### 命令自动批准设置

设置 → 系统与隐私 → 命令执行权限提供「始终自动批准命令执行」。默认关闭；开启后持久化到 `agentAutoApproveCommands`，下次任务起生效。Rust 从应用设置读取并传给 sidecar，模型工具参数无法更改权限。仅跳过 bash / PowerShell 确认（Shell 本身可读写文件），直接文件工具和业务动作沿用原确认规则。关闭后下次任务恢复逐次确认；执行详情、停止和目录选择保持可用。


## 任务可靠性加固（2026-10-16）

- 系统工具审批等待 5 分钟后失效，通过 `approval-expired` 移除界面确认卡片；拒绝、取消和超时使用不同的错误说明。
- Agent 输出连续 10 分钟无事件，或单轮任务达到 30 分钟时，应用停止本轮运行。等待用户确认也计入时限；这些上限目前为后端常量。
- 完成、失败、协议错误、输出中断和超时统一先结束 Agent 进程、清理待确认业务草稿并释放运行槽位，再向界面发送终态，允许立即发起后续对话。
- 超时和通信错误明确提醒用户此前可能已有部分操作完成；保存记录失败也不暗示实际操作失败。系统不会自动重试这些操作，也不承诺回滚已发生的修改。
- 首批只处理运行时可靠性；任务记录持久化见下一节，会话持久化本身不代表任务可恢复。浏览器回归使用模拟 Tauri 桥接，不能代替真实桌面运行时验收。


## 任务记录与中断恢复（2026-10-16）

- `agent/tasks.json` 使用现有 storage 原子替换及事务锁，保存最近 100 轮任务；每轮最多记录 256 个工具步骤。工具名称、步骤标识和状态落盘，不新增提示词、工具参数、输出或凭据副本。
- Agent 启动前先保存记录，步骤开始与返回时更新；终态保存后再通知界面。记录损坏时保留原文件并阻止新任务，进度写入失败时停止本轮，提示先核对实际结果。
- `agent_list_tasks` 在运行槽位锁内读取记录，将没有本进程活动任务对应的未结束记录标为 `interrupted`，未返回的工具步骤标为 `unknown`。也会在新任务启动前执行同一恢复过程。
- 对话区显示最近 10 轮任务记录，中断任务默认展开，支持刷新。窗口重新打开或重启后读取记录，不恢复旧确认卡片、不启动 Agent、不重放工具。
- “工具已返回”仅代表工具报告完成，不是独立的业务结果验证。日志观察与外部副作用不属于同一事务，崩溃时必须保守地显示结果未知；当时只提供记录恢复；安全续跑见下文，仍不对任意 Shell 外部副作用承诺恰好一次。
- 任务标识在保留的记录范围内禁止重复使用；这不是跨记录保留期的幂等保证。


## 中断任务只读核对（2026-10-16）

- 中断、失败、取消的任务及有工具步骤的已结束任务提供“只读核对结果”入口。前端提交 `verificationOf`，后端校验任务确实存在且处于终态，再将原任务元数据作为核对上下文；不以旧工具返回状态代替实际证据。
- 核对轮次仅注册文件 `read` 和目录选择工具；选择或切换目录后仍不启用 write/edit/bash/PowerShell，命令自动批准设置也不能越过工具集限制。
- 业务工具列表只保留 `risk=read` 且 `confirmation=never` 的工具，Rust 实际派发时再次检查相同条件，禁止模型通过伪造工具调用创建写入草稿。目录外读取仍按原流程等待审批。
- 后续提问保持核对状态，用户结束核对或新建对话后恢复普通工具能力。核对状态目前在窗口内保存，重新打开时仍通过任务记录重新发起核对，不会自动执行。
- 失败和取消事件通过状态卡片展示，保留已生成的部分回复，不把错误消息作为正常回答。卡片的原“重试/重新生成”按钮改为“编辑后再发送”，只恢复输入草稿。不会因点击该按钮直接重放原指令。
- 核对缺少目标路径或验收标准时应追问；报告应区分已核实、未完成、无法确认，并指出证据。完成核对不自动将原任务标为“已验证”，也不自动执行余下步骤。首批只读核对不提供续跑；后续增加了带检查点和读回验收的安全续跑。


## 执行结果交付（2026-10-16）

- 有工具调用的轮次到达终态后显示结果卡片，普通聊天与执行中不显示。统计来自真实 `tool-start/tool-end` 事件，区分成功返回、报告失败、结果未知；Agent 报告 completed 也不能隐藏失败或未返回步骤。
- 卡片展示工具输出片段（最多 400 字符，纯文本渲染），完整输出仍在执行详情。只从成功返回的 write/edit 调用参数提取去重的文件操作目标，可复制原始路径，不从模型回复或 Shell 文本猜测文件存在与否。
- 已结束任务也支持只读核对，沿用后端只读工具限制；结果卡片不把工具返回状态当作独立业务验收，不自动生成“已验证”状态。
- 最近任务记录显示相同口径的步骤统计。工具输出和文件路径仍只用于当前界面，不额外写入任务日志；重启后恢复状态统计，不恢复证据片段。
- 切换到下一轮或新对话时清空当前结果卡片；复制状态按任务重置。当前不自动打开路径或执行生成文件。


## 全面修复与安全续跑（2026-10-16）

- 系统日历以一年为查询窗口覆盖原有过去十年到未来两年的区间，跨窗口重叠事件按日历、事件标识和开始时间去重；权限、UTF-8 和原生异常防护保留。
- HTML 预览默认离线，联网授权绑定当前源文档，文档更换或取消授权会立即卸载旧框架。原生窗口导航回调禁止外部导航；浏览器演示的离线框架禁用脚本并移除刷新与链接导航。独立窗口沿用当前令牌策略。未授权时 CSP 禁止 HTTPS 外部脚本、资源和连接。
- 组件与工具函数拆分为组件模块、数据模块和无 JSX 的导出入口；订阅使用稳定回调读取最新闭包，相关定时器有完整清理。Lint 与严格 Clippy 作为交付检查。
- 长期记忆按当前任务匹配优先召回，中文使用词组切片；画像保留独立小预算，置顶画像不能挤掉相关任务记忆。隐私与 Active 状态过滤保留。
- 上下文窗口和输出上限可配置，0 使用模型目录，未知模型保守回退 32k/4k；本地服务按实际配置填写。连接空闲超时使用已有超时设置。stderr 持续排空但只保留前 32KB，过滤常见凭据字段及已知 API key，保留最近 20 份诊断，界面按需读取。
- 运行时可补充要求，使用 SDK steering 队列，在下一轮模型调用前生效；正在执行的副作用不能撤销。补充要求会废弃旧审批卡片、降低命令自动批准策略、持久化撤销旧授权代际，并在实际收件后清空输入框。已确认的补充要求写入正常会话记录。
- 文件写入/精确替换在副作用前写入原子持久化检查点，保存前态与期望内容摘要，不额外存正文。成功后读回内容验收；续跑时已满足的目标直接跳过，已授权且前态未变的未完成操作可续接。已完成目标被外部改动、未知编辑效果、损坏检查点一律停止自动重放。
- 内置备忘录、提醒与日程创建使用操作根标识、规范参数、批次位置派生稳定实体 ID；崩溃后按同一 ID 核对，避免重复创建。删除以已授权目标 ID 的实际不存在为完成条件。授权与前态摘要在变更前持久化，完成后保存终态；外部改变导致无法证明前态时仅允许核对，不再产生副作用。
- 新增安全续跑入口，沿用原 SDK 会话与操作根链。相同操作的旧授权在用户补充要求后不会因重启恢复。后续新步骤仍需明确审批，未知插件写入和 Shell 在续跑中不开放；这些外部工具不能承诺幂等。
- 工具事件带独立验收状态，文件内容或本地业务记录读回通过才显示“验收通过”；LLM 文本或正常结束事件不能代替验收。检查点写入失败也会返回工具错误，不让桥接请求无限等待。
