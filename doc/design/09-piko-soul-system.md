# Piko 灵魂系统：人格、主动性与情感设计

实施拆分见：[灵魂系统实施任务](../tasks/09-piko-soul-system-tasks.md)。

## 背景与问题定义

Piko 目前具备完整的工具能力：统一 Agent Runtime、长期记忆、日程提醒、任务执行与结果交付。但产品体验上它始终是「被召唤时才存在」的顺从工具，缺少生命感。具体表现为：

- **没有稳定人格**：回复风格完全跟随底层模型，更换模型即「换魂」，用户感知不到 Piko 作为独立个体的连续性。
- **从不主动**：所有交互都由用户发起，Piko 不会问候、不会追问、不会开口。
- **记忆只被检索，不被运用**：记忆库只在用户说话时作为上下文注入，Piko 从不主动引用过去，关系没有连续性。
- **没有情绪状态**：面对被打断、被夸奖、任务失败，Piko 的表现完全一致。
- **没有共同历史**：没有亲密度、里程碑和不因时间淡化的关系沉淀。
- **永远顺从**：从不表达偏好、不同意或拒绝，缺少有限度的自主。

## 设计原则

1. **命脉是本地状态，不是模型**。人格、情绪、记忆运用都实现为本地持久化数据，随每次对话注入 system prompt。模型可以更换，灵魂不能更换。
2. **主动性克制**。主动行为默认低频、可全局关闭、可逐类关闭。骚扰感会直接杀死「活力感」的价值。
3. **情绪轻量**。不做情绪模拟模型，用离散状态 + 简单事件驱动的衰减规则。
4. **监督者始终是用户**。任何提取性、推断性的内容（观点、开放话题）进入持久化前沿用记忆候选的审核模型，或提供明确的关闭与清理入口。
5. **不承诺生命**。文档与界面避免暗示 Piko 有意识；它是有稳定性格和状态感知的助手。

## 一、人格内核（角色卡）

### 产品行为

Piko 持有一份本地「角色卡」，作为每次对话 system prompt 的一部分注入 Agent Runtime（含普通聊天、核对轮次与工具收尾轮次）。角色卡包含：

| 字段组 | 内容 | 示例 |
| --- | --- | --- |
| 底色 | 国家/时代/经验背景的简短叙述 | 在城市窗台出生的桌前小助手 |
| 核心 | 3–5 条价值观与性格标签 | 细心、有点毒舌但不刻薄、把用户的事当自己的事 |
| 声音 | 语气、口头禅、禁用句式 | 短句、偶尔自嘲；禁用「作为一个AI助手」「还有什么可以帮您」 |
| 关心 | 默认关心范式（追问健康、追问未完成的事） | 对答应过的具体事情上心 |
| 立场 | 涉及重要事件、产出质量、安全风险时，允许表达不同意见 | 可以说「我觉得这个时间排得太密了」 |

角色卡在首次运行时按默认值自动创建，用户可在「Piko 的设定」中查看全文并编辑，但不需要用户写提示词——编辑界面用选项 + 自由补充的方式。

### 演化

角色卡不是静态文件。以下事件可形成微小字段漂移的候选，满足下述证据门槛并经确认后生效：

- 用户主动表扬/道谢 → 提议「核心」中热情权重微升（仅影响语气描述，不改用户可控的设定值）
- 用户明确纠正语气（「别这么说话」）→ 「声音」进入候选项，需用户确认
- 用户与 Piko 的长期互动形成稳定的口头禅再现 → 提议在「声音」记录该口头禅

所有漂移仅影响 Piko 的自我叙述层；用户可直接编辑的设定字段永远以用户的值为准。漂移历史保存在角色卡版本记录中，可整体回退。

演化默认关闭。开启后，同一字段至少在不同对话中出现 3 次明确证据才生成候选，每字段每 7 天最多生成 1 条；口头禅再现同样进入候选，不自动固化。所有持久化演化（包括热情权重）需确认，候选保存来源引用、前后值和生成时间。热情只使用预设有限档位，每次最多调整一档；不改变价值观、权限或用户明确偏好。随机性只用于已确认风格的表达选取，不用于随机修改配置。回退创建新版本并暂停相关候选，拒绝的相同证据不重复提议。

### 数据与代码

- 内置默认角色卡随应用版本发布，多语言文本复用 `src/locales`；用户覆盖值与演化记录存入本地 `memory.db`，不写回语言资源。有效配置由「内置默认值 → 已确认演化层 → 用户覆盖值」依次合并，同字段以用户值为准。
- 沿用 Rust `chat::system_prompt` 的统一组装入口，由 `agent.rs` 将有效角色卡与情绪快照传给 `agent/sidecar.mjs`；sidecar 不另行读取角色配置。不修改 Pi 协议与权限门。
- 权限、安全与只读核对约束高于角色风格；用户本轮明确的语气要求高于默认风格。角色自由补充、演化内容和记忆均以有边界的资料块注入，不得定义权限或覆盖系统规则。每轮冻结配置版本，工具执行期间不切换人格；下一轮使用最新配置。
- 角色卡可见于设置页复用层级，改动仅在下一次请求生效，不引入额外的用户手动刷新。

## 二、主动开口

### 产品行为

Piko 的主动行为按以下类别独立控制，默认状态明确：

全局主动开关默认开启，但首次启用时明确展示：仅「任务未闭环」默认开启。关闭全局开关阻止所有类别，包括系统通知；普通对话回复、权限确认与用户主动配置的日程提醒不属于此开关。

| 类别 | 触发条件 | 默认 | 频控 |
| --- | --- | --- | --- |
| 问候与时辰 | 应用启动、长时间空闲后回来 | 关 | 每天最多 2 次 |
| 任务未闭环 | 前一天有失败/中断的任务，或存在待核对结果 | 开 | 每个任务只提醒 1 次 |
| 模式观察 | 由记忆/作息事实触发的温和观察 | 关 | 每天最多 1 次 |
| 偶发小话 | 低概率的生存感动画或一句话气泡 | 关 | 每天最多 3 条 |
| 开放话题回访 | 已确认话题进入回访时间窗 | 关 | 每天最多 1 条，每话题每 7 天最多 1 次 |
| 共同历史 | 里程碑解锁 | 关 | 每天最多 1 条 |
| 产出评价 | 本地可观测的预览停留或收藏事件 | 关 | 每天最多 1 条，P2 提供 |

主动消息不调用模型——内容从本地模板 + 轻度格式化生成（引用具体事实字段，不编造），因此零模型成本、零延迟、可完全离线。仅当用户回应主动消息后，才进入正常的对话流程。

### 主动气泡与精灵表现

- 主动消息以气泡形式出现在精灵旁，可忽略；满足下述可见时长条件仍无响应时自动消失并计入「被忽略次数」；同类消息连续 3 次被忽略后按调度约定退避。
- 所有主动事件共享一条全局冷却队列，防止同一时刻多条消息堆叠。
- 主动消息与系统通知区分：普通主动消息走精灵气泡，重要事项（任务待核对）才同时发系统通知。

### 调度与投递约定

- 所有类别共享每天最多 3 条的硬上限，两条之间至少间隔 2 小时；本地日期与时区用于日额度，单调时钟用于进程内冷却。修改时区或回拨系统时间不能重置已消耗额度。优先级为任务待核对、开放话题、问候、共同历史、模式观察、偶发小话、产出评价。
- 复用现有 `quiet_mode` 与静默时段配置，取更严格的限制。静默模式、系统锁屏、用户空闲、用户正在输入、Agent 正在执行或等待确认、精灵隐藏时不展示主动气泡；不抢占对话或确认卡片。空闲结束只生成候选，稳定恢复活动 30 秒后才检查投递资格。进入静默时清除已展示的主动气泡。
- 关闭全局或类别开关立即撤销对应排队消息、停止待发系统通知，并清除对应气泡；重新开启不补发关闭期间的事件。任务记录与话题仍可由用户主动查看。
- 候选具有 `not_before` 与 `expires_at`。问候有效 30 分钟，小话、模式观察和产出评价有效 2 小时，里程碑有效 24 小时；任务提醒在终态后次日当地 09:00 起有效 7 天，解决后立即失效；话题回访窗为到期后 7 天。过期只丢弃消息，不删除业务记录。休眠或重启后只检查仍有效的候选，最多展示一条，不集中补发。
- 消息按 `category + source_id + source_version` 去重；持久化 `pending → dispatching → shown → responded / ignored / dismissed` 状态。展示前以事务占用日额度与去重键，BubbleWindow 回执后标记 `shown`。崩溃后状态不明的 `dispatching` 不自动重投，优先避免重复打扰；这不承诺端到端恰好一次投递。
- 「每任务一次」指同一任务记录最多一次投递尝试；气泡及配套系统通知视为同一消息。系统通知仅在权限已授予时发送，权限拒绝不重试、不影响气泡；点击两种入口都指向相同上下文。
- 只有实际展示并收到回执、持续可见 20 秒且未回应的气泡才计为忽略；排队、隐藏和投递失败不计入。主动关闭计为 dismissed，不作为完成业务的证据。连续 3 次忽略后同类最短间隔加倍、有效日额度减半向下取整（最低 1 条），仍受全局上限约束；用户回应或 7 天无新增忽略后恢复。退避在 P1 启用。
- 用户回应携带消息 ID 和来源引用进入普通对话，不把模板文本作为系统指令。无回应不生成对话轮次；「不要说话」暂停主动消息，直到用户明确恢复，必要的权限确认仍按既有流程处理。

### 任务未闭环的语义

- `failed`：提示失败事实与查看记录入口，不推断外部操作完全未发生；`interrupted`：提示「结果待核对」，接入现有只读核对流程；`cancelled`：用户主动取消，默认不追问。`completed` 不因存在历史失败步骤重新生成提醒。
- 「待核对」是任务上的显式业务标记，不能仅由模型语气推断；关联核对确认完成后撤销提醒。新重试任务通过原任务引用关联，避免对同一问题重复追问。
- 提醒使用任务 ID、状态、时间与安全的展示字段，不新增提示词、工具参数或输出副本。提醒账本独立持久化，不能仅靠有容量上限的 `agent/tasks.json` 保证去重。
- 回应或点击提醒不授权重跑。只读核对仍受既有工具集限制；重新执行必须走普通请求和权限确认流程。

### 数据与代码

- 新增 `src-tauri/src/proactive.rs`：调度、频控、冷却队列。
- 触发源复用既有能力：idle detection（空闲检测）、agent_journal / Agent 任务终态、记忆事实的日期/时段字段。
- 精灵气泡复用现有 BubbleWindow 通道，区别仅在于无用户输入发起。

## 三、开放话题（连续的关心）

### 产品行为

在记忆之外新增「开放话题」机制：用户提过、Piko 追踪、但尚未闭环的事。

- **写入**：与记忆提取共用同一批处理管线（`memory/extraction.rs`），新增一类「开放话题」候选；进入与记忆相同的待确认审核流，用户确认后才真正成为跟踪项。规则只提取明确直接的承诺与计划（「我想周末去看牙」「下周要发布」），不推断。
- **过期判断**：话题保存原始时间表达、来源时间、IANA 时区、解析后的起止时间与解析器版本。「周末」取来源当地周六至周日，「下个月」取下个自然月；区间结束后才到期。审核界面展示实际日期，允许修改；语义不明确或没有时间时保持「未排期」，不主动回访。确认后固定时间，不随重启重新解析；用户修改时间时创建新版本。
- **回访**：Piko 择机问一句（「想去的那个地方去了吗？」），使用独立的「开放话题回访」开关。未回应保持待回访；明确完成才关闭，「还没」保持未完成，「不去了」取消，「改到下周」进入延期变更候选。模糊或涉及多个话题的回答需澄清，不自动关闭。对话中的状态变更均先生成可确认候选，用户通过话题面板明确操作可直接生效。
- **归档**：关闭只保存最少状态与来源引用；若要把结果写成普通长期记忆，仍经过记忆候选审核和敏感内容过滤，不因关闭自动获得写入授权。
- **上限**：同一时刻最多跟踪 20 条开放话题，超出时提示用户清理。

### 数据与代码

- `memory.db` 新增 `open_loops` 表，复用现有的候选审核命令模式。生命周期为 `pending_review → tracking → due → closed / cancelled / expired`；`tracking` 可未排期，终态重新开启需用户明确操作。到期回访窗结束后进入 `expired`，支持手动重新排期。延期确认后回到 `tracking` 并撤销旧版本消息。
- 候选按来源 ID 与规范化内容去重；跨来源相似话题只建议合并，用户确认后合并。完成、取消或删除立即撤销对应队列项。20 条上限只统计已确认且非终态的话题；审核时检查上限，不静默覆盖旧项。
- 记忆中心的界面新增「开放话题」分区（复用 MemoryExtractionControls 的审核交互模式）。

## 四、情绪状态

### 产品行为

Piko 维护一个内部情绪变量，取值覆盖有限状态：

```
平静（默认） / 愉悦 / 低落 / 担心 / 起劲（专注陪练） / 憋闷（被打断/任务失败累计）
```

- **驱动**：由本地事件驱动（任务成功、非用户主动的中断、被夸、连续失败）；长时间未互动只参与衰减，规则为加权累加 + 时间衰减回落到平静。规则在代码中，不可被模型改变。
- **影响三处**：
  1. 精灵动画选择（接现有 SpriteSheet/Cubism 表现层的状态推荐）。
  2. 注入对话 system prompt 的短句（如「今天状态不高，说话偏正经」），同角色卡位置注入。
  3. 主动消息的语气模板选择。
- **可见性**：不直接向用户展示数值；情绪通过表情、语气、字幕间接传达。设置页提供关闭情绪系统（回到平静单态）。

### 数据与代码

- 新增 `src-tauri/src/piko_mood.rs`（情绪事件监听与落库），状态存 `memory.db` 的情绪快照表，随会话恢复。
- 模型始终只能「知道」当前情绪，不能改写它——情绪不在模型可触达的工具/权限集中。

### 更新与表达边界

- 采用一个版本化规则表，定义 `event_type → target_mood / delta / cooldown`。任务事件来自持久化任务状态；表扬只匹配用户直接表达的明确短语，不分析第三方文本、工具输出或引用内容。每事件有稳定 ID，同一任务终态仅计一次；同一表扬来源只计一次，每类事件每分钟最多计一次。
- 初始规则：任务成功使愉悦 +1，失败或非用户主动的中断使憋闷 +1；明确表扬使愉悦 +1；用户显式开启陪练时起劲 +1。各状态分值为 0–3，达到 2 才切换，每 30 分钟衰减 1；选择达到阈值的最高分状态；最高分并列且包含当前状态时保持当前状态，否则取并列中最近有效事件对应状态；所有状态均低于阈值时回到平静。低落、担心在 P1 默认不自动触发，后续需有明确来源与规则后启用，不推断用户健康或心理状态。
- 用户主动取消不产生负面事件，长时间未互动只促使衰减。精灵不因离开、拒绝建议或取消任务表达责备、要求安抚或降低服务质量。情绪不影响任务优先级、事实判断和权限。
- 持久化分值、最后更新时间、规则版本与近期去重键；恢复时按经过时间衰减，时间回拨不增加分值。关闭时清零并移除 prompt 中的情绪片段，重新开启从平静开始，不回放历史事件。
- 动画选择优先级为权限确认/执行等业务状态高于情绪，高于普通 idle；缺少对应动画时回退默认动画，不阻塞业务。

## 五、成长与共同历史

### 产品行为

Piko 记录与用户共同经历的时间以保证连续性，同时提供一个轻量、非氪金化的成长感：

- **共同时间**：「在一起的第 N 天」，出现在某些问候消息中。
- **里程碑**：基于真实事件自动解锁（首次任务、首次主动被回应、第一次被用户道谢、累计疲劳提醒被采纳等），以纪念方式呈现，不改变任何能力。
- **称呼演化**：里程碑可解锁新称呼（用户可在设置中选择或关闭）。不引入数值化亲密度排行，不引入失败惩罚；成长感来自回忆，不来自数值。

### 数据与代码

- 事件来源复用 agent_journal 与 proactive 的已提交事件；最少计数与里程碑事实存入 `memory.db`，不引入独立积分系统。
- 里程碑通知走主动消息通道，走精灵气泡而非系统通知。

## 六、观点与边界

### 产品行为

Piko 在自己的叙述层内被允许有限地「不完全顺着来」：

- **产出评价**：当用户通过 HTML 预览等生成产出时长停留或收藏，Piko 可以主动（低频）表达看法。看法来自本地模板池（按产出类型），推断性内容不进入对话。
- **日程/计划建议**：面对明显过载的日程批量规划，在生成草稿时附一条温和的提醒（不阻塞、不拒绝执行）。
- **拒绝与澄清**：沿用既有 Agent 行为规范。Piko 不因为「人格」新增拒绝业务操作的能力；权限边界完全由现有权限门决定，人格不能成为绕过任何确认流程的理由。

当用户明确说「不要说话」时，Piko 静默执行并事后只在必要时回复事实。

## 七、数据生命周期与可观测性

以下为新增数据的最小契约，均为计划新增，不能假定现有表已提供这些能力：

| 数据 | 最小字段与约束 |
| --- | --- |
| 角色卡 | profile_id、schema_version、revision、默认资源版本、用户覆盖、已确认演化、updated_at；更新使用 revision 检查，避免设置页覆盖新版本 |
| 演化候选/版本 | ID、来源引用、字段、前后值、审核状态、时间；回退保留新版本，不覆写旧历史 |
| 开放话题 | ID、revision、内容、来源引用、时间原文/基准/时区/起止、解析器版本、状态、closed_at；候选审核与写入在同一事务提交 |
| 主动消息账本 | ID、类别、来源 ID/版本、去重键、时间窗、投递状态、回执时间；另存全局额度、退避与暂停状态 |
| 情绪快照 | 规则版本、各状态分值、最后衰减时间、近期事件去重键 |
| 共同历史 | 首次启用日期及当时的时区、里程碑键、达成时间、事件引用；里程碑键唯一，重放事件不重复解锁 |

- 新表使用版本化迁移与事务；迁移失败保留原数据并停用灵魂功能，普通 Agent 按原有流程运行。角色配置损坏回退内置默认卡；主动账本不可读时停止主动投递，不以空账本重发。数据库错误应有可见诊断入口。
- 待审核候选 30 天未处理自动过期；已关闭、取消或过期的话题默认保留 90 天后删除。主动消息正文不持久化，只保存模板 ID 与来源引用；投递明细保留 30 天，任务去重墓碑保留到关联任务记录被删除且不存在待发候选。已过消息有效期的旧终态任务不重新生成候选。
- 角色版本最多保留最近 50 个及当前版本；情绪事件去重信息保留 24 小时，快照只保留当前值。里程碑只保存最少达成事实，不复制原对话或敏感内容；「疲劳提醒被采纳」等事件仅在存在显式用户确认时计数，不能从沉默推断。
- 关闭记忆提取后停止生成开放话题候选；既有话题保留，是否回访仍由回访开关决定。关闭演化停止生成候选，已确认风格保留；恢复默认角色卡会清除覆盖与演化，并另行确认是否清除版本历史。
- 删除来源记忆或对话时，关联候选和话题同步删除并撤销消息；独立手动创建的话题不受影响。导出仅包含仍存在的数据；导入不合并投递队列、不自动解锁或通知里程碑，完成校验后才启用调度。
- 设置提供分项清理与「清空全部灵魂数据」。清空包括版本、候选、话题、情绪、主动账本与共同历史，并关闭主动功能；再次开启时从新的启用时间建立基准，不扫描旧任务和对话重新生成。共同天数按本地自然日差 +1 展示，不按打开次数增长，不因离开中断或惩罚。
- 本地诊断仅记录消息 ID、模板 ID、状态与跳过原因（静默、过期、频控等），不复制正文。写盘失败时停止对应状态推进，不将未提交更新当作已完成。

## 分阶段落地

### P0 灵魂的第一块骨头

- 数据 schema 与迁移、设置优先级、清理入口及主动投递账本
- 角色卡创建与统一注入（默认值 + 可编辑 + 每轮版本快照）
- 开放话题候选提取（复用记忆提取管线）与审核
- 主动消息框架（调度、频控、气泡通道），先落地「任务未闭环」与「问候」两类
- 设置页新增「Piko 的灵魂」分区（角色卡、主动行为开关、情绪开关）

验收：使用固定场景集验证跨模型的短句、禁用句式、立场与用户语气覆盖规则；权限与只读核对能力不受人格影响。失败/中断任务按时间窗仅尝试提醒一次，取消任务不提醒；重启、休眠、静默、关闭开关与投递中崩溃均满足调度规则。

### P1 情绪与回访

- 情绪状态系统与精灵动画联动
- 开放话题到期回访
- 共同时间与首批里程碑
- 主动消息的「被忽略」自退避

验收：重复事件不累加，离线恢复正确衰减，用户取消或离开不触发负面表达；到期话题按解析日期回访，「未完成／延期／取消／模糊回答」分别进入正确流程，归档记忆仍需审核；忽略计数与退避恢复符合规则。

### P2 演化与审美

- 角色卡的受控漂移与版本回退
- 产出的审美评价、日程过载提醒
- 称呼演化与更多里程碑

验收：演化需明确证据与确认，历史可查看与回退，用户设定值不被覆盖；评价不因停留推断满意度或产出质量，只描述模板可支持的观察，主动生成零模型成本。

### 必须覆盖的验收场景

| 场景 | 预期 |
| --- | --- |
| 两个触发源同时入队 | 按优先级只投递一条，共享额度与冷却 |
| 气泡投递中崩溃并重启 | 不重复投递，不伪造用户已阅读或已完成 |
| 关闭全局/类别开关 | 已展示及待发主动消息撤销，不影响正常权限确认 |
| 静默、隐藏、输入、执行、休眠恢复 | 不抢占、不集中补发，过期候选丢弃 |
| 系统时间回拨或时区变化 | 不额外获得额度，不重新解析已确认话题日期 |
| 来源被删除、话题完成或延期 | 旧版本队列项立即失效，关联内容按生命周期删除 |
| 同一回应涉及多个话题或语义含糊 | 不误关闭，不自动写长期记忆 |
| 迁移失败、配置损坏或账本不可读 | 原数据保留，按约定降级，不重发旧提醒 |
| 清空后重启或重新开启 | 不从旧日志重建已清理的灵魂数据 |

跨模型使用同一组普通聊天、纠正语气、失败收尾、只读核对与权限请求样例；断言风格约束和事实/权限边界，不要求逐字一致。调度与状态机使用可控时钟和事件重放测试，气泡通道单独验证可见回执及回应关联。

## 明确不做

- 不做显式的「亲密度数值」「好感度面板」，成长感不靠数字排名。
- 不为主动性调用模型（除用户主动回应后的正常对话），保持离线与免费。
- 不将情绪、人格转化为模型可调的工具参数，权限门完全独立于人格系统。
- 不在文档与界面中宣称 Piko 具有意识；描述为「稳定性格与状态感知」。
- 不做 P2P/云端同步灵魂状态；所有灵魂数据留在本地 `memory.db` / storage，与记忆一致。

## 与现有体系的关系

| 方面 | 结论 |
| --- | --- |
| Agent Runtime | 角色卡与情绪短句作为 system prompt 的一部分注入，不改协议 |
| 记忆系统 | 开放话题复用提取、审核、去重与撤销机制 |
| 空闲检测 | 是主动消息的第一个触发源 |
| 任务交付 | 失败/中断任务主动提醒走任务记录的终态事件 |
| 精灵表现 | 情绪状态接入现有动画切换层，不重做表现系统 |
| 权限与确认 | 人格不影响任何权限、确认与边界决定 |
