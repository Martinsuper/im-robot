# Piko 应用壳层与桌面代理设计

## 1. 范围

本篇合并桌面代理接口、实施设计、状态结构、桌面操作层、受控执行、节律提醒和输入统计相关内容。

## 2. 目标

- 统一窗口与托盘行为。
- 统一原生命令边界。
- 统一状态流转和持久化原则。
- 把系统能力限制在明确授权范围内。

## 3. 能力分层

| 层 | 内容 |
| --- | --- |
| 展示层 | pet、bubble、panel、capture |
| 交互层 | 点击、拖动、快捷键、上下文菜单 |
| 代理层 | Tauri commands、窗口管理、系统感知 |
| 安全层 | 受控执行、权限校验、确认流程 |

## 4. 接口原则

- 命令名必须稳定且白名单化。
- 不向前端暴露任意 shell 执行。
- 事件驱动优先于轮询。
- 状态结构应分清前端态、持久态和运行态。

## 5. 主要功能

### 桌面操作层

- 显示、隐藏、打开面板、打开气泡。
- 处理拖动、定位、窗口恢复。
- 为宠物精灵提供最小且稳定的系统动作集。

### 受控执行

- 仅允许有限、可确认、可撤销的操作。
- 文件写入和外部操作需要显式边界。
- 不让模型直接接触高风险系统动作。

### 工作节律与提醒

- 休息提醒、专注节奏和用户使用节律联动。
- 只在合适时机给轻提示。

### 输入统计

- 记录输入活跃度时，优先只做本地统计。
- 统计口径要固定，避免模型或 UI 自行猜测。

## 6. 状态设计

建议将状态拆为三类：

- 窗口态：显示、隐藏、位置、置顶。
- 交互态：当前会话、当前动作、最近事件。
- 持久态：设置、偏好、统计、历史。

## 7. 实施顺序

1. 先稳定桌面窗口和命令接口。
2. 再补状态结构与受控执行。
3. 再接节律提醒和输入统计。
4. 最后扩展更复杂的工具能力。
