# Piko 记忆、存储与数据设计

## 1. 范围

本篇合并数据存储、持久记忆与记忆实现方案，作为 Piko 数据层的统一设计。

## 2. 目标

- 保留必要的用户偏好与历史。
- 让记忆可以参与上下文构建和成长反馈。
- 让数据存储结构清晰、可迁移、可删除。

## 3. 数据分层

| 层 | 内容 |
| --- | --- |
| 设置层 | 主题、活泼度、静默偏好、窗口偏好 |
| 统计层 | 互动次数、输入统计、使用频率 |
| 记忆层 | 用户偏好、长期协作片段、重要事件 |
| 历史层 | 会话、提醒、面板记录 |

## 4. 核心原则

- 先本地化，再谈同步。
- 先最小必要数据，再谈扩展。
- 记忆应可查询、可清理、可解释。
- 不把敏感内容当作默认长期存储。

## 5. 记忆系统

记忆建议分三类：

- 短期记忆：最近会话上下文。
- 中期记忆：最近几天高频偏好。
- 长期记忆：稳定偏好、关系和成就。

## 6. 存储建议

- 设置和统计分开。
- 结构化数据优先使用明确 schema。
- 与聊天相关的记忆要有保留策略。

## 7. 与前端的关系

- 前端只拿自己需要的摘要。
- 记忆详情由专门页面展示，不散落在各业务组件。
