# Piko 宠物核心系统设计

## 1. 范围

本篇合并原先的角色、动画、情绪、成长、装扮、性格和 UI 组件设计，作为宠物核心系统的统一入口。

## 2. 模块组成

| 模块 | 作用 |
| --- | --- |
| 形象系统 | 定义角色外观、阶段和资源规范 |
| 动画系统 | 管理 idle、thinking、working 等动作 |
| 情绪系统 | 将交互映射为 emotion 和 reaction |
| 成长系统 | 处理经验、等级、阶段和成就 |
| 装扮系统 | 处理外观替换与配置 |
| 性格系统 | 影响主动行为和反应强度 |
| UI 组件 | 承载精灵、气泡、面板与通用控件 |

## 3. 设计原则

- 角色表现必须可读。
- 动画要服务状态，而不是炫技。
- 情绪、成长和性格应彼此联动。
- UI 需要紧凑、稳定，不抢角色中心。

## 4. 核心状态

宠物主状态建议仍保持以下主干：

- `idle`
- `listening`
- `thinking`
- `speaking`
- `working`
- `success`
- `confirming`
- `resting`
- `error`

情绪与身体反应需要和主状态解耦，避免一一绑定。

## 5. 关键实现方向

### 形象与动画

- 使用统一 sprite 规格或等价资源约束。
- 按阶段管理外观，不在 UI 层临时拼贴。
- 动画帧和状态切换要有明确表。

### 情绪与互动

- 鼠标、对话、文件和系统事件都应该进入同一套情绪触发器。
- 反应强度与持续时间要受事件类型和上下文影响。

### 成长与装扮

- 养成值不只是数值，要能驱动外观和行为变化。
- 装扮应该是独立配置，不直接污染状态机。

### UI

- 面板、气泡、精灵本体尽量使用同一套术语。
- 控件复用要优先于在各处重复写相似逻辑。

## 6. 与前端代码的关系

建议将核心渲染与状态逻辑继续收敛到 `src/features/pet/` 下，避免 UI、动画和情绪逻辑在 `App.tsx` 一类入口里扩散。
