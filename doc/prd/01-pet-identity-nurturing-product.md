# Piko 宠物身份与养成产品方案

## 1. 目标

把 Piko 从单纯的桌面角色，整理成一只“有身份、有成长、有陪伴关系”的宠物精灵。

本篇合并了原先的宠物养成、形象设计和产品设计内容，重点回答三件事：

1. Piko 是什么样的角色。
2. 用户为什么愿意长期和它互动。
3. 养成与外观变化如何服务陪伴体验。

## 2. 产品定位

Piko 不是工具壳，而是桌面常驻的轻陪伴角色。

它的产品价值由三层组成：

- 情感价值：会打招呼、会回应、会记住用户的习惯。
- 养成价值：互动会影响亲密度、成长阶段和外观状态。
- 低打扰价值：默认不打断用户，只有在合适时机给轻反馈。

## 3. 角色设定

Piko 的角色要满足三个条件：

- 可爱但不幼稚。
- 活泼但不吵闹。
- 有辨识度，但不会压过用户当前工作。

角色表现应围绕以下特征展开：

- 视觉上有稳定的轮廓和阶段变化。
- 行为上有“靠近、观察、回应、陪伴”的倾向。
- 台词上简短、自然、不过度拟人化。

## 4. 养成系统

养成系统应把日常交互转成长期成长。

推荐的核心维度：

| 维度 | 含义 | 来源 |
| --- | --- | --- |
| 亲密度 | 用户与 Piko 的关系强度 | 点击、摸摸、陪伴、聊天 |
| 活跃度 | 近期互动频率 | 日常使用行为 |
| 陪伴度 | 是否长期处于桌面和工作场景 | 在线时长、专注场景 |
| 协作度 | 是否参与文件、提醒、任务 | 文件拖放、提醒完成 |
| 稳定度 | 是否受用户偏好与安静模式约束 | 设置与行为记录 |

养成结果不应只体现在数值上，还要体现在：

- 表情更丰富。
- 小动作更自然。
- 问候语更贴合上下文。
- 视觉阶段或装扮解锁。

## 5. 交互关系

Piko 与用户的关系建议分成四类：

| 关系状态 | 触发条件 | 典型反馈 |
| --- | --- | --- |
| 初识 | 刚安装或很少互动 | 简单问候、保守反应 |
| 熟悉 | 经常点击、拖放、聊天 | 更主动的小动作 |
| 默契 | 持续协作和完成任务 | 记忆性反馈、轻提示 |
| 安静陪伴 | 用户长期专注或开启最小打扰 | 少说话，只在需要时提醒 |

## 6. 外观与阶段

角色外观建议按阶段推进，而不是一次性堆复杂换装。

| 阶段 | 外观方向 | 对应体验 |
| --- | --- | --- |
| 幼体 | 简单、柔和、动作少 | 让用户建立第一印象 |
| 少年体 | 活泼、反应更明显 | 开始形成陪伴感 |
| 成体 | 动作稳定、神态丰富 | 长期桌面主角 |
| 个性化阶段 | 可加装扮与材质差异 | 让角色更像“自己的 Piko” |

## 7. 交互设计

产品交互要围绕“短反馈 + 长积累”：

- 单击：打招呼，打开气泡。
- 摸摸：开心、亲密度增加。
- 拖文件：好奇并进入协作状态。
- 双击：休息/唤醒。
- 长时间没互动：轻微关注或静默陪伴。

## 8. 数据设计

建议保留以下产品级数据：

```ts
interface PetProfile {
  name: string;
  stage: "egg" | "child" | "teen" | "adult";
  intimacy: number;
  activityScore: number;
  companionshipScore: number;
  collaborationScore: number;
  preference: {
    quietMode: "minimal" | "balanced" | "expressive";
    theme: string;
    visualStyle: string;
  };
}
```

## 9. UI 设计原则

- 以精灵为视觉中心，不把说明文堆成大段页面。
- 养成信息尽量以状态、图标、进度和轻提示表达。
- 关键行为入口少而明确。
- 配置项按“日常使用”和“个性化”分组。

## 10. 实施顺序

1. 统一交互事件和亲密度统计。
2. 接入基础养成值和阶段变化。
3. 建立角色外观阶段与互动反馈联动。
4. 再考虑更细的装扮和个性化扩展。
