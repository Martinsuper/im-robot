# Piko 桌面代理交付计划

## 1. 目标

把桌面代理相关的里程碑、任务拆解和交付标准整理成一份执行文档，减少计划类内容分散在多篇文档里的情况。

## 2. 里程碑总览

| 阶段 | 目标 |
| --- | --- |
| M0 | 三窗口 Spike、托盘、快捷键、跨平台验证 |
| M1 | 精灵状态机、位置恢复、基础设置 |
| M2 | AI 文本对话、流式响应、安全存储 |
| M3 | 文本文件拖入、截图提问 |
| M4 | 提醒、通知、权限中心 |
| M5 | 正式动画、性能优化、静默规则 |
| M6 | 自动化测试、CI、安装包 |
| M7 | Beta 冒烟、缺陷修复、发布 |

## 3. 任务拆解

推荐把任务分成四条主线：

1. 桌面壳层与窗口行为。
2. 对话与文件处理。
3. 提醒、权限和系统集成。
4. 动画、性能和稳定性。

## 4. 依赖关系

- 桌面操作层先于受控执行和工具调用。
- 状态结构先于复杂事件流。
- 安全与权限先于自动化能力扩展。
- 测试与验收应该贯穿每个阶段，而不是最后补。

## 5. 风险控制

| 风险 | 对策 |
| --- | --- |
| 跨平台窗口差异 | macOS、Windows、Linux 分别验证 |
| 透明窗口事件不稳定 | 使用明确的事件边界和兜底逻辑 |
| 权限申请打断体验 | 只在必要时申请，并说明用途 |
| 任务扩展失控 | 保持预览、确认、可撤销 |

## 6. 交付标准

- 功能可演示。
- 关键流程有自动化或冒烟验证。
- 错误场景有兜底提示。
- 文档和代码的术语一致。
