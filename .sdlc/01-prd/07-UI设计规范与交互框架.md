# 模块 07 · UI 设计规范与交互框架

> 关联：[00-产品总览与设计原则](./00-产品总览与设计原则.md) · 全模块
> 代码位置（现状）：`src/App.css`（2721 行）、`src/features/app/design-system.css`（128 行）

---

## 1. 模块目标

建立**唯一一套**视觉与交互规范，解决当前 UI 的核心问题：

- 两层 CSS 互相覆盖、选择器重复（`.panel-shell` 20 次、`.bubble-thread__ai-content` 28 次）；
- 同类控件在不同窗口样式不一致；
- 状态反馈（加载 / 空 / 错误 / 成功）表现五花八门；
- 窗口行为（拖动 / 关闭 / 置顶）各写各的。

---

## 2. 样式架构（重构核心）

### 2.1 目标结构

```text
src/styles/
├─ tokens.css          # 设计令牌：颜色 / 间距 / 圆角 / 字号 / 阴影 / 动效
├─ base.css            # reset、字体、通用元素、可访问性
├─ components/         # 复用组件样式（Button / Card / Field / Toast / Chip / Empty）
├─ windows/            # 各窗口布局（pet / bubble / panel / capture / onboarding）
└─ index.css           # 入口，按顺序 @import
```

规则：

- **单一来源**：每个选择器只在一处定义，杜绝 `App.css` + `design-system.css` 双写。
- **令牌驱动**：颜色、间距、圆角、字号只允许使用 `var(--*)`，禁止硬编码色值（少量特例需注释）。
- **组件样式**：可复用控件样式与业务样式分离。
- **迁移方式**：以 `tokens.css` + `base.css` 为地基，逐窗口替换，最后删除旧文件。

### 2.2 设计令牌

```css
:root {
  /* 颜色 */
  --color-bg: #f7f7f2;
  --color-surface: #fffefa;
  --color-surface-2: #f1f3ee;
  --color-text: #26332c;
  --color-text-muted: #6b7770;
  --color-border: #e2e7de;
  --color-accent: #356951;
  --color-accent-soft: #e9f0e7;
  --color-danger: #a6473d;
  --color-warning: #b07a2a;
  --color-success: #3f7d54;

  /* 间距（4 的倍数） */
  --space-1: 4px;  --space-2: 8px;  --space-3: 12px;
  --space-4: 16px; --space-5: 24px; --space-6: 32px;

  /* 圆角 */
  --radius-sm: 6px; --radius-md: 10px; --radius-lg: 16px; --radius-full: 999px;

  /* 字号 */
  --text-xs: 11px; --text-sm: 12px; --text-md: 14px;
  --text-lg: 16px; --text-xl: 20px; --text-2xl: 24px;

  /* 阴影 */
  --shadow-sm: 0 1px 2px rgb(0 0 0 / 6%);
  --shadow-md: 0 4px 12px rgb(0 0 0 / 8%);

  /* 动效 */
  --duration-fast: 120ms; --duration-base: 200ms; --duration-slow: 320ms;
  --ease-standard: cubic-bezier(.2, 0, 0, 1);
}
```

深色主题通过 `[data-theme="dark"]` 覆盖同一批令牌。

## 3. 布局框架

### 3.1 窗口清单

| 窗口 | 尺寸 | 装饰 | 置顶 | 可缩放 |
| --- | --- | --- | --- | --- |
| 精灵 | 200×240 | 无 | 是 | 否 |
| 对话 | 420×560（记忆） | 无 | 是 | 是 |
| 主面板 | 420×720（记忆） | 系统装饰 | 否 | 是 |
| 截图 | 全屏 | 无 | 是 | 否 |
| 引导 | 480×560 | 无 | 是 | 否 |

> 现状主面板 400×700 且 8 Tab，目标 3 Tab，信息密度显著降低。

### 3.2 主面板布局

```text
┌─────────────────────────────────────────────┐
│ 头部：Piko · 今天 / 记录 / 设置   （Tab 行） │
├─────────────────────────────────────────────┤
│                                             │
│              内容区（滚动）                  │
│                                             │
├─────────────────────────────────────────────┤
│ （可选）底部操作条                          │
└─────────────────────────────────────────────┘
```

- **头部固定**，内容区独立滚动。
- Tab 切换时**重置滚动位置到顶部**（现状不重置）。
- 只渲染当前 Tab 内容（现状用 `.is-hidden` 全量渲染，性能与可维护性都差）。
- 移动/窄屏下 Tab 横向排列可滚动，不折成两行。

### 3.3 对话窗口布局

见模块 02 第 3 节。

### 3.4 通用页面骨架

```text
<Page>
  <PageHeader title subtitle actions? />
  <PageSection title? description? action?>
    ...
  </PageSection>
  <EmptyState /> | <ErrorState /> | <LoadingState />
</Page>
```

所有页面复用同一套骨架，禁止各写各的 `section`。

## 4. 组件规范

### 4.1 基础组件清单

| 组件 | 用途 | 变体 |
| --- | --- | --- |
| `Button` | 操作 | primary / secondary / ghost / danger；sm / md |
| `IconButton` | 图标操作 | 必须有 aria-label 与 title |
| `SegmentedControl` | 少量互斥选择 | 2~4 项 |
| `Select` | 下拉选择 | — |
| `TextField` | 输入 | 单行 / 多行 / 密码 |
| `Switch` | 开关 | — |
| `Card` | 内容容器 | 普通 / 可折叠 |
| `ListRow` | 列表项 | 单行 / 双行 / 带操作 |
| `Chip` | 标签 / 附件 | 静态 / 可删除 |
| `Badge` | 状态徽标 | 中性 / 成功 / 警告 / 危险 |
| `EmptyState` | 空状态 | 图标 + 文案 + 可选操作 |
| `ErrorState` | 错误 | 文案 + 重试 |
| `Skeleton` | 加载占位 | 行 / 卡片 |
| `Toast` | 轻提示 | info / success / error |
| `ConfirmDialog` | 二次确认 | 普通 / 危险 |
| `Tooltip` | 补充说明 | — |

规则：

- 一个组件一个职责，不允许「万能按钮」。
- 所有可点击元素有 hover / active / focus-visible / disabled 四态。
- 图标按钮必须有 `aria-label`。

### 4.2 状态反馈统一

| 状态 | 表现 | 禁止 |
| --- | --- | --- |
| 加载 | 骨架屏（首屏）/ 按钮内联 spinner（操作） | 大转圈遮罩 |
| 空 | `EmptyState`：图标 + 一句引导 + 可选操作 | 空白页面 |
| 错误 | 内联 `ErrorState` 或 `Toast`，带重试 | `alert()`、原始报错 |
| 成功 | `Toast` + 控件状态变化 | 弹窗阻塞 |
| 进行中 | 按钮禁用 + 文案变化（「保存中…」） | 无反馈 |

**现状问题**：错误提示混用 `reminder-error` / `speech-error` / `memory-error` / `connection-status` / `calendar-notice`，目标态统一为 `Toast` + `ErrorState`。

## 5. 交互规范

### 5.1 窗口拖动

- 无装饰窗口（精灵 / 对话 / 引导）：顶栏作为拖动区。
- 拖动区内按钮需 `data-no-drag`（排除）。
- 主面板使用系统标题栏，不自定义拖动。

### 5.2 键盘

| 快捷键 | 作用 |
| --- | --- |
| `Esc` | 关闭当前浮层 / 收起对话 |
| `Cmd/Ctrl + Enter` | 发送消息 |
| `Cmd/Ctrl + ,` | 打开设置 |
| `Tab / Shift+Tab` | 焦点移动 |
| `Enter` | 确认（对话框） |

- 焦点顺序符合视觉顺序。
- 对话框打开时焦点锁定，关闭后归还。

### 5.3 反馈时长

| 类型 | 时长 |
| --- | --- |
| 按钮 hover | 120ms |
| 面板 / 卡片过渡 | 200ms |
| Toast | 3s（错误 5s，可手动关闭） |
| 精灵轻提示 | 2.5s |

### 5.4 动效原则

- 动效服务于状态变化，不做装饰性动画。
- 尊重 `prefers-reduced-motion`。
- 精灵动画可关闭（安静模式自动降级）。

## 6. 文案规范

- 使用第二人称、口语化、简短。
- 按钮文案为动词短语（「开始专注」「保存记录」），不用「确定 / 提交」。
- 错误文案：说清「发生了什么 + 怎么办」。
- 不用技术词：Provider → 服务；Token → 密钥；SSE → （不出现）；Embedding → （不出现）。
- 数字与单位之间加空格：`18 分钟`。

### 6.1 术语表（与 00 保持一致）

统一使用：精灵 / 对话窗口 / 主面板 / 今天 / 记录 / 我的记录 / Piko 记住的 / 安静模式 / 亲密度 / 成长阶段。

---

## 7. 可访问性

- 所有交互元素可通过键盘到达与操作。
- 图标按钮有 `aria-label`。
- 文本对比度 ≥ 4.5:1。
- 焦点环清晰可见（统一 `:focus-visible` 样式，现状在 `App.css` 与 `design-system.css` 各写一份）。
- 动态内容（流式回复）使用 `aria-live="polite"`。
- 表单错误通过 `aria-describedby` 关联。

---

## 8. 响应式与窗口尺寸

- 桌面应用以窗口尺寸为主，不做移动端适配。
- 断点：
  - `< 380px`：面板内边距压缩，Tab 横向滚动。
  - `< 480px`：对话窗口单列。
- 窗口最小尺寸约束见第 3.1 节。

---

## 9. 视觉语言

- **底色**：暖纸白，避免纯白刺眼。
- **强调色**：自然的绿色系，可由用户调整强调色。
- **圆角**：卡片 16px，控件 10px，chip 全圆角。
- **阴影**：仅用于浮层（菜单 / Toast / 对话框），卡片用边框而非阴影。
- **图标**：统一使用 `lucide-react`，线宽 1.7，尺寸 16 / 18。
- **头像 / 精灵**：作为视觉锚点，不堆叠过多装饰。

---

## 10. 迁移策略

1. 新建 `src/styles/tokens.css` + `base.css`，先在对话窗口试点。
2. 建立 `components/` 基础组件库，逐步替换原生 `button/input`。
3. 逐窗口迁移，每迁移一个窗口删除对应旧 CSS 段。
4. 全部迁移后删除 `App.css` 与 `design-system.css`。
5. 用 ESLint 规则（或 CI 检查）禁止硬编码色值与内联样式。

## 11. 验收标准

- [ ] 只有一个样式入口，无重复选择器。
- [ ] 所有颜色 / 间距来自令牌。
- [ ] 基础组件库覆盖 90% 以上控件。
- [ ] 加载 / 空 / 错误 / 成功状态表现统一。
- [ ] 面板只渲染当前 Tab，切换重置滚动。
- [ ] 键盘可完成主要流程，焦点可见。
- [ ] 无 `alert()`、无原始错误直出、无 `undefined` 展示。
- [ ] `prefers-reduced-motion` 生效。
