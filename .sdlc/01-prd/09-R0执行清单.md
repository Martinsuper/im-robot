### 1.3 已确认决策

1. **D-2 的处理方式**：**删除 `pet-actions`，只保留右键菜单**。注意这不是纯粹的删除——`pet-actions` 是当前精灵上唯一的「对话」「休息」入口，只留右键就必须同步把右键菜单从「只 `toggle_panel`」升级为「对话 / 休息 5 分钟 / 打开面板」，否则构成功能回退。且宠物窗口只有 260×300 且 `transparent`（`src-tauri/tauri.conf.json`），React 内联菜单会被窗口边界裁剪，**必须走 Tauri 原生菜单 `Menu::popup`**（Rust 侧）。
2. **D-3 的范围**：原生 `confirm()` **不纳入 R0**，仅在本文档登记，R1 随二次确认组件一起替换。
3. **D-1 的迁移边界**：R0-5 只做令牌层抽取 + 对话窗口试点，**不清洗** `App.css` 里 34 处重复选择器，留给 R5（08 §3 R5 已列「删除旧 CSS」）。

## 3. 执行顺序与文件冲突

R0 的 6 个任务并不是「互不依赖」，它们是**文件高度重叠**的。先看冲突矩阵（跨任务重复出现的文件就是必须先串行的地方）：

| 任务 | 触碰的文件 |
| --- | --- |
| R0-1 | `components/feedback/*`（新）、`lib/errors.ts`（新）、**PanelWindow.tsx**、BubbleWindow.tsx、**MemoryCenter.tsx**、**App.css** |
| R0-2 | **PanelWindow.tsx**、`hooks/useAutoSave.ts`（新）、CSS |
| R0-3 | **PanelWindow.tsx**、**design-system.css** |
| R0-4 | PetWindow.tsx、**App.css**（pet 部分）、**design-system.css**（pet 部分）、src-tauri/src/lib.rs、previews.spec.ts |
| R0-5 | `src/styles/*`（新）、App.tsx、**design-system.css**、**App.css** |
| R0-6 | **MemoryCenter.tsx**、MemoryDetail.tsx、pet/interaction/*、pet/personality/*、OnboardingWindow.tsx、I18nProvider.tsx、LiveCharacterPet.tsx |

**结论**：`PanelWindow.tsx`（R0-1/2/3）、`App.css`（R0-1/4/5）、`design-system.css`（R0-3/4/5）、`MemoryCenter.tsx`（R0-1/6）四个热点直接决定了并发上限。真正能做到零冲突并行的只有 **R0-4**（只碰 pet 与 Rust）。

```
R0-5 令牌层 ──→ R0-1 统一状态反馈 ──┬─→ R0-3 只渲染当前 Tab ──→ R0-2 即时保存
```

- R0-3 必须先于 R0-2（R0-2 在条件渲染后的结构上接入 `useAutoSave`）。

### 6.1 模型确认（已完成实测）

**结论：子 agent 将使用 `cliproxy / cn:hy4-preview-f · 免费 x0.00`，不会继承当前会话的 `cn:deepseek-v4.1-flash · 付费 x0.03`。**

证据链：

1. `orca worktree create --agent pi` 的语义只是“在首个终端启动 pi”，命令本身**没有任何模型参数**（`worktree create --help`）。
2. Orca 的 agent 启动配置里 **pi 不在任何默认 args/env 表里**：
   - `app.asar.unpacked/out/shared/tui-agent-permissions.js` 的 `YOLO_TUI_AGENT_ARGS` / `YOLO_TUI_AGENT_ENV` 无 pi；
   - 用户实际配置 `orca-data.json → settings.agentDefaultArgs`（23 个 agent）与 `agentDefaultEnv`（仅 goose）也无 pi；
   - `settings.agentCmdOverrides` 为空；
   - `tui-agent-config.js` 中 pi 仅声明 `detectCmd: 'pi'`、`promptInjectionMode: 'argv'`、`draftPromptEnvVar: 'ORCA_PI_PREFILL'`。
3. 所以实际命令就是裸 `pi`，模型完全由 `~/.pi/agent/settings.json` 决定：`"defaultProvider": "cliproxy"`，`"defaultModel": "cn:hy4-preview-f · 免费 x0.00"`。
4. 实测：`cd /tmp && pi --no-session -p "Output only the exact model id you are running as"` → 返回 `cn:hy4-preview-f`。

当前会话的 `PI_MODEL=cn:deepseek-v4.1-flash · 付费 x0.03` 是 per-pane 环境变量；`orca-data.json` 中并未持久化任何 pi 模型偏好，子 agent 拿不到。

### 6.2 能不能给子 agent 指定别的模型

`orca orchestration worker-start --model` **只支持 fresh Claude / Codex / Cursor**，pi 不在支持列表（见 `references/coordinator-loop.md`：「For a fresh Claude, Codex, or Cursor terminal, `--model` accepts…」）。给 pi 换模型只有三条路：

| 方案 | 做法 | 代价 |
| --- | --- | --- |
| (a) 改全局默认 | 把 `~/.pi/agent/settings.json` 的 `defaultModel` 改掉 | 影响用户自己所有 pi 会话，**不推荐** |
| (b) low-level 路径 | `orca terminal create --worktree <sel> --command 'pi --model "cn:deepseek-v4.1-flash · 付费 x0.03"'` | 失去 supervised 归属，需自己盯 |
| (c) 接受默认 | 不动 | 免费，但预览模型，判断力弱于当前会话 |
