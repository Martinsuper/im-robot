### 1.3 已确认决策

1. **D-2 的处理方式**：**删除 `pet-actions`，只保留右键菜单**。注意这不是纯粹的删除——`pet-actions` 是当前精灵上唯一的「对话」「休息」入口，只留右键就必须同步把右键菜单从「只 `toggle_panel`」升级为「对话 / 休息 5 分钟 / 打开面板」，否则构成功能回退。且宠物窗口只有 260×300 且 `transparent`（`src-tauri/tauri.conf.json`），React 内联菜单会被窗口边界裁剪，**必须走 Tauri 原生菜单 `Menu::popup`**（Rust 侧）。

## 3. 执行顺序与文件冲突

R0 的 6 个任务并不是「互不依赖」，它们是**文件高度重叠**的。先看冲突矩阵（跨任务重复出现的文件就是必须先串行的地方）：

| 任务 | 触碰的文件 |
| --- | --- |
| R0-1 | `components/feedback/*`（新）、`lib/errors.ts`（新）、**PanelWindow.tsx**、BubbleWindow.tsx、**MemoryCenter.tsx**、**App.css** |
| R0-2 | **PanelWindow.tsx**、`hooks/useAutoSave.ts`（新）、CSS |

| R0-6 | **MemoryCenter.tsx**、MemoryDetail.tsx、pet/interaction/*、pet/personality/*、OnboardingWindow.tsx、I18nProvider.tsx、LiveCharacterPet.tsx |

**结论**：`PanelWindow.tsx`（R0-1/2/3）、`App.css`（R0-1/4/5）、`design-system.css`（R0-3/4/5）、`MemoryCenter.tsx`（R0-1/6）四个热点直接决定了并发上限。真正能做到零冲突并行的只有 **R0-4**（只碰 pet 与 Rust）。

```
R0-5 令牌层 ──→ R0-1 统一状态反馈 ──┬─→ R0-3 只渲染当前 Tab ──→ R0-2 即时保存
```

### 6.1 模型确认（已完成实测）

**结论：子 agent 将使用 `cliproxy / cn:hy4-preview-f · 免费 x0.00`，不会继承当前会话的 `cn:deepseek-v4.1-flash · 付费 x0.03`。**

1. `orca worktree create --agent pi` 的语义只是“在首个终端启动 pi”，命令本身**没有任何模型参数**（`worktree create --help`）。
