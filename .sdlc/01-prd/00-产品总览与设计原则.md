# Piko 产品总览与设计原则

> 文档版本：v2.0（重构版）
> 状态：已评审 · 待落地
> 适用范围：Piko 桌面 AI 伙伴（Tauri + React）
> 关联文档：本目录 `01` ~ `08`

---

## 1. 一句话定位

**Piko 是一只住在桌面上、会陪你说话、也帮你记住事情的小伙伴。**

它不是「桌面宠物 + 工具面板」两个产品的拼接，而是一个统一体：陪伴是外壳，对话是入口，记录与提醒是长期价值。

---

## 2. 为什么要重做

当前版本功能已经不少，但产品呈现出典型的「功能堆叠型膨胀」：

- 面板 8 个 Tab：精灵 / 设置 / 提醒 / 日程 / 备忘 / 历史 / 记忆 / 关于；
- 时间类能力有 4 套并存：提醒事项、本地日程、专注模式、休息提醒（外加工作节奏统计）；
- 记录类存储有 3 套并存：备忘、AI 记忆、对话历史；
- 养成类系统有 5 套并存：情绪、人格、成长、属性、成就（外加换装 / Live2D）；
- 设置项分散在 4 个互不相干的 section，并且每个 section 有自己的「保存」按钮；
- 视觉上同时存在 `App.css`（2700+ 行）与 `design-system.css` 两层样式，`.panel-shell` 被定义 20 次、`.bubble-thread__ai-content` 被定义 28 次，互相覆盖；
- 已接入 i18n（中文 / 英文 / 日文），但只有引导页用了翻译，其余界面全部硬编码中文，且没有任何语言切换入口。

结果就是：**开发者维护成本高，用户学习成本高，产品定位说不清。**

本次重构的核心不是「加功能」，而是**做减法、定身份、统一框架**。

更详细的现状问题清单见 [08-重构落地与验收计划.md](./08-重构落地与验收计划.md) 第 2 节。

## 3. 目标用户与核心场景

### 3.1 目标用户

| 用户 | 特征 | 核心诉求 |
| --- | --- | --- |
| 桌面工作者 | 长时间在电脑前，需要陪伴感与轻提醒 | 抬头能看到陪伴，低头不被打扰 |
| 知识工作者 / 开发者 | 有大量碎片想法、需要快速问答 | 随手问一句、随手记一笔、随时找回 |
| 泛用户 | 不熟悉 AI 配置 | 三步之内能用起来，零配置也能聊 |

### 3.2 核心场景（按重要度排序）

1. **随手一问**：遇到问题时，点一下桌面的 Piko 就能对话，回答流式出现。
2. **随手一记**：有个念头，直接丢给 Piko，它自动整理成记录。
3. **到点提醒**：说「明天 10 点提醒我开会」，Piko 记住并在合适时机轻提醒。
4. **专注陪伴**：工作累了，Piko 提醒休息、陪你倒计时，但默认安静。
5. **找回过去**：想起之前聊过 / 记过的事，在「记录」里搜一下就能找到。

### 3.3 反场景（明确不做）

- 不做全能办公套件（不做多级项目管理、团队协作、复杂日历视图）。
- 不做常驻屏幕读写（不持续截屏、不读取输入内容明文）。
- 不做无确认的高风险操作（文件写入、系统动作必须预览 + 确认）。
- 不做需要用户理解「Provider / Base URL / Temperature」才能开聊的产品。

## 4. 产品结构与信息架构（目标态）

```text
Piko
├─ 精灵窗口（桌面常驻，透明置顶）
│   ├─ 悬停：轻浮出快捷操作（对话 / 休息 / 更多）
│   ├─ 单击：打开 / 收起对话
│   ├─ 双击：休息 / 唤醒
│   ├─ 右键：快捷菜单（对话 / 今天 / 记录 / 设置 / 隐藏）
│   └─ 拖拽：移动位置；拖入文件：进入对话附件
│
├─ 对话窗口（Bubble）—— 唯一对话入口
│   ├─ 对话流（含历史折叠）
│   ├─ 输入区（文字 / 附件 / 截图 / 语音）
│   └─ 回复工具条（复制 / 朗读 / 保存 / 更多）
│
├─ 主面板（Panel）—— 3 个 Tab
│   ├─ 今天 Today     ：问候 + 专注/休息 + 今日时间线 + 快速添加
│   ├─ 记录 Records   ：一个记录入口 +「我的记录 / Piko 记住的」+ 对话历史
│   └─ 设置 Settings  ：伙伴 / 对话与模型 / 提醒与免打扰 / 系统与隐私 / 关于
│
├─ 引导 Onboarding（首次启动，可跳过）
├─ 截图框选 Capture
└─ 系统托盘菜单
```

对比现状的关键变化：

| 现状 | 目标 | 变化 |
| --- | --- | --- |
| 面板 8 Tab | 面板 3 Tab | 按「用户意图」而非「数据表」组织 |
| 提醒 / 日程 / 专注 / 休息 4 套 | 合并进「今天」 | 一条时间线 + 一个计时器 |
| 备忘 / 记忆 / 历史 3 套 | 合并进「记录」 | 一个入口，两个分类 |
| 设置 4 个 section，各自保存 | 设置 5 个分组，即时保存 | 去掉「保存」按钮 |
| 养成 5 套系统 | 收敛为「亲密度 + 成长阶段」 | 可见、可解释，其余内部化 |

## 5. 设计原则（重构的宪法）

1. **一个入口原则**
   同一个能力只能有一个主入口。对话只在对话窗口，记录只在记录页，设置只在设置页。

2. **默认零配置原则**
   首次安装不配置任何东西也能聊天（使用内置默认 / 本地模型提示）。所有技术参数默认折叠。

3. **即时保存原则**
   设置改动立即生效并持久化，不出现「改完忘了保存」。

4. **低打扰原则**
   默认平衡模式；主动行为必须在安静模式与免打扰时段内被抑制；任何主动提示都可一键关闭。

5. **可见即可解释原则**
   所有养成 / 记忆数据都要让用户看得懂「为什么」「来自哪里」。不展示无法解释的黑箱数值。

6. **两屏可达原则**
   任意核心任务，从主面板出发不超过 2 次点击即可完成。

7. **确定性文案原则**
   空状态、错误、加载都有明确文案，禁止出现 `undefined`、原始错误堆栈、英文技术术语直出。

8. **单一数据源原则**
   同一份数据只有一个权威存储位置，跨窗口通过事件同步，不再用 localStorage + 自定义 window 事件打补丁。

9. **可逆原则**
   删除、清空、写入、系统动作都可撤销或有二次确认。

10. **渐进披露原则**
    高级能力（模型参数、插件、工作节奏细节）收进「高级」区域，不干扰主流程。

## 6. 关键功能决策（做减法）

### 6.1 保留并强化

- 桌面精灵的陪伴感（存在感 + 轻反馈）。
- 对话（流式、附件、截图、朗读、保存）。
- 提醒与日程（合并为「今天」）。
- 记录与记忆（合并为「记录」）。
- 专注 / 休息计时（并入「今天」）。
- 亲密度与成长（收敛为可见的简单体系）。

### 6.2 合并

| 合并前 | 合并后 |
| --- | --- |
| 提醒事项 + 本地日程 | 「今天」的一条时间线（统一模型，用类型区分） |
| 专注模式 + 休息提醒 | 「今天」的一个计时器 + 一个免打扰开关 |
| 备忘 + AI 记忆 | 「记录」的两个分区：我的记录 / Piko 记住的 |
| 对话历史 + 备忘检索 | 统一的搜索入口（在「记录」内） |

### 6.3 降级 / 折叠

| 能力 | 处理 |
| --- | --- |
| 工作节奏 / 输入字符统计 | 从主界面移除；保留内部检测用于智能休息提醒，可在「设置 → 高级」查看开关 |
| 模型 Base URL / Temperature / Timeout | 折叠进「高级设置」，默认只暴露「服务 + API Key」 |
| 语音模型下载（SenseVoice / Whisper） | 折叠进「高级设置 → 语音」 |
| HTML 预览插件 | 折叠进「设置 → 高级 → 实验室」 |
| 外部插件列表 | 移入「设置 → 高级 → 插件」，无插件时不显示入口 |
| 权限状态展示 | 从被动标签改为可操作项（去授权 / 已授权） |

### 6.4 下线（建议）

| 能力 | 原因 |
| --- | --- |
| 换装 / Outfit 系统 | 用户几乎无感知，维护成本高；改用「外观风格」一项代替 |
| 属性 / 成就 / 每日任务等成长子系统 | 不解释、不展示、易产生无意义数值；收敛为「亲密度 + 阶段」 |
| `pet-clock` 精灵上的时钟 | 与系统时钟重复，纯噪音 |
| 英文 / 日文界面（若短期不做） | 未完成的 i18n 比没有 i18n 更伤体验 |

> 下线项不删除底层数据表，先隐藏入口，后续版本再清理。

## 8. 成功指标

### 8.1 北极星指标

**周活跃陪伴时长**：用户每周与 Piko 有有效交互（对话 / 记录 / 完成提醒）的天数 × 平均每日有效交互次数。

### 8.2 分阶段指标

| 阶段 | 指标 | 目标 |
| --- | --- | --- |
| 激活 | 完成引导并发出第一条消息的比例 | ≥ 70% |
| 首次价值 | 首次会话在 60 秒内得到可用回答的比例 | ≥ 85% |
| 留存 | 次日 / 7 日留存 | ≥ 40% / ≥ 20% |
| 习惯 | 每周使用「今天」或「记录」≥ 3 次的用户占比 | ≥ 30% |
| 打扰 | 主动关闭提醒 / 免打扰的用户占比 | ≤ 15% |
| 稳定 | 崩溃自由会话占比 | ≥ 99.5% |

### 8.3 体验质量指标

- 主面板任意核心任务 ≤ 2 次点击。
- 首屏可交互时间 < 1s。
- 设置项修改后无「未保存」状态（即时保存成功率 100%）。
- 全应用无硬编码「undefined / NaN / [object Object]」展示。

## 9. 迭代路线（高层）

| 阶段 | 主题 | 交付重点 |
| --- | --- | --- |
| R0 | 止血 | 统一状态提示与错误文案、修掉双 CSS 覆盖、设置即时保存 |
| R1 | 收敛信息架构 | 面板 8 Tab → 3 Tab；提醒/日程/专注合并为「今天」；备忘/记忆/历史合并为「记录」 |
| R2 | 简化对话与配置 | 引导零配置化；模型设置收敛为「服务 + Key」；对话窗口状态精简 |
| R3 | 陪伴体系重构 | 亲密度 + 成长阶段可见化；交互动效与文案统一；安静模式标准化 |
| R4 | 系统与生态 | 权限可操作化、更新流程重做、插件收进高级 |
| R5 | 打磨与多语言 | 无障碍、性能、按需启用多语言 |

每个阶段的详细任务与验收见 [08-重构落地与验收计划.md](./08-重构落地与验收计划.md)。
