# 模块 04 · 记录与记忆

> 关联：[00-产品总览与设计原则](./00-产品总览与设计原则.md) · [02-模块-AI对话与助手](./02-模块-AI对话与助手.md)
> 代码位置（现状）：`src/features/memory/*`、`src/features/panel/PanelHistory.tsx`、memos 相关 UI

---

## 1. 模块目标

把现状中 **备忘、AI 记忆、对话历史** 三套割裂的存储，合并成一个用户能理解、能找回来的界面：**记录**。

一句话心智：**「我写下的」和「Piko 记住的」，都在这里，都能搜到。**

---

## 2. 为什么合并

现状的问题：

- 备忘（memos）和 AI 记忆（memories）用户分不清区别，经常找不到刚记的东西；
- 对话历史又是一个独立 Tab，检索方式和前两者不同；
- 记忆中心有「记忆列表 / 待确认 / 反思总结」三个子 Tab，术语（反思、语义记忆、置信度）对普通用户过于技术化；
- 备忘有 AI 自动分类 + 摘要 + 标签，但展示方式（分类宫格）和记忆列表不一致。

合并原则：

- **一个记录入口**：想记点什么都丢进来。
- **两个分区**：`我的记录`（用户主动）与 `Piko 记住的`（AI 推断）。
- **一个搜索**：三处内容统一检索。
- **术语去技术化**：不再出现「反思、语义记忆、置信度、候选记忆」等词。

---

## 3. 信息架构

```text
记录 Records
├─ 顶部：记录入口（输入框）
├─ 搜索框（跨全部内容）
├─ 分区切换： [ 我的记录 ] [ Piko 记住的 ] [ 对话历史 ]
└─ 列表 / 卡片
```

### 3.1 记录入口

```text
┌────────────────────────────────────────────┐
│ 记一笔…                                     │
│ （多行输入）                                │
│ [ 分类 ▼ ]                     [ 保存 ]     │
└────────────────────────────────────────────┘
```

- 保存后自动生成摘要与标签（本地或模型）。
- 也可以在对话窗口中让 Piko 帮忙记录（走确认流程）。

### 3.2 我的记录

用户主动写下的内容。

| 字段 | 说明 |
| --- | --- |
| 标题 | 必填，可为首行 |
| 内容 | 正文 |
| 分类 | 任务 / 想法 / 学习 / 工作 / 生活 / 资料 / 其他（保留现状分类） |
| 标签 | 自动生成，可编辑 |
| 摘要 | 自动生成，列表展示用 |
| 时间 | 创建 / 更新时间 |

- 列表按更新时间倒序，置顶项优先。
- 支持编辑、删除、置顶。
- 分类筛选（顶部 chip），不使用宫格统计（现状的 memo-summary-grid 去掉）。

### 3.3 Piko 记住的

AI 从对话中推断并保存的长期记忆。对用户呈现为「Piko 记住的事」，而不是「记忆数据库」。

| 字段（对用户可见） | 说明 |
| --- | --- |
| 内容 | 一句话描述 |
| 来源 | 「来自 X 月 X 日的对话」 |
| 状态 | 已记住 / 待你确认 |
| 操作 | 置顶 / 删除 / 反馈「有用/没用」 |

- **隐藏**：内存类型（profile/event/semantic/operational/reflection）、置信度小数、embedding、隐私等级等技术字段。
- 待确认项集中展示在列表顶部，一次最多展示 5 条，操作只有「记住」与「忽略」。
- 不再有独立「反思」按钮；系统自动在每天结束时生成一条「今天的回顾」，作为一条普通记录展示（可关闭）。

### 3.4 对话历史

- 按**会话**（ChatSession）展示，而不是单条问答对。
- 每条显示：标题（自动摘要）、时间、消息数、首条摘要。
- 展开可在「记录」页内查看完整会话，或「在对话中继续」。
- 支持按关键词搜索、按时间筛选（今天 / 本周 / 更早）。

> 现状的 `PanelHistory` 用「附件 / 截图 / 代码 / 链接 / 长回复」标签过滤，对用户价值低且实现不稳定（靠字符串匹配），目标态移除，改为搜索 + 时间筛选。

---

## 4. 统一搜索

- 顶部一个搜索框，同时搜索：我的记录、Piko 记住的、对话历史。
- 结果分组展示，并标注来源。
- 支持简单关键词（现状的实现即可），未来可加语义搜索。
- 空结果文案：「没有找到关于「xxx」的内容。要不要现在记一笔？」

---

## 5. 记录与记忆的产生

### 5.1 来源

| 来源 | 进入分区 | 是否需确认 |
| --- | --- | --- |
| 用户在「记录」页手动写 | 我的记录 | 否 |
| 用户在对话中说「帮我记一下」 | 我的记录 | 否（用户明确要求） |
| Piko 从对话中推断（如「我下个月搬家」） | Piko 记住的 | 是（待确认） |
| 完成提醒 / 专注后的结果 | Piko 记住的（可选） | 否 |
| 每日自动回顾 | Piko 记住的 | 否（可关闭） |

### 5.2 自动摘要与标签

- 保存记录后异步生成摘要与标签。
- 生成失败时展示原始内容，不阻塞保存。
- 不允许因摘要失败而丢失记录。

## 6. 数据模型（目标态）

```ts
interface RecordItem {          // 我的记录
  id: string;
  title: string;
  content: string;
  category: "task" | "idea" | "learning" | "work" | "life" | "reference" | "other";
  summary: string;
  tags: string[];
  pinned: boolean;
  createdAt: number;
  updatedAt: number;
}

interface MemoryItem {          // Piko 记住的
  id: string;
  content: string;
  sourceRef?: { sessionId: string; at: number };
  status: "confirmed" | "pending";
  pinned: boolean;
  createdAt: number;
  updatedAt: number;
}

interface ChatSessionSummary {  // 对话历史
  id: string;
  title: string;
  messageCount: number;
  preview: string;
  updatedAt: number;
}
```

底层仍可复用现有记忆存储（`memory/store.rs`），但**前端只暴露语义化字段**。

---

## 7. 隐私与控制

- 在「记录」页顶部提供「Piko 可以记住的事」开关：
  - 关闭后，不再从对话中推断新记忆（已有记忆保留）。
- 提供「清空 Piko 记住的」（二次确认）与「导出全部记录」。
- 所有记录默认仅本地存储，不上传。
- 记录中标记为敏感的内容不进入对话上下文注入。

---

## 8. 界面规范

| 元素 | 规范 |
| --- | --- |
| 列表项 | 卡片，显示标题 + 摘要 + 时间 + 分类/来源标签 |
| 标签 | 圆角 chip，最多显示 3 个 + 「+N」 |
| 空状态 | 分区各自的引导文案 |
| 加载 | 骨架屏 |
| 搜索 | 顶部固定，输入防抖 300ms |
| 错误 | 内联提示 + 重试，不使用 alert |

---

## 9. 文案规范

| 位置 | 文案 |
| --- | --- |
| 我的记录空态 | 还没有记录。写下第一个想法吧。 |
| Piko 记住的空态 | Piko 还在慢慢认识你。 |
| 对话历史空态 | 还没有聊过天。 |
| 待确认标题 | Piko 想记住这些 |
| 待确认操作 | 记住 / 忽略 |
| 关闭记忆 | 关闭后 Piko 不再主动记住新的事 |
| 每日回顾 | 今天的回顾 |

---

## 10. 验收标准

- [ ] 面板不再有独立的「备忘」「记忆」「历史」Tab，统一在「记录」。
- [ ] 一个输入框可保存记录，自动摘要标签生效。
- [ ] 「我的记录 / Piko 记住的 / 对话历史」三区切换顺畅。
- [ ] 搜索跨三区返回结果并标注来源。
- [ ] 待确认记忆 ≤ 5 条集中展示，操作简单。
- [ ] 界面不出现类型 / 置信度 / embedding / 反思等术语。
- [ ] 可一键关闭「Piko 主动记住」。
- [ ] 对话历史按会话展示，可继续对话。
- [ ] 清空 / 导出有二次确认与明确结果提示。
