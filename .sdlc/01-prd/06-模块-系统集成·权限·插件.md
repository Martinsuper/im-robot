# 模块 06 · 系统集成 · 权限 · 插件

> 关联：[00-产品总览与设计原则](./00-产品总览与设计原则.md) · [05-模块-设置与个性化](./05-模块-设置与个性化.md)
> 代码位置（现状）：`src-tauri/src/lib.rs`（tray / shortcut / notification / update）、`src/features/panel/PanelWindow.tsx` about 部分

---

## 1. 模块目标

让 Piko 与操作系统「安静而正确地」协作：

- 托盘、快捷键、开机启动、通知行为符合桌面应用预期；
- 权限状态可见、可操作，不再只是被动标签；
- 插件能力收敛、默认隐藏、安全可控；
- 更新流程可理解、可完成。

---

## 2. 系统托盘

### 2.1 菜单

```text
显示 / 隐藏 Piko
────────────
与 Piko 对话          （快捷键提示）
今天
记录
────────────
休息 5 分钟
────────────
设置
退出
```

- 菜单文案跟随语言与状态（如专注中显示「结束专注 · 18:42」）。
- 左键单击托盘图标 = 切换对话窗口（符合直觉）。
- 托盘图标提供「勿扰」状态的视觉区分（可选）。

### 2.2 行为

| 操作 | 结果 |
| --- | --- |
| 左键单击 | 打开 / 收起对话 |
| 右键单击 | 打开菜单 |
| 关闭主窗口 | 隐藏到托盘，不退出（首次提示一次） |
| 退出 | 真正退出进程 |

## 3. 全局快捷键

| 快捷键 | 行为 | 可修改 |
| --- | --- | --- |
| `Cmd/Ctrl + Shift + Space` | 打开 / 收起对话 | 是 |
| `Cmd/Ctrl + Shift + T`（可选） | 打开「今天」 | 是 |

- 注册失败（被占用）时提示用户并引导修改。
- 快捷键在设置 → 系统与隐私中展示与修改。
- 不在文档/UI 中硬编码平台差异（统一显示 `Command/Ctrl`）。

## 4. 开机启动

- 开关在设置 → 系统与隐私。
- 使用系统原生 autostart 机制。
- 首次开启时说明「Piko 会在登录后自动出现」。
- 关闭后立即移除自启项。

## 5. 系统通知

### 5.1 使用场景

| 场景 | 通知 |
| --- | --- |
| 提醒到点 | ✅ |
| 日程开始 | ✅ |
| 专注结束 | ✅ |
| 休息提醒 | 可选（默认仅精灵提示） |
| 对话完成 | ❌（不打扰） |
| 更新可用 | ❌（仅在「关于」中展示） |

### 5.2 权限

- 首次需要时申请，并说明用途（「用于在提醒到点时通知你」）。
- 未授权时：
  - 降级为精灵轻提示；
  - 在「提醒与免打扰」显示提示条：「系统通知未开启 · 去开启」。

## 6. 权限中心

现状是一组被动标签（通知权限 / 文件访问 / 屏幕录制 / 主动感知），用户无法操作。

目标态：放在「设置 → 关于 → 权限」，每项提供状态 + 操作：

| 权限 | 状态 | 操作 |
| --- | --- | --- |
| 通知 | 已授权 / 未授权 / 未询问 | 去开启（跳系统设置）/ 重新申请 |
| 屏幕录制 | 已授权 / 未授权 | 去开启 |
| 文件访问 | 仅主动拖入（说明性） | — |
| 麦克风（语音输入） | 已授权 / 未授权 | 去开启 |
| 主动感知 | 开 / 关 | 切换 |

- 每项附一句「用途」说明。
- 不使用「主动感知」这类含糊词，改为「根据使用节奏提醒休息」。

## 7. 更新

### 7.1 现状问题

现状「检查更新」→「下载更新」再调用一次 `check_for_updates_extended`，逻辑绕；且没有真正的自动安装，体验割裂。

### 7.2 目标态

```text
设置 → 关于
  版本 v1.2.7
  状态：已是最新 / 发现新版本 v1.3.0
  [ 检查更新 ]
  （发现新版本时）
  更新说明（折叠）
  [ 立即更新 ]  → 下载并安装 → 提示重启
```

规则：

- 检查更新是显式操作，不自动弹窗打扰。
- 有更新时，设置入口显示一个小红点，不强推。
- 下载显示进度与速度。
- 安装后提示「重启后生效」，提供「立即重启」。
- 失败时给出人话原因 + 手动下载入口。

> 若使用 Tauri updater，优先走原生自动更新；否则保留手动下载 + 打开安装包。

## 8. 插件

### 8.1 现状

- 外部插件列表放在「关于」Tab，无插件时显示「未发现外部插件清单」；
- 业务插件（提醒 / 日程）与外部插件概念混在一起；
- HTML 预览以独立设置 section 出现。

### 8.2 目标态

- **内置能力**（提醒、日程、记录、专注）不再叫「插件」，就是功能。
- **外部插件**移入「设置 → 高级 → 插件」，无插件时**不显示入口**。
- **HTML 预览**移入「设置 → 高级 → 实验室」，默认关闭。
- 插件页展示：名称、版本、权限、状态、启用开关、卸载。
- 插件必须声明所需能力，安装时展示权限清单。
- 只读插件可自动执行；写入插件必须确认（与模块 02 一致）。

## 9. 数据与隐私

| 项 | 策略 |
| --- | --- |
| 数据存储 | 全部本地（SQLite / 文件），不上传 |
| 导出 | 设置 → 系统与隐私 → 导出我的数据（JSON） |
| 清空 | 二次确认 + 输入确认词 |
| 日志 | 不含对话内容，仅状态与错误码 |
| 屏幕 | 仅用户主动框选时读取，不后台截屏 |
| 输入 | 仅统计活跃度用于休息提醒，不落盘明文、不外传 |
| 网络 | 仅调用用户配置的模型服务与 GitHub 更新检查 |

---

## 10. 崩溃与诊断

- 崩溃时生成本地日志，可在「设置 → 关于 → 诊断」中查看与导出。
- 不上传遥测（除非未来明确告知并同意）。
- 错误上报给用户时只显示可读信息，技术细节折叠。

## 11. 验收标准

- [ ] 托盘菜单项与状态正确，左键/右键行为符合预期。
- [ ] 全局快捷键可修改，冲突有提示。
- [ ] 关闭主窗口隐藏到托盘，首次有提示。
- [ ] 通知权限状态可操作，未授权有降级路径。
- [ ] 权限中心每项可操作且有用途说明。
- [ ] 更新流程可完成，失败有人话原因。
- [ ] 插件入口只在有插件时出现。
- [ ] HTML 预览默认关闭且位于高级。
- [ ] 导出 / 清空数据可用且有确认。
