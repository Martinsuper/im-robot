## 背景

现在的 `catch {` 有两个问题：

1. **用户主动操作失败被吞掉或只给笼统文案**（如 `setError("删除失败")`），丢了真实原因，也没有 toast/重试入口。
2. **读取失败被伪装成空数据**（如 `catch { setMemories([]) }`）。用户在界面上看到的是「没有记录」，而真实情况是「加载失败」——这是最误导的一类。

## Change

### 1. `src/features/memory/MemoryCenter.tsx`（14 处 + 渲染层）

- **读取类**（`loadMemories` / `loadRecent` / `loadPending` / `loadSummaries` / `searchMemories`）：`catch { setXxx([]) }` 改为 `catch (error) { setError(toUserMessage(error, "记录加载失败，请重试。")); }`，**不要**再清空列表掩盖失败。
- **写操作类**（`handleDelete` / `handlePin` / `handleUnpin` / `handleFeedback` / `handleClearAll` / `handleReflectNow`）：改为 `toast.error(toUserMessage(error, "删除失败"))` 这类形式——保留原有的具体动作文案作为 fallback，真实原因优先。
- 渲染层：`{error && <p className="memory-error">{error}</p>}` 改为 `<ErrorState message={error} onRetry={...} onDismiss={() => setError("")} />`。
- 列表为空时用 `<EmptyState title=... description=... />` 替换现有的裸 `<p>` 空态。

### 2. `src/features/memory/MemoryDetail.tsx`（3 处）

编辑 / 删除 / 保存失败 → `toast.error(toUserMessage(error, "<对应动作>失败"))`。

### 4. `src/features/pet/personality/personalityRuntime.ts`（3 处）

### 5. `src/features/onboarding/OnboardingWindow.tsx`（3 处）

- 后 2 处已有 `/* ignore ... */` 注释，**保留原样**，只需确认注释说明了理由。
