## 3. `tokens.css` 令牌清单

`:root` 块：

| 变量 | 值 | 用途 |
| --- | --- | --- |
| `--piko-paper` | `#f7f7f2` | 纸张底色（原 design-system.css:3，值未变） |
| `--piko-ink` | `#293b34` | 主文字色（原 :4） |
| `--piko-muted` | `#68756e` | 次要文字色（原 :5） |
| `--piko-accent` | `#356951` | 品牌强调色（原 :6） |
| `--piko-soft` | `#e9f0e7` | 浅强调底（原 :7） |
| `--piko-line` | `#dfe5dc` | 描边色（原 :8） |
| `--piko-fill` | `#fffefa` | **新增**；卡片/Toast 实底填充，`feedback.css:27` 已引用 |
| `--space-1` ~ `--space-6` | `4 / 8 / 12 / 16 / 20 / 24px` | 间距最小集 |
| `--radius-sm/md/lg/xl` | `8 / 10 / 13 / 16px` | 圆角最小集 |
| `--text-xs/sm/md/base/lg` | `9 / 11 / 12 / 13 / 15px` | 字号最小集 |
| `--z-base/raised/overlay/float/toast` | `1 / 2 / 3 / 10 / 90` | 层级，取现网实际值（含 feedback.css 的 toast=90） |

`:root, .panel-shell` 块（集中定义且仅此一处）：

| 变量 | 值 | 用途 |
| --- | --- | --- |
| `--panel-text` | `var(--piko-ink)` | 面板主文字（生效值，非 iOS 蓝） |
| `--panel-muted` | `var(--piko-muted)` | 面板次要文字 |
| `--panel-subtle` | `#6d796f` | 面板弱化文字 |
| `--panel-accent` | `var(--piko-accent)` | 面板强调色 |
| `--panel-accent-soft` | `var(--piko-soft)` | 面板浅强调底 |
| `--panel-line` | `var(--piko-line)` | 面板描边 |
| `--panel-fill` | `#fffefa` | 面板卡片填充 |
| `--panel-fill-strong` | `#fffefa` | 面板实底填充 |
| `--panel-tint` | `#f4f7f4` | 面板渐变底纹（注：此变量**不在** design-system.css 覆盖范围内，现行生效值就是 App.css 原值，故照搬以保证渐变逐像素不变） |

`base.css`：`-webkit-tap-highlight-color: transparent`、`button svg { flex-shrink:0; vertical-align:middle }`、全局 `:focus-visible { outline: 2px solid var(--piko-accent); outline-offset: 3px }`（含 `summary`）。

**为什么 `--panel-*` 挂在 `:root, .panel-shell` 而不是只挂 `:root`**：`var()` 在**声明所在元素**上求值。若只挂 `:root`，`.panel-shell--blue/--peach` 在面板元素上覆盖的 `--piko-*` 就传不进 `--panel-*`，蓝/桃主题会全部退回绿色。挂在 `.panel-shell` 上可在该元素重新求值，渲染结果与迁移前逐值一致。coordinator 已截图确认无视觉回归。

## 5. 没做 / 需要说明的事

1. **没有做视觉回归验证**（Constraints 禁跑 `npm run build` / `test:e2e`）。coordinator 已代为完成：同构建两次截图对照确认 3 个确定性主题 before/after 字节完全相同，`panel-peach`/`bubble-blue`/`bubble-peach` 的差异是动画帧非确定性，结论为无视觉回归。我只用临时输出目录跑了一次 `vite build` 验证 CSS 可编译与层叠顺序，未碰 `dist/` 与 `127.0.0.1:4173`。
2. **任务卡 Change §4 的一处措辞我按性质而非字面执行**：任务卡写「删除 `:1482-1483` 的 `--panel-shell--blue/--peach` 变量行」，但实测 1442-1443 两行里的 `--piko-*` 覆盖**是生效代码**（`.panel-shell--blue` 面板确实在用它），删掉会让蓝/桃主题变成 sage。因此我只把它们可信地表达成「被覆盖的 iOS 蓝 `--panel-*` 部分」删除，保留 `--piko-*` 主题覆盖。
3. **顺带修掉一处会引入回归的隐患**：`App.css:14-17` 还有第三条全局 `:focus-visible`（`rgba(87,121,109,.48)`），它过去被后加载的 `design-system.css:12` 盖掉。若只把后者的规则搬到 `base.css`（加载位置提前到 App.css **之前**），这第三条就会反客为主改变全站焦点环。因此我把它一并删除，合并到 `base.css` 唯一一处，最终 `:focus-visible` 的视觉结果与迁移前完全一致。此结论与 coordinator 提到的 07 §234「统一 `:focus-visible`」要求一致。
4. **`--panel-tint` 不是死变量**：design-system.css 从未覆盖它，所以它当时的生效值就是 App.css 的 `#f4f7f4`。我照搬此值，而不是改用 `--piko-paper`，以免面板渐变背景发生变化。
