# 模块 03 · 今天（提醒 · 日程 · 专注）

> 关联：[00-产品总览与设计原则](./00-产品总览与设计原则.md) · [02-模块-AI对话与助手](./02-模块-AI对话与助手.md)
> 代码位置（现状）：`PanelWindow.tsx` 的 reminders / calendar / focus 部分；`src-tauri/src/reminder_schedule.rs`、`src-tauri/src/sync/calendar_sync.rs`

---

## 1. 模块目标

把现状中 **提醒事项、本地日程、专注模式、休息提醒、工作节奏** 五套时间能力合并成一个用户一眼就懂的界面：**今天**。

一句话心智：**「今天要做什么、什么时候、现在在专注还是该休息。」**

---

## 2. 为什么合并

现状的问题：

- 提醒和日程是两个几乎相同的列表，用户不知道该记在哪个；
- 专注计时器放在「提醒」Tab 里，位置反直觉；
- 休息提醒在「设置」里，和专注又有关联，用户找不到；
- 工作节奏（输入字符数、前台应用、空闲时长）信息对普通用户价值低且略带隐私压力。

合并原则：

- **一条时间线**：提醒和日程本质都是「某个时间点要做的事」，用同一种卡片展示，用标签区分。
- **一个计时器**：专注 / 休息是「当下正在做的事」。
- **一个免打扰设置**：休息提醒与免打扰时段合并为「什么时候可以提醒我」。

---

## 3. 统一模型

```ts
type ScheduleKind = "reminder" | "event";

interface ScheduleItem {
  id: string;
  kind: ScheduleKind;        // 提醒 = 单点；日程 = 有起止
  title: string;
  startAt: number;
  endAt?: number;            // 仅 event
  repeat: "none" | "daily" | "weekly" | "weekdays";
  status: "pending" | "done" | "missed" | "triggered";
  location?: string;
  notes?: string;
  createdAt: number;
  updatedAt: number;
}
```

- 提醒 = `kind: "reminder"`，只有 `startAt`。
- 日程 = `kind: "event"`，有 `startAt` + `endAt`。
- 同一条时间线渲染，提醒显示为点，日程显示为区间。

## 4. 界面结构

「今天」Tab 从上到下：

```text
┌───────────────────────────────────────────────┐
│ ① 问候区                                        │
│   早上好，今天有 3 件事，现在在专注中。         │
│   [ 开始对话 ]                                  │
├───────────────────────────────────────────────┤
│ ② 专注 / 休息卡片                               │
│   （未开始）选择时长 → [开始专注] / [休息 5 分钟]│
│   （进行中）⏱ 18:42  [暂停] [结束]              │
├───────────────────────────────────────────────┤
│ ③ 快速添加                                      │
│   [ 说点什么或输入…                    ] [添加]  │
│   ⚡自然语言：明天 10 点开会 / 每晚 9 点提醒喝水 │
├───────────────────────────────────────────────┤
│ ④ 今天时间线                                    │
│   09:00  ● 晨会                         [✓][…] │
│   10:00  ▬ 项目评审  10:00–11:00        [✓][…] │
│   14:30  ● 起来活动                     [✓][…] │
│   ……                                           │
├───────────────────────────────────────────────┤
│ ⑤ 接下来（明天 / 本周，可折叠）                 │
└───────────────────────────────────────────────┘
```

### 4.1 问候区

- 按时段问候 + 一句摘要（今天几件事 / 是否专注中）。
- 摘要数据来自时间线与专注状态。
- 移除现状中面板顶部常驻的 4 项「总览」（AI 对话 / 今日专注 / 亲密度 / 最近互动）——这些要么放进各自模块，要么去掉。

### 4.2 快速添加

支持自然语言解析：

| 输入 | 解析结果 |
| --- | --- |
| `明天 10 点开会` | event，明天 10:00，时长默认 1h |
| `10 分钟后喝水` | reminder，now + 10min |
| `每晚 9 点提醒我总结` | reminder，daily 21:00 |
| `周五下午 3 点项目复盘` | event，本周五 15:00 |

- 解析后展示一张确认卡（可编辑时间 / 标题 / 类型），确认才保存。
- 解析失败则提示「没太听懂，手动选个时间吧」，并展开手动表单。
- 也可以直接在对话窗口说，由模型调用创建工具（走模块 02 的确认流程）。

### 4.3 时间线

- 按时间升序；已过时间的未完成项标灰并显示「已错过」。
- 每条右侧两个操作：`✓ 完成`、`… 更多`（编辑 / 删除 / 稍后提醒）。
- 时间冲突：两条区间重叠时用 ⚠ 标记，并在顶部提示「有 1 处时间冲突」。
- 空状态：「今天还没有安排。要不要加一件？」

### 4.4 接下来

- 折叠区，展示明天与本周内的事件。
- 每条可「提前到今天」或删除。

## 5. 专注与休息

### 5.1 状态

```ts
interface FocusState {
  status: "idle" | "running" | "paused";
  kind: "focus" | "break";
  remainingSeconds: number;
  todayMinutes: number;
}
```

### 5.2 交互

- 未开始：选择 15 / 25 / 45 / 60 分钟 → 「开始专注」；或快捷「休息 5 / 10 / 15 分钟」。
- 进行中：显示环形倒计时；操作 `暂停 / 继续 / 结束`。
- 结束时：系统通知 + 精灵庆祝动画 + 亲密度 +5。
- 今日专注分钟数在卡片角落轻量展示。

### 5.3 休息提醒（智能）

- 基于本地输入活跃度与空闲检测，在连续工作过久时轻提醒休息。
- 提醒方式：精灵轻提示 + 可选系统通知。
- 频率受免打扰时段与冷却时间约束。
- **不展示**输入字符数、前台应用类别等原始数据。

### 5.4 免打扰

合并现状的「静默时段 + 休息提醒开关 + 安静模式」为一个设置组：

```text
免打扰时段     [ 22:00 ] – [ 08:00 ]   （开关）
休息提醒       [ 开 ]  间隔 45 分钟   冷却 30 分钟
专注时免打扰   [ 开 ]
```

- 免打扰时段内：不发声、不主动弹窗、不发送系统通知（除用户主动设置的提醒）。
- 用户主动创建的提醒不因免打扰而丢弃，只在结束后一并提示（可配置）。

## 6. 提醒与日程的通知

| 场景 | 通知方式 |
| --- | --- |
| 提醒到点 | 系统通知 + 精灵轻提示 |
| 日程开始 | 系统通知 + 精灵轻提示 |
| 日程结束 | 不通知 |
| 专注结束 | 系统通知 + 精灵庆祝 |
| 休息提醒 | 精灵轻提示（可选系统通知） |

- 首次使用通知时申请权限，并说明用途。
- 未授权时降级为精灵轻提示，并在设置页提示「去开启通知」。

---

## 7. 与系统日历

现状有「同步到系统日历 / 从系统同步 / 导出 iCalendar」三个入口，过于复杂。

目标态简化为：

- 默认：本地管理，提供 **导出 iCalendar**（在「更多」菜单中）。
- 若平台支持双向同步（macOS），在「接下来」区域提供 **一个** 开关：「与系统日历同步」。
- 同步为增量、冲突以本地为准，并展示最后同步时间。
- 不把三个按钮并排放在标题栏。

---

## 8. 权限与隐私

- 不读取位置、不读取系统日历以外内容。
- 输入活跃度仅本地计算，不外传、不落盘明文。
- 用户可在「设置 → 系统与隐私」关闭智能休息提醒。

---

## 9. 数据与迁移

现状数据：

- 提醒：`list_reminders` / `create_reminder` / `delete_reminder`（`Reminder` 结构）。
- 日程：`list_calendar_events` / `create_calendar_event` / `delete_calendar_event`（`CalendarEvent` 结构）。
- 专注：`get_focus_state` / `start_focus` / `start_break` / `pause_focus` / `resume_focus` / `stop_focus`。

迁移策略：

1. 新增统一 `ScheduleItem` 存储。
2. 首次启动时把现有 `Reminder` 与 `CalendarEvent` 导入为 `ScheduleItem`（保留原 id 前缀区分来源）。
3. 旧命令保留一个版本用于兼容，后续移除。
4. 专注状态结构不变，仅 UI 合并。

## 11. 验收标准

- [ ] 面板不再有独立的「提醒」和「日程」Tab，统一在「今天」。
- [ ] 提醒与日程在同一时间线，视觉可区分。
- [ ] 自然语言添加能正确创建提醒 / 日程，并经过确认。
- [ ] 时间冲突有提示。
- [ ] 专注 / 休息闭环可用，结束有通知与庆祝。
- [ ] 免打扰时段内无任何打扰（除用户主动提醒）。
- [ ] 智能休息提醒不再展示输入字符数等原始隐私数据。
- [ ] 系统日历同步只保留一个入口，并提供导出。
- [ ] 旧提醒 / 日程数据可无损迁移。
