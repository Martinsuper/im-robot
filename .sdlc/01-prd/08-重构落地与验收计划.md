# 模块 08 · 重构落地与验收计划

> 关联：[00-产品总览与设计原则](./00-产品总览与设计原则.md) · 全模块
> 目的：把前 7 篇产品文档转成可执行、可验收的重构计划，并记录现状问题审计结果。

---

## 1. 重构总原则

1. **先收敛信息架构，再改视觉**：Tab 与模块合并是第一优先级，否则样式重构会白做。
2. **先统一数据源，再做 UI**：设置 / 成长 / 记录的状态来源先合并，避免边改边打架。
3. **每个阶段可发布**：每个 R 阶段结束都应有可运行、可体验的版本。
4. **不删底层能力，只隐藏入口**：养成 / 换装等先隐藏，数据保留，后续再清理。
5. **每阶段必须修掉对应的现状问题**：见第 2 节审计表。

## 2. 现状问题审计

### 2.1 信息架构

| # | 问题 | 证据 | 影响 | 对应优化 |
| --- | --- | --- | --- | --- |
| IA-1 | 面板 8 个 Tab，按数据类型划分 | `PanelTab = companion/settings/reminders/calendar/memos/history/memory/about` | 用户找不到功能 | 合并为 3 Tab |
| IA-2 | 提醒与日程两套几乎相同的列表 | `Reminder` vs `CalendarEvent` | 不知道该记哪 | 统一 `ScheduleItem` |

## 3. 阶段计划

### R0 · 止血（1~2 周）

目标：不改变信息架构，先把「坏体验」修掉，为后续重构铺路。

任务：

1. 统一状态反馈：引入 `Toast` + `ErrorState` + `EmptyState`，替换 5 种错误样式。
2. 修复设置保存：所有设置项改为即时保存，失败回滚 + Toast。
3. 面板只渲染当前 Tab（去掉 `.is-hidden` 全量渲染），切换重置滚动。
4. 移除精灵上的 `pet-clock` 与常驻 `pet-actions`，改为悬停浮出。
5. 清理 `catch {}`，接入统一错误提示。
6. 建立 `src/styles/tokens.css` 与 `base.css`，对话窗口试点迁移。

验收：

- [ ] 全应用无 `alert()`，无原始错误直出。
- [ ] 设置修改即时生效，无「保存」按钮。
- [ ] 面板 Tab 切换不卡顿且滚动复位。
- [ ] 精灵无时钟、无常驻操作栏。

### R1 · 收敛信息架构（2~3 周）

目标：面板 8 Tab → 3 Tab；时间与记录各自合并。

任务：

1. 新增统一 `ScheduleItem` 存储与迁移脚本，导入旧提醒 / 日程。
2. 新建「今天」Tab：问候 + 专注卡片 + 快速添加 + 时间线 + 接下来。
3. 新建「记录」Tab：记录入口 + 搜索 + 我的记录 / Piko 记住的 / 对话历史。
4. 新建「设置」Tab 骨架（5 组 + 高级）。
5. 移除 companion / reminders / calendar / memos / history / memory / about Tab。
6. 自然语言快速添加（先支持 4 类模板）。

验收：

- [ ] 面板只有 3 个 Tab。
- [ ] 提醒与日程在同一条时间线。
- [ ] 旧数据无损迁移。
- [ ] 记录三区可用，搜索跨区。
- [ ] 任意核心任务 ≤ 2 次点击。

### R2 · 简化对话与配置（2 周）

目标：对话窗口成为唯一入口，配置零门槛。

任务：

1. 拆分 `BubbleWindow` 为 `ChatHeader` / `ChatThread` / `ChatComposer` / `ChatToolbar`。
2. 会话化对话历史（`ChatSession`）。
3. 模型设置收敛为「服务 + Key + 测试」，高级折叠。
4. 引导重做：3 步、可跳过、无技术字段、共用 provider 预设。
5. 未配置模型的引导与降级。
6. 错误文案人话化。

验收：

- [ ] 引导 3 步可完成且可跳过。
- [ ] 模型设置默认只见 2 项。
- [ ] 对话窗口状态齐全（空/思考/流式/确认/失败/停止）。
- [ ] 历史按会话展示，可继续对话。

### R3 · 陪伴体系重构（1~2 周）

目标：亲密度与成长可见、可解释。

任务：

1. 交互事件归一化，阈值集中。
2. 状态机收敛为 7 状态，情绪收敛为 4 种。
3. 亲密度 + 成长阶段落地，进度可见。
4. 隐藏人格 / 属性 / 成就 / 换装入口。
5. 外观风格三选一。
6. 悬停快捷操作与原生快捷菜单。

验收：

- [ ] 亲密度互动后增长并持久化。
- [ ] 阶段提升有反馈。
- [ ] 抚摸 / 拖动 / 双击 / 右键均正确。
- [ ] `minimal` 无声音无主动弹窗。
- [ ] 养成入口不再出现技术数值。

### R4 · 系统与生态（1~2 周）

目标：系统集成可靠，权限可操作，插件收敛。

任务：

1. 托盘菜单重做（中文、状态感知）。
2. 快捷键可修改 + 冲突提示。
3. 权限中心可操作 + 用途说明。
4. 更新流程重做。
5. 插件 / HTML 预览收进高级。
6. 数据导出 / 清空 + 二次确认。

验收：

- [ ] 托盘与快捷键行为符合规范。
- [ ] 权限可授权、有降级路径。
- [ ] 更新可完成。
- [ ] 无插件时不显示插件入口。

### R5 · 打磨与多语言（按需）

任务：

1. 无障碍审计与修复。
2. 性能优化（首屏、流式、精灵渲染）。
3. 根据决策启用完整多语言或彻底清理 i18n。
4. 删除旧 CSS、旧组件、下线模块代码。

验收：

- [ ] 键盘可完成主要流程。
- [ ] 首屏可交互 < 1s。
- [ ] 无死代码文件。

## 5. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 数据迁移丢失提醒 / 日程 | 高 | 迁移前备份 + 幂等迁移 + 旧数据保留一版 |
| 面板重构期间功能不可用 | 中 | 新旧 Tab 并行一个版本，灰度切换 |
| 样式重构引发全局视觉错乱 | 中 | 逐窗口迁移，先试点对话窗口 |
| 养成系统隐藏引发老用户不满 | 低 | 亲密度数据保留，仅隐藏入口 |
| i18n 清理引发外文用户流失 | 低 | 先统计使用；保留语言文件但隐藏入口 |
| 跨平台窗口行为差异 | 中 | macOS / Windows / Linux 分别验证 |

## 6. 总体验收标准

### 6.1 产品层

- [ ] 用户能在 2 次点击内完成：对话、加提醒、记一笔、看今天。
- [ ] 首次使用无需理解任何技术概念即可聊天。
- [ ] 主动打扰可完全关闭，关闭后真正安静。
- [ ] 所有数值 / 状态都能被用户解释。

### 6.2 工程层

- [ ] 单一 CSS 入口，无重复选择器。
- [ ] 单一数据源，无 localStorage 跨窗口补丁。
- [ ] 面板只渲染当前 Tab。
- [ ] 无 `alert()`、无原始错误直出、无 `undefined`。
- [ ] 关键路径有单测 / E2E。

### 6.3 文档层

- [ ] 代码术语与产品文档术语一致（见 00 名词表）。
- [ ] 每个模块的验收清单全部通过。
