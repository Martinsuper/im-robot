# Piko Passport 固件 0.11.0

目标：FoloToy AI Passport，ESP32-C3，8 MB Flash，无 PSRAM。使用官方 BSP，不复用硬件测试菜单。0.8.0 起固件精简为语音、连接、输入三个页面：移除陪伴、专注、消息页面及其宠物动画、专注计时、操作回执等相应资源与协议处理。新增按住说话和设备播报。

## 构建

安装 ESP-IDF **5.5.3** 并激活环境，随后：

```sh
cd firmware/passport
python3 prepare.py
idf.py set-target esp32c3
idf.py build
```

`prepare.py` 将官方仓库固定到 `006c2279852e352a8433b2c21e5e09be2ca36f77`，存入忽略提交的 `vendor/`。Component Manager 锁定依赖见 `dependencies.lock`，设备 UI 固定使用 LVGL `9.6.0~1`。常规构建不需要重新生成字体；如需重新生成，安装 Node/npm 与 Python fontTools 后运行 `python3 generate_font.py`。

构建后可运行 `python3 package.py`，验证镜像芯片与写入边界，并生成 `build/piko-passport-0.11.0.zip`。包内含三个分段镜像及带 SHA-256 的地址清单；该脚本不会连接设备。

## 写入和数据保护

**此仓库的修改不会自动刷写设备。** 写入前确认目标串口、Flash 容量、现有分区表，备份现有固件与数据，并取得用户刷写授权。

本项目使用独立分区表：应用在 `0x10000..0x34ffff`，为已知原厂设备身份区 `0x356000..0x359fff` 留出不写入区域。但保留此地址不代表兼容所有已安装玩法的分区布局；写入新的应用/分区表可能使旧玩法数据不可用。禁止整片擦除，禁止将带填充的合并镜像直接写入现有设备。

确认分区兼容且已获得授权后，使用 ESP-IDF 生成的分段刷写参数：

```sh
idf.py -p <确认的串口> flash monitor
```

不要运行 `erase-flash`。固件启动时遇到 NVS 错误会停止，不会自动擦除设备数据。

## 使用

电脑端 Piko 设置 → 系统与数据 → Piko Passport：开启局域网连接。设备首启进入配网，连接屏幕显示的开放热点后访问 `http://192.168.4.1`。页面会扫描附近的 2.4 GHz Wi-Fi，选择与电脑相同的网络并输入密码。保存后设备重启并自动发现电脑；在电脑设置中核对设备 ID，点击“确认连接此设备”即可，不用手输 IP 或配对码。多台电脑同时运行时，只在希望连接的电脑上确认。若网络隔离导致广播发现失败，可展开“手动配置”，填写隐藏网络名称、电脑私网 IPv4 和手动配对码。桌面需使用支持自动发现的新版客户端。发现使用 UDP 19389，设备连接使用 TCP 19388。

以下按键说明为 0.8.x 历史记录；当前按键见文末「0.9.0 按键与设置」与「0.10.0 万年历」。

- UP / DOWN：切换语音、连接和输入三页。
- 语音页：按住 OK 约 0.3 秒后录音，松开发送；新版电脑端支持持续按住录音；处理中或播放时短按 OK 取消，切页也会取消当前语音。回复从设备扬声器播放，长文字按实际字宽分页，短按 OK 手动翻页，阅读位置保持不变。
- 连接页：发起/断开连接与解除配对；未配对时长按 OK 进入配网模式。
- 输入页：核对屏幕电脑 IP 后按确定选择，按住上键说话、松开结束，短按下键发送 Enter。

语音需要电脑端启用语音识别功能，在 Piko 设置中下载 SenseVoice 模型，并配置有效的聊天模型。识别在电脑本地完成；识别文本发送给已配置的聊天模型。语音任务复用 Piko 的人格、记忆和模型配置，对话与执行结果保存在桌面任务记录中。语音现在调用与桌面相同的 Agent，可查询知识库、管理提醒/日程/备忘、控制专注，并按现有授权使用文件和命令工具。每台设备使用稳定的独立任务会话，复用该会话已选择的工作目录和知识范围。

设备播报由电脑的系统语音合成后分块回传，不从电脑扬声器播放：macOS 使用 Tingting 中文音色；Windows 需安装可朗读中文的系统语音；Linux 需安装 `espeak-ng` 及中文音色。合成失败时保留文字回复。回复音频最多 40 秒。

内置 Noto Sans SC 中文、ASCII 和常用标点子集，支持常用简体中文；生僻字和部分 emoji 不保证显示。授权见 `main/LICENSE.font.txt`。重新生成字体需 Node/npm、Python fontTools（`python3 -m pip install fonttools`）和联网，运行 `python3 generate_font.py`；常规构建不需要重新下载字体。

音频通过有界队列分块传输，设备不会缓存整段录音或整段回复；断线会取消当前语音。设备不运行模型，也不保存模型 API Key。Wi-Fi WebSocket 仅供可信局域网使用。提醒同步和自定义形象同步尚未实现。

## 操作确认

- 提醒、日程、备忘、专注：设备显示完整待执行内容。核对后重新短按 OK 确认，长按 OK 拒绝；确认前不执行。长内容每 6 秒翻页，确认在 120 秒后过期。
- 录音结束时的松手/单击不会被用来确认后续操作；旧确认码和重复点击也不会再次执行。
- 内容过长、字形不受支持，或需要文件/命令授权与目录选择：电脑自动打开“Passport 语音任务”窗口，必须在电脑查看完整内容后操作。设备不能代替桌面批准这些请求。已有命令自动批准偏好继续由桌面 Agent 执行。
- 处理中短按 OK、切页或断线会取消当前任务。此前可能已有部分步骤完成，请在电脑任务记录核实，不要盲目重试整条指令。
- 旧固件未声明 `voice-confirm-v1` 能力时，全部操作确认都转到电脑，不会在设备上盲目执行。设备侧确认需要 0.3.0 固件。

## 无硬件测试

```sh
python3 tests/run.py
```

使用系统 C 编译器和 pthread 模拟 RTOS/I2S，验证真实音频 worker 的录音结束、有限队列、音频顺序、播放确认、取消重启和溢出恢复。同时验证确认卡必须显示后重新按键，且不能重复确认、错卡确认或批准桌面专属操作。不能代替真实麦克风、扬声器和网络测试。

完整协议与验收清单：[设备设计](../../doc/design/07-passport-device-bridge.md)。

### 配网失败恢复

连续认证失败或 30 秒内未取得 IP，设备会自动恢复开放配网热点。重新连接屏幕上的热点并打开 `http://192.168.4.1`，页面会显示失败原因并选回上次网络，重新输入密码即可。已配对设备修改 Wi-Fi 不需要重新配对。设备各页面和状态提示使用中文；确认键对应硬件 OK 键，上下键对应 UP/DOWN 键。

### MiMo流式回复（0.5.0）

新版桌面端与0.5.0固件配合，MiMo首段音频到达即可开始播放。仍最多40秒，按确认键或切页可取消。旧固件可继续使用，但回复仍需等待整段合成；仅更新桌面端不足以启用设备流式播放。

### 屏幕与交互（0.5.1）

补齐破折号、中间点和常用中文标点；正文改为 16px，并按实际字宽分页。阅读卡片、连接/电量状态和四页导航固定显示；专注计时放大。短按翻页与按住录音分离，长按打开结束专注提示后，需重新按下确认，避免松手误结束。

本机回归：`python3 firmware/passport/tests/run.py`，覆盖分页内容完整性、UTF-8、标点换行、录音阈值和原有音频/确认/配网逻辑。

### 设备端连接管理（0.6.0）

电脑开启「局域网设备连接」后，ESP32 的「连接」页短按 OK 发起连接，无需电脑重复确认。未配对设备的主动搜索最长两分钟；配对成功后仍使用令牌自动重连。已有配对可短按断开/恢复连接，重启后保持所选状态。

在「连接」页长按 OK 打开解除配对提示，再重新短按确认。无线网络设置保留，双方配对凭据清除；电脑离线时，设备立即停止业务交互，保留令牌仅用于电脑上线后同步撤销，收到撤销回执再清除本地凭据。重复撤销可安全重试。新连接仍受电脑端单设备限制，发现请求与短期配对码绑定设备 ID 和随机 nonce，业务操作的确认流程不变。

旧版固件仍可使用电脑端的「连接旧版设备」或手动配对码。Piko 重启后需重新开启局域网连接开关。

### 录音上传抖动修复（0.6.1）

录音缓冲从 3 个 1024 字节块扩大为 16 块（16kHz/16bit/mono 下由 96ms 增至 512ms），仍保持有界。先完成 voice_start 控制消息发送，再开始采集，避免网络初始化耗尽录音队列。渲染获取 LVGL 锁最多等待 1ms；该库参数 0 表示无限等待，不能作为非阻塞尝试。语音期间推迟电量 I2C 读取，录音期间推迟心跳发送。

录音积压、麦克风读取失败、扬声器写入失败使用独立错误码与提示，错误日志只记录代码、已上传字节数和剩余堆空间，不记录语音内容或凭据。上传失败保留具体错误提示。增加消费者短暂停顿后完整排空队列、持续阻塞有界失败、读写故障区分及恢复的测试。

### 持续按住录音（0.6.2）

新版电脑与设备通过 `voice-long-upload-v1` 协商后，取消 12 秒输入截断：一直按住即可持续录音，松手后开始识别。设备仍只保留 512ms 有界缓冲；电脑写入权限受限的临时文件，不在内存累计整段音频。录音期间以持续收到数据为准，仅上传中断 15 秒才超时，不以录音总时长超时。

松手后每段最长 30 秒识别，重叠 0.5 秒并去重拼接；完整识别文字交给 Agent，设备只接收前 400 字的识别预览。处理时限随录音长度增长，取消或处理结束会清理临时文件。没有固定录音总时长上限，但磁盘空间不足或连接断开仍会明确报错。旧版电脑未协商此能力时，设备保留 12 秒兼容限制。回复播放的 40 秒限制不受影响。


## 随身语音输入（0.7.0）

新增“输入”入口，兼容 [folo-ai-passport-voice](https://github.com/manchunx7-bit/folo-ai-passport-voice) 的电脑客户端：核对屏幕电脑 IP 后按确定选择，按住上键说话、松开结束，核对电脑文字后短按下键发送 Enter，短按确定退出输入控制。文字由电脑输入法识别并输入当前光标处，与 Piko 语音助手独立。需按上游教程配置 BlackHole（Mac）或 VB-CABLE（Windows）及输入法；本项目未自动安装这些组件。接入细节、限制和验收见 [随身语音输入设计](../../doc/design/10-passport-voice-input.md)。

新增协议测试：`IDF_PATH=<ESP-IDF目录> python3 tests/voice_input_run.py`。模拟测试和编译不代表真实设备/输入法出字已验收。


### 0.7.1 实机修复与验收

修复输入模式上键按下/松开事件被旧按键过滤器丢弃的问题。2026-10-24 已在 ESP32-C3 实机刷入 0.7.1，完成三轮录音、BlackHole 音频接收和微信输入法 F9 出字验证，用户确认 Enter 正常。详见 [实机验证记录](../../doc/validation/2026-10-24-passport-voice-input.md)。

### 页面精简（0.8.0）

应用从六页精简为语音、连接、输入三页：删除陪伴、专注、消息页面，及其宠物动画（18 帧精灵图约 200 KB flash）、专注计时字体、操作回执（`event`/`ack`）与宠物/专注状态（`state`）协议处理。桌面端仍可通过语音任务控制专注；设备不再展示消息回执。原陪伴页长按重新配网的入口移至连接页：未配对状态（无令牌）时长按 OK 进入配网模式，其余连接页按键行为不变。

### 0.9.0 按键与设置

- 浏览页面：短按上下切页，短按确认进入当前页。未进入时长按不录音、不调整音量。
- Piko 已进入：按住确认约 0.3 秒录音，松开发送；短按确认取消当前任务并退出，录音松键不会误退出。短按上下翻阅识别文字／回复；空闲或播放时长按上下调整五档音量，持续按住可连续调整，零档静音。录音、思考及操作确认期间不调整音量。
- 操作确认：上下阅读全部内容后，重新按住确认执行；短按确认取消并退出。电脑专属授权仍需在电脑完成。
- 语音输入已进入：按住上键录音，松开输入文字；仅短按下键发送回车，绝不自动回车。短按确认退出。长按下键不发送回车。
- 设置已进入：仅“Wi-Fi 网络”和“电脑配对”两项；短按上下选择、确认进入，首页长按确认退出。网络详情长按确认重新配网、短按返回；电脑详情短按确认显示解绑卡，再重新长按执行，短按取消。固件版本显示在设置底部。
- 配对后自动连接、断线自动重连，不提供手动开始／停止连接开关。旧设置仅迁移音量／静音状态，旧自动回车配置不再使用。
- 音量保存失败恢复原值并显示提示。

Piko 页识别完成后先显示“你说的话”，思考和执行期间保留正文；回复到达后切换正文。正文保留数字页码。

运行 `python3 tests/run.py` 验证锁定导航、录音释放、仅手动回车、音量及 NVS 失败回滚、两项设置、重新按住确认执行和原有音频／网络逻辑。

### 0.9.1 会话与确认

- 每次进入 Piko 开始新聊天，当前操作模式内的多轮录音共用会话；退出取消正在执行的任务，再进入不会带入上一段聊天记录。长期记忆与历史记录不会删除。
- 日程确认使用标题、开始、结束等结构化字段，未处理的确认卡不会被普通进度消息覆盖；读完后长按确认执行。电脑专属授权仍在电脑确认，设备明确显示提示。
- 需要同时运行新版桌面端。普通聊天／日程等业务不要求工作目录；生成文件默认使用文稿/Piko，操作现有文件仍在电脑选择目标，目录选择不自动批准文件或命令操作。

### 0.10.0 万年历

新增「日历」页（语音输入 → Piko → 日历 → 设置 四页导航），覆盖 1901–2100 年的农历、节气、传统节日、干支生肖与每日宜忌，全部在设备本地推算（`main/piko_lunar.c`，位表数据取自开源 solarlunar 项目，ISC 许可），不依赖联网；时间来自已有 SNTP 对时，未同步时显示提示。

- 浏览态：日历页显示标题与图标预览，短按确认进入。
- 今日黄历（进入默认）：大号公历日期、星期与农历日期、干支年（与生肖一致）、节气或节日、宜忌白卡与彭祖百忌；顶部提示行显示冲煞与建除值神。短按上下翻日（按住连翻）。
- 短按确认呼出月历跳转器：上下选日（跨月自动翻、按住连翻），今日格墨绿圆环高亮、节气与节日墨绿标点；再短按确认查看选中日的黄历。长按确认退出日历页（与全局一致）。
- 宜忌为建除十二值神、彭祖百忌与冲煞的民俗算法输出，仅作参考展示。
- 字体子集由 `generate_font.py` 自动扫描 `main.c` 与 `piko_lunar.c` 生成，无需手工维护字符表。
- 月历网格新增约 55 个 LVGL 控件，LVGL 内存池从 24 KB 扩到 48 KB（`CONFIG_LV_MEM_SIZE`）；首次刷入时曾因 24 KB 池耗尽在首帧绘制崩溃，扩容后实机验证通过。
- 运行 `python3 tests/run.py` 新增农历/节气/干支/宜忌锚点测试（期望值离线导自 solarlunar 参考实现）。

## 手动息屏与亮屏

在任意页面（含配网界面）快速双击确定键，切换息屏／亮屏。使用 BSP 原有双击识别窗口（两次点击间隔约 180 ms 以内），双击不执行单击的进入、退出、选择或日历切换。单击、长按规则保持原样。

息屏只关闭背光，并跳过应用层界面更新；保留当前页面、页面锁定状态及按键操作。语音录音、上传、播放、电脑输入控制和联网继续运行，其他按键及收到消息不会自动亮屏。再次双击确定键恢复原有亮度（65%），界面随后更新为最新状态。息屏不等于深睡或断电，电源键仍由硬件处理。

主机验证：`python3 tests/run.py` 与 `python3 tests/voice_input_run.py`。设备验证需检查四个页面的双击切换、息屏录音／松手结束、息屏发送 Enter、长按确认以及配网界面恢复显示；主机测试不能代替实机按键时序和功耗测量。

### 启动循环重启：内存预算

六页界面曾耗尽 64 KB LVGL 固定池，首帧文字绘制时崩溃。单纯增至 96 KB 又会挤占音频 DMA 和网络任务的系统内存。当前使用 `CONFIG_LV_USE_CLIB_MALLOC=y`，让图形按需共享 ESP-IDF 堆；Wi-Fi 静态接收缓冲为 4 个，动态收发上限各 8 个，接收 BA 窗口为 4。

已有构建目录需在 `idf.py menuconfig` 中同步上述选项（defaults 不覆盖已有 sdkconfig），再构建。启动日志记录系统堆当前与最低空闲量。实机验收记录见 `doc/validation/2026-10-25-passport-boot-memory.md`。

### 六页界面的内存管理

内容视图按需创建，切换到其他内容视图时释放旧控件；状态栏、标题和导航常驻。日历、时钟与翻页的业务状态保留，返回页面时重建控件。翻页页释放界面不会清除蓝牙配对。

进入输入页后，设备发现 worker 暂停并销毁电脑 WebSocket 客户端、关闭发现 UDP socket；离开输入页后自动恢复连接。录音走独立 UDP 通道，暂停电脑连接不会清除配对配置。

`CONFIG_ESP_WIFI_IRAM_OPT`、`CONFIG_ESP_WIFI_RX_IRAM_OPT` 和 `CONFIG_ESP_WIFI_EXTRA_IRAM_OPT` 关闭，减少 RAM 中的可选 Wi-Fi 加速代码。已有 sdkconfig 需要同步配置。启动、视图切换与连接暂停会记录内存余量。

主机测试 `tests/ui_lifecycle_run.py` 覆盖 700 次视图切换的分配释放、动画取消及共享控件保留；实际长录音、Wi-Fi/蓝牙共存与切页体验仍需设备验收。

### 时钟布局与蓝牙初始化回归

`python3 tests/clock_layout_run.py` 使用本机 CMake/C 编译器构建真实 LVGL，检查加高盘面（216×194）内时间与秒数、日期+农历合并行、世界时+周数合并行的边界与互不重叠，以及设置菜单打开时表盘隐藏、关闭时恢复，并生成 PPM 预览。首次运行需要编译 LVGL，后续复用临时构建缓存。

ESP-IDF 5.5.3 的 NimBLE HID 在 GATT 注册失败时会留下已初始化的全局指针，导致重试报 `HID device profile already initialized`。`cmake/nimble_hid_cleanup.cmake` 只修补构建目录内的 SDK 源码副本，补上失败清理，不修改 ESP-IDF 安装目录。若未来 SDK 改动该函数，配置会要求重新审核补丁。

翻页页暂停桌面 WebSocket 与发现 socket，确认暂停完成后再启动 BLE；只为一个 HID 实例分配资源（其中同时包含键盘和媒体键报告）。

### 蓝牙与 Wi-Fi 共存的内存预算

翻页器仅有一个 HID 连接，ATT MTU 为 64，MSYS1/MSYS2 缓冲块数为 6/8，ACL 接收块数 6，HCI 事件池 8/4，控制器活动数 2。不要直接恢复默认的大池配置：实机曾在打开翻页界面后仅余约 1.6 KB，导致 Wi-Fi 资源不足；当前同场景约余 18.8 KB，广播与 Wi-Fi 获取 IP 已验证。

时钟盘面不再显示温度（温度占位已移除）；小字号 UI 字体仍需包含间隔点「·」，`tests/clock_layout_run.py` 检查该字形，防止字体子集再次遗漏。

### 音频 / 蓝牙按模式分配资源

开机与普通页面不预分配音频资源。短按确认进入 Piko 或输入模式时，创建 I2S/codec、录音/播放队列和音频 worker，恢复保存的音量；退出后取消会话/录音，等待 worker 退出，再释放队列、任务栈与 DMA。音频停止超时时不强制删除仍在 I2S 内的任务，保留待清理状态，后续重试不会覆盖遗留队列。

进入翻页模式前确保音频资源已释放。退出翻页模式时停止广播/连接，等待 NimBLE 主机退出，再释放 HID、事件任务、主机和控制器。退出会断开蓝牙，但不会清除配对记录；重新进入时再次广播。停止失败会阻止切换，并允许重试，避免两套资源同时常驻。

BSP 的公开 sleep 接口保留 DMA，因此 `cmake/audio_lifecycle.cmake` 为构建目录内的 BSP 源码副本添加完整释放入口，不修改 vendor 源码。更新 BSP 时需要复核其内部清理函数。

测试覆盖 40 轮音频释放/恢复、在 I/O 中退出、退出超时后恢复、并发读取及重复初始化，以及 50 轮 BLE 分阶段清理和失败重试。2026-10-25 实机完成 8 轮短录音、静音播放、BLE 启停，诊断版蓝牙视图余量约 50 KB，释放后约 116 KB。自动诊断只在显式使用 `-DPIKO_MODE_LIFECYCLE_TEST=ON` 构建时启用，测试录音不会发送；正常使用必须保持该选项关闭。

### 蓝牙页布局回归

配对、翻页、放映、黑屏各自使用独立内容组，模式菜单显示时隐藏底层内容。设备名固定单行省略，说明文字固定宽度换行，临时提示不与说明叠放。图标使用字体回退，UI 字体子集同时扫描 pager_page.c 与 pager_keys.c；设备名使用完整常用中文字体。

`python3 tests/pager_layout_run.py` 编译真实 LVGL 并渲染各状态、三种按键模式、中英文长设备名、提示与断线恢复，检查可见标签不重叠、文字未裁切、控件不越界，并验证重复重建。时钟布局测试也已复查。

### 从电脑切换到手机配对

电脑端“忽略此设备”不会通知 ESP32 删除绑定。设备已有绑定时，新设备需要在实体按键开放的两分钟窗口内配对。等待连接页也可以长按上/下键打开菜单，再长按确认开启新设备配对窗口，无需先连接旧电脑。手机如缓存了之前失败的 Passport Pager 条目，应先忽略该条目再搜索连接。不需要手动输入 PIN。

回归测试 `tests/pager_pairing_run.py` 覆盖已绑定设备回连、新设备窗口准入、过期及计时回绕；原生 LVGL 测试覆盖已有绑定时从等待页打开菜单和窗口反馈。该入口修复版是否刷入以对应验收记录为准。
